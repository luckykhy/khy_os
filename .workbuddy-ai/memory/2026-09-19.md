### 诊断：一个被漏掉的空白（实测证据）

本仓 Git 治理是**成对**的，但只覆盖了两半：
- 提交**格式** → `[DESIGN-GIT-001]` §2 / `[DESIGN-GIT-002]`，守卫 `check-commit-message.js`（pre-commit 第 5 项）

⇒ 判据缺失被转嫁给人：AI 要么改完就提交（半成品入库），要么永不提交（实测暂存区 **3993** 项）。

### ★ 三个实测得出的新判据（值得进长期记忆）

1. **⚠⚠ 执行器强度写死 warning ⇒ `STAGE` 常量变成装饰。**
   初版所有 finding 都 `SEV_WARNING`，结果 **S1 与 S3 跑出完全相同的输出与退出码**
   ⇒ 升到 S3 后**仍然不拦截**，而所有守卫全绿（登记表说 S3、源码常量 S3、漂移比对也过）。
   **表现恰好伪装成 S1 的预期行为** —— 与 `[DESIGN-ARCH-113]` 踩过的坑**同形**。
   修法：`severityFor(criterion)` 单点派生（按阶段 + R/S 判据）。
   **验收判据：同一改动集在 S1/S3 下 `Summary` 的 error 数必须不同**
   （实测：S1 `0 error` exit 0；S3 `1 error` exit 1）。**这条已写成测试用例。**

2. **⚠ 测试副本**不能**落在 `scripts/ci/`。**
   初版把 S3 副本写 `scripts/ci/_ct-timing-S3.js`，而那正是 `check-wiring.js` 的扫描范围 ——
   测试跑的几秒里另一个终端跑 `check:wiring` 会看到它「零接线」而报 **1 error**，
   且**间歇性、极难归因**（「没改任何东西却突然变红」）。
   ⇒ 副本落 `scripts/.ct-timing-tmp/`：仍是 `scripts/` 子目录（`__dirname/../..` 推根层数不变），
   但不在任何守卫 glob 里。**推论：任何「临时脚本」都不要放守卫的扫描目录。**

3. **⚠ `--files=`（空值）与「未提供 `--files`」必须可区分。**
   初版 `argValue()` 对两者都返回 `''` ⇒ 空 `--files=` 会**静默 fall through 到真实暂存集**，
   在本仓读到 3993 项。调用方以为在测空集，其实在测仓库现状。
   ⇒ 单开 `filesArgOrNull()` 返回 `null`。

4. **`--changed` 必须读 `--cached`（暂存区）而非工作区全量。**
   本仓工作区长期 3000~4000 项未提交，按全量判会得到「跨 10 板块 / 3993 文件」
   这种**真实但不可行动**的结论 ⇒ 4 条 finding 变成常驻噪声 ⇒ 噪声被整体忽略
   （**比没有守卫更糟**）。暂存区 = 提交单元，且与 `.githooks/pre-commit` 的
   `git diff --cached` 对齐。工作区视角保留为显式的 `--worktree`。

   → 不该补。A 类 18 个里有 **3 个属后者**。
2. **补别名前必须先跑一次原脚本** —— 否则把已坏的脚本接上别名，只是把「dangling」换成
   「一跑就红」。本次实测 `restore-plan.js --json` 输出合法 JSON 才敢推荐。
3. ⚠ **`dev:frontend` 这类"看着像根命令"的目标，真实命令可能在子包** —— 查 `package.json`

## 提交时机 · 阶段三（实现）—— 判据落到 AI 的实际决策路径

用户三步走「先改规则，再做测试，最后实现」的**最后一步**。阶段一交付了规范+守卫+接线，
但**判据光有守卫不够**：守卫答「这次提交**合不合**判据」，不答「**现在该不该**提交」。
判据不落到 AI 的实际决策路径上，就只是文档里的一段话 —— 正是规范 §1.2
「判据缺失被转嫁给人」的原地复发。

### ★★ 关键发现：`gitCommit` 工具描述是「AI 不知道何时提交」的**机制根源**

`services/backend/src/tools/gitCommit.js`（AI 真正用来提交的工具）原描述是
**`Use it only when the user asks to commit`** —— AI 被明确告知**不要主动提交**。
这就是用户抱怨的成因。⇒ **改机制先改这句**，而不是去教育 AI。

### 落地三层（执行面与阶段迁移**正交解耦**）

| 件 | 位置 | 角色 |
|---|---|---|
| 纯叶子 | `services/backend/src/cli/commitTiming.js`（330 行） | 判据纯函数（零 IO·绝不抛·`KHY_COMMIT_TIMING` 门控）。三结论 `commit-now`/`ask-first`/`do-not-commit` |
| 人用命令 | `services/backend/src/cli/handlers/commit.js` → `khy commit` | 采 git → 交叶子 → 渲染。**默认只判断**，真提交要显式 `--yes` |
| AI 用工具 | `services/backend/src/tools/gitCommit.js` 新增 `checkTiming` | `enforce` 判据不满足**直接拒绝**；`warn`（默认）提交但回传判断；`off` 逐字节回退 |

> **为什么不违反 PP-3「S1/S2 禁止阻断」**：阶段（S1→S4）管**守卫的拦截强度**，
> 执行面管**判据有没有被用**。执行面不引入新拦截通道 —— `khy commit` 是人主动敲的，
> `gitCommit` 是 AI 主动调的，都不是「自动门」。二者正交，执行面在 S1 即可生效。

### ⚠⚠ 踩到的致命假阴性（写了一遍才发现）

`hasVerifyEvidence` 初版用 **`process.uptime()` 当「会话开工时间」** ⇒ CLI 是短命进程，

新增（`scripts/ci/check-change-safety.js`，+40 行）：
```js
function collectDanglingMaintainerPaths(maintainerMap) {
  const dangling = [];
  for (const area of (maintainerMap && maintainerMap.areas) || []) {
    for (const areaPath of (Array.isArray(area.paths) ? area.paths : [])) {
      const normalized = normalizeRepoPath(areaPath);
      if (!normalized) continue;
      if (getMaintainerPathType(normalized) === 'missing') {
        dangling.push({ area: area.id, path: normalized });
      }
    }
  }
  return dangling;
}
```
