## 规范落地自查（审计，未改守卫）

需求：找出 Khy OS 不符合自己规范的地方并设计解决方案。产出：`[IMPL-RPT-060] KhyOS规范落地自查报告-2026-09-21`（已入仓 + `.html` 孪生件 + 索引回写 057~060）。
脚本：`.khyos/diag/audit-spec-compliance.js`（9 项机械检查）、`.khyos/diag/gen-one-twin.js`（单文件生成孪生件，复用 `build_docs_site.js` 导出，避免跑全站的非零副作用）。

**核心病症：规范没被违反，是被架空了**——所有相关守卫全绿，而 15 条规则永不执行。

### 新增判据（★ 高价值）

1. ★★ **`gate=advisory` 是死指针**：`GATE_ORDER.advisory=4 > release=2` ⇒ 15 条（`LAYOUT-005/006/007`、`API-004`、`TOOLING-003`、`DOCS-002`、`IR-001`、`DR-001`、`BACKUP-001`、`NOTIFY-001`、`OPS-002/003`、`FF-001`、`PROMPT-001`、`FE-004`）**任何门档都不跑**。实测 `rules:gate:commit` 只跑 6 个执行器，这 15 条一个不出现。**根因：`gate` 字段混装了两套语义**（强度档位 + 执行方式标签）。正解：gate 只留 `commit|pr|release|manual`，观察期用 `gate=commit + severity=advisory`。
2. ★★ **`p0-unenforced` 红线被 `kind=manual` 绕过**：红线条件是 `priority==='P0' && kind==='unenforced'`，而 `kind` 来自登记表字段、`gate` 不参与推导 ⇒ P0 规则只要 `kind/gate=manual` 就**永久豁免**。实测 `PROCESS-001`（P0 + manual + 零 exec）下 `buildCoverage().redLines === []`，且输出"阻断红线：全部通过"。**这是合法的豁免后门。**
3. ★★ **`coverage.js` 主动放弃阻断权**：`coverageCode()` 只认 `redLines` + `registry.errors`；`unenforced`/`orphans`/`unregisteredCheckers`/`externalRules` **全不阻断**。`:166-168` 注释明写"缺的是登记不是执行，故 `--ci` 下也不阻断"，把最大盲区（31 未登记检查器 + 35 未登记规则 ID）降级为"需人工裁决"——在 `PROCESS-006` 框架下 = 永久挂着。
4. ★ **`check-staged-secrets.js`（148 行，防密钥泄漏）真实挂在 `.githooks/pre-commit:74`）但登记表无对应规则**；`check-commit-message.js` 同理。⇒「有实际在拦人的门，在规则体系里查无此规则」。
5. ★ **台账 `measured` 靠手填、与实测长期脱节**：`cross-layer-require` 台账 37 / 基线 39 / 实测 **18**；`dangling-task` 台账 98 / 基线 88 / 实测 **76**。两项都是 `status=open` ⇒ `check-debt-ledger` 只校验 `closed` 项 ⇒ **填错也没人发现**。违反其自身 `QUAL-1`（基线必须是实测值）。
6. ★ **`severity` 缺失 78/87（90%）**：新写的规则会带（8 条 advisory + 1 条 ratchet），存量普遍没有 ⇒ 强度落执行器默认值，`priority` 与实际强度**无强制绑定**。
7. ★ **守卫自曝范围漂移只当 warning**：`check:json-schemas` 打印"`COMMS-002` 登记的 paths 与本执行器实际扫描范围不一致，属待修缺陷"，但不影响 exit code、不进台账。`paths` 是 `rules:apply` 的输入 ⇒ 失真会让"改这个文件适用哪些规则"给出**错误答案**。

产出：`.khyos/diag/modularity-diagnosis.md`（未改任何源码，纯诊断）。

### ★★ 核心判据：问题是「模块化做了一半」，不是「没有模块化」

- **`SB/src/services/domain/` 已存在完整模块化骨架**：31 个领域、610 个 `.js`
  （trajectory 50 / messaging 49 / project 43 / network 41 / security 35 / maintenance 34 / state 31 / desktop 31 …）。
- **旧轨未迁完**：`SB/src/services/` 根仍平铺 **658 个 `.js`** + **150 个目录** = 811 项
  （认知负荷标准 5–9 ⇒ 超标 90 倍，是全仓最大热点）。
- ⇒ **新轨/旧轨双轨并存** 才是真问题。
