[PROCESS-007] 引导式搜索与压缩保留清单#

规则卡 · 格式依据 [MGMT-STD-008] §1（frontmatter 14 字段 + 六小节）。

字段真源是 docs/10_规范/registry/RULES-REGISTRY.json（GOV-TOOL-006 校验），
本文件由 node scripts/docs/gen-rules-cards.js 生成，禁止手改（同 [MGMT-STD-007] R6 对 .html 孪生件的约束）。
正文原文在 ssot 指向的位置：CLAUDE.md#二行为准则-b1b3（B4/B5）。

约束#

B4 引导式搜索：处理多文件任务必须按 Grep 符号定位 → Glob 列目录 → 仅 Read 2–3 个最相关文件 → 大输出任务先评估委派的顺序执行，禁止无明确目标的大范围读取；定位必须按符号名而非文件名（本仓同名文件多，按名找会改错）。B5 压缩保留清单：上下文压缩必须保留四类信息——① 所有已修改文件的完整路径列表；② 失败的测试用例及错误堆栈；③ 当前任务尚未完成的剩余步骤；④ 本次已跑过的守卫及其结论（三守卫绿灯不得被压缩掉，避免重复跑）。

授予权力#

授权 AI 代理按 B4 的定位顺序自行决定搜索关键词与读取范围，并按 B5 的类别判据自行决定摘要中保留什么，无需事前审批。

提供福利#

把「仓库太大、上下文装不下」从一句正确的空话变成可执行的动作序。实测本仓 docs/ 有 230+ 设计文档与 165+ 规范、AGENTS.md 796 行、toolUseLoopCore.js 12,105 行（单文件约占 1/4 可用上下文），书的算例（20 万 token 窗口实际可用代码空间 ≈3.5–4 万行）在此字面成立。B5 的关键发现是它已具备机制通路：contextCompressor.js:745 已有任务锚点保护（首条 user 消息以 <original_task> 原文注入，上限 1500 字符），:624 的 PreCompact hook 支持 additionalContext —— 故保留清单可由 .khy/hooks.json 的钩子注入压缩提示，不是纯文档约定。

反例#

见 ssot 指向的真源原文；本卡不复制反例，以免与真源漂移。

校验方式#

人工评审（该规则暂无机械守卫）

例外#

单文件任务、目标已明确的一次性读取不适用 B4；B5 的第四类（守卫结论）是 khyos 专属增补，书原样只有前三类；若 PreCompact 钩子返回 blocked 则整轮压缩被跳过，此时 B5 不触发；B4/B5 均属流程约定，无机械守卫，靠人工评审与压缩器日志兜底。
