[PROCESS-009] 提交时机判据（到点就提交）#

规则卡 · 格式依据 [MGMT-STD-008] §1（frontmatter 14 字段 + 六小节）。

约束#

一个提交必须满足五条判据才可提交：T1 单元闭合（只有一个逻辑意图，代码顶层板块跨度 <3）；T2 可运行（改了可执行代码则须有验证证据，落 .khy/feedback/<task-id>/verify.txt，不接受转述）；T3 仓库自洽（暂存集不得含本机态文件，不得卷入 mtime 早于本会话开工的并发方改动）；T4 无游离产物（tmp-* / .tmp / probe / .bak / *.orig 不得入库）；T5 可回滚（改动集 ≤20 个文件，且能单独 revert）。任一 R 判据不满足则不得提交，且必须输出「缺哪一条」。AI 主动提交前还须过四道问询闸：含删除、板块跨度 ≥3、文件数 >20、触及敏感路径四者之一时改为先问人。绝对禁止 git add -A / git add . / git commit -a。

授予权力#

见约束边界：授权 AI 助手在 T1–T4 全绿、无删除、板块跨度 ≤2、文件数 ≤20 且不触敏感路径时不经逐次确认直接执行提交（这是本规则对被授权方的核心让渡）；并授权其在判据不满足时自主选择「不提交并说明缺失项」而无需先征得同意。判据不满足即不再持有该授权。

提供福利#

补上本仓 Git 治理唯一缺失的一半。既有件已成对覆盖提交「格式」（DESIGN-GIT-001 §2 / 002，守卫 check-commit-message.js）与「内容」（DESIGN-GIT-003 §4，pre-commit 前三项），但「什么时候该提交」无任何判据 —— 全仓检索只命中 3 处无关巧合。后果是判据缺失被转嫁给人：AI 要么改完就提交（半成品入库），要么永不提交（实测工作区 4002 项未提交），两条路都不会被任何既有守卫报出来。本规则把「要记住的动作」变成「有判据的结论」。

反例#

见 ssot 指向的真源原文；本卡不复制反例，以免与真源漂移。

校验方式#

人工评审（该规则暂无机械守卫）

例外#

紧急安全修补可在判据未全绿时提交，但须在同一次提交的信息里写明跳过的判据与原因；纯文档单元的 T2（可运行）不适用；发布/回滚类提交按 DESIGN-GIT-001 §5 处理，不适用 T1 的单元闭合。
