[DESIGN-MEM-004] 记忆快速参考卡#

快速查阅记忆时机、模板和命令的参考卡。

记忆时机速查#

✅ 应该记住#

场景示例记忆类型
用户明确偏好"我喜欢简洁回复"feedback
项目架构约定"使用 2 空格缩进"project
技术决策"选择 PostgreSQL 因为..."reference
关键配置"API 端点是..."reference
反复出现的问题"这个错误通常是因为..."feedback

❌ 不应记住#

场景原因
一次性请求"帮我写个 hello world"
临时调试具体的调试过程
过时信息旧版本的配置
过于细节具体的代码行号

类型用途保鲜期示例
user用户身份、核心偏好3650 天语言偏好、工作习惯

project项目背景、技术约定180 天架构设计、代码规范
reference外部资源、参考资料365 天API 文档、工具配置

命令速查#

记忆管理#

# 查看记忆状态
khy memory project

# 记忆蒸馏（清理）
khy memory distill
khy memory distill --apply

# 查看已归档记忆
khy memory distill archived

# 恢复记忆
khy memory distill restore [filename]

记忆创建#

# 快速记忆
/remember 用户偏好简洁回复

# 结构化记忆
/remember --type feedback --name "回复风格" --desc "用户偏好简洁回复" 用户希望回复简洁

# 项目记忆
/remember --type project --name "代码风格" --desc "项目代码规范" 使用 2 空格缩进，单引号

记忆清空#

# 预览清空
npm run memory:clear

# 执行清空
npm run memory:clear:apply

# 按优先级清空
npm run memory:clear:p0  # 核心记忆
npm run memory:clear:p1  # 学习缓存
npm run memory:clear:p2  # 会话数据

# 恢复记忆
npm run memory:restore
npm run memory:restore:all

记忆质量检查#

检查清单#

  • [ ] 信息是否对未来有持久价值？
  • [ ] 信息是否会反复使用？
  • [ ] 是否已存在相似记忆？
  • [ ] 是否选择了正确的记忆类型？
  • [ ] 是否使用了描述性的名称和摘要？
  • [ ] 是否在信息新鲜时记录？

质量指标#

  • 准确性：内容是否正确
  • 时效性：是否仍然相关
  • 完整性：是否包含足够信息
  • 唯一性：是否与其他记忆重复

常见问题#

Q: 什么时候应该创建记忆？#

A: 当信息满足以下条件时：

  • 对未来工作有持久价值
  • 会反复使用或参考
  • 代表用户的稳定偏好或项目的关键约定

Q: 记忆写错了怎么办？#

A: 有几种修复方式：

  • 直接编辑记忆文件
  • 使用 /remember 命令覆盖
  • 运行记忆蒸馏清理错误记忆

Q: 如何避免记忆膨胀？#

A: 遵循以下原则：

  • 只记住核心信息，不记录过程细节
  • 定期运行记忆蒸馏清理过期记忆
  • 使用结构化格式，避免冗长描述

Q: 误删了记忆怎么办？#

A: 使用恢复命令：

# 查看可恢复的记忆
npm run memory:restore

# 恢复所有记忆
npm run memory:restore:all

记忆生命周期#

创建 → 活跃 → 老化 → 归档 → 恢复
  ↑                              ↓
  └──────────────────────────────┘

状态说明#

  • 创建：新记忆写入系统
  • 活跃：正常使用中
  • 老化：接近保鲜期
  • 归档：被蒸馏系统归档
  • 恢复：从归档中恢复

最佳实践#

记忆创建#

  1. 及时性：在信息新鲜时立即记录
  2. 准确性：确保记忆内容正确无误
  3. 结构化：使用标准格式和分类
  4. 描述性：提供清晰的名称和摘要

记忆管理#

  1. 定期维护：每月检查记忆系统
  2. 及时更新：发现过时信息立即更新
  3. 避免冗余：合并相似记忆，删除重复
  4. 质量保证：运行蒸馏清理低质量记忆

记忆使用#

  1. 主动回忆：在需要时主动检索记忆
  2. 上下文关联：将相关记忆关联起来
  3. 验证准确性：使用前验证记忆是否仍然有效
  4. 反馈改进：根据使用效果改进记忆策略
