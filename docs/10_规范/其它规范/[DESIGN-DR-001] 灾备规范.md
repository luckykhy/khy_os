# [DESIGN-DR-001] 灾备规范

<!-- RULES-REGISTRY: DR-001 -->

> **用途**：定义 khy-os 平台的灾难恢复（Disaster Recovery）标准，包括 RTO/RPO 目标、
> 备份策略、故障转移流程、数据一致性保障。
> 当前 BACKUP-001 覆盖备份操作，但无灾备级别的 RTO/RPO 目标和故障切换流程。

---

## 1. 原则

1. **RTO/RPO 可量化**：每个服务有明确的恢复目标和恢复点目标
2. **备份即代码**：备份脚本版本化、可重复执行
3. **定期演练**：至少每季度一次灾备演练
4. **数据主权**：用户数据可导出、可迁移、不锁定
5. **渐进式恢复**：核心功能优先恢复，非核心功能后恢复

---

## 2. 恢复目标

### 2.1 RTO（恢复时间目标）

| 服务 | RTO | 说明 |
|------|-----|------|
| AI 网关 | 15 分钟 | 核心服务，直接影响用户体验 |
| 后端 API | 30 分钟 | 用户认证、数据操作 |
| 前端 | 5 分钟 | CDN 静态资源，可快速切换 |
| 数据库（主库） | 30 分钟 | 切换到从库或恢复备份 |
| 数据库（从库） | 5 分钟 | 提升为主库 |
| 对象存储 | 15 分钟 | 切换到备用存储桶 |
| 监控/日志 | 1 小时 | 非核心，延迟影响可接受 |

### 2.2 RPO（恢复点目标）

| 服务 | RPO | 说明 |
|------|-----|------|
| AI 网关 | 5 分钟 | 对话状态可丢失 |
| 后端 API | 15 分钟 | 用户数据需保障 |
| 数据库（主库） | 15 分钟 | 基于 WAL 归档 |
| 数据库（从库） | 实时 | 流复制 |
| 对象存储 | 1 小时 | 上传文件可重传 |

### 2.3 恢复优先级

```
P0（最先恢复）：AI 网关 → 后端 API → 数据库
P1（随后恢复）：前端 → 监控 → 日志
P2（最后恢复）：文档 → 分析工具 → 非核心服务
```

## 3. 备份策略

### 3.1 备份矩阵

| 数据 | 频率 | 保留 | 类型 | 存储位置 |
|------|------|------|------|----------|
| 数据库（主库） | 每 15 分钟 WAL 归档 + 每日全量 | 30 天 | 增量 + 全量 | 对象存储 + 异地 |
| 数据库（从库） | 实时复制 | 同主库 | 流复制 | 同机房 |
| 用户上传文件 | 实时同步 | 30 天 | 对象存储多副本 | 跨区 |
| 配置/密钥 | 每次变更 | 永久 | Git + 加密归档 | Git + 异地存储 |
| 对话记录 | 每日 | 90 天 | 增量 | 对象存储 |
| AI 模型 | 按需 | 永久 | 对象存储 | 跨区 |

### 3.2 备份验证

```bash
# 每周自动验证备份可恢复性
scripts/backup/verify-restore.sh --backup-id <latest> --dry-run
```

**规则**：
- 备份创建后 24 小时内必须验证可恢复性
- 每月至少一次完整恢复演练
- 备份脚本必须幂等（重复执行不破坏现有备份）

## 4. 故障转移

### 4.1 数据库故障转移

```
检测：主库不可用（心跳检测 > 30s）
    ↓
决策：是否需要切换
  ├─ 预计恢复 < 5min → 等待恢复
  └─ 预计恢复 > 5min → 执行切换
    ↓
操作：
  1. 停止写入主库
  2. 提升从库为主库
  3. 更新连接字符串
  4. 通知所有服务重连
  5. 旧主库恢复后作为从库接入
```

```javascript
// 自动故障转移检测
async function checkDbHealth() {
  const start = Date.now();
  try {
    await db.raw('SELECT 1');
    return { healthy: true, latency: Date.now() - start };
  } catch {
    return { healthy: false, latency: Date.now() - start };
  }
}

// 定期检查（每 10 秒）
setInterval(async () => {
  const health = await checkDbHealth();
  if (!health.healthy) {
    await emitIncident('P1', 'Database primary unreachable');
    // 触发故障转移流程
  }
}, 10000);
```

### 4.2 AI 网关故障转移

```
检测：AI 网关错误率 > 50%
    ↓
降级：按 GW-002 降级链执行
  P0 模型 → P1 模型 → P2 模型 → 缓存响应
    ↓
恢复：主模型恢复后自动回切
```

### 4.3 前端故障转移

```
检测：CDN 节点不可用
    ↓
切换：
  1. DNS 切换到备用 CDN
  2. 或直接返回 fallback 页面
```

## 5. 数据一致性

### 5.1 跨区复制

```
主区（华东） → 异步复制 → 备用区（华北）
```

| 参数 | 值 |
|------|-----|
| 复制延迟目标 | < 30 秒 |
| 复制延迟告警 | > 60 秒 |
| 一致性模型 | 最终一致性（主区优先） |

### 5.2 事务保障

- 写操作必须在主区完成
- 读取可路由到任意区域
- 跨区事务禁止（性能不可接受）

## 6. 演练计划

### 6.1 演练类型

| 类型 | 频率 | 范围 | 说明 |
|------|------|------|------|
| 桌面推演 | 每月 | 团队 | 讨论场景，不实际切换 |
| 部分演练 | 每季度 | 单服务 | 实际切换，但限流 |
| 全量演练 | 每半年 | 全平台 | 完整灾备切换 |

### 6.2 演练清单

```markdown
## 灾备演练检查清单

### 前置准备
- [ ] 通知所有团队成员演练时间
- [ ] 准备回滚方案
- [ ] 确认备份完整性
- [ ] 设置监控面板

### 执行步骤
- [ ] 模拟主库故障（停止主库）
- [ ] 执行故障转移
- [ ] 验证从库可写
- [ ] 验证 API 正常响应
- [ ] 验证前端可访问

### 恢复步骤
- [ ] 恢复主库
- [ ] 重新配置为主库
- [ ] 验证数据一致性
- [ ] 确认监控恢复正常

### 复盘
- [ ] 记录 RTO（实际恢复时间）
- [ ] 记录 RPO（数据丢失量）
- [ ] 记录问题和改进项
```
