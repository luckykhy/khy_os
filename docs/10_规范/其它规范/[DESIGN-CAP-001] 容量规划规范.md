# [DESIGN-CAP-001] 容量规划规范

> **用途**：定义 khy-os 平台的容量规划标准，确保系统在用户增长和数据增长下保持稳定。
> 当前项目无容量规划和性能预算机制。

---

## 1. 原则

1. **数据驱动**：容量决策基于实际指标，而非猜测
2. **提前规划**：至少提前一个季度规划容量需求
3. **渐进扩容**：容量按阶梯式增长，避免过度投入
4. **监控先行**：容量指标持续监控，提前预警
5. **压测验证**：每次扩容后必须通过压测验证

## 3. 容量模型

### 3.1 线性增长模型

```
所需容量 = 当前容量 × (1 + 预期增长率 × 时间)
```

**示例**：
```
当前 API 容量：1000 QPS
预期月增长率：20%
3 个月后需求：1000 × 1.2^3 = 1728 QPS
扩容建议：提升至 2000 QPS（留余量）
```

### 3.2 AI 成本模型

| 模型 | 输入 Token 成本 | 输出 Token 成本 | 日预算上限 |
|------|-----------------|-----------------|-----------|
| Claude Sonnet | ¥12/M | ¥60/M | 按配额 |
| GPT-4o | ¥42/M | ¥84/M | 按配额 |
| 本地模型（Ollama） | 硬件成本 | 硬件成本 | 硬件上限 |

**成本预警**：
- 日费用 > 预估 150% → 黄色预警
- 日费用 > 预估 200% → 红色告警 + 限流

## 4. 压测标准

### 4.1 压测场景

| 场景 | 目标 | 工具 |
|------|------|------|
| API 基准压测 | 找到单实例 QPS 上限 | autocannon / k6 |
| 极限压测 | 找到系统崩溃点 | k6 / JMeter |
| 稳定性压测 | 24h 持续负载 | k6 |
| AI 网关压测 | 模型调用并发上限 | 自定义脚本 |

### 4.2 压测阈值

```
正常：错误率 < 1%，P99 < 500ms
告警：错误率 < 5%，P99 < 1000ms
不可接受：错误率 ≥ 5%，P99 ≥ 1000ms
```

### 4.3 压测执行

```javascript
// k6 压测脚本示例
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '2m', target: 100 },   //  ramp up
    { duration: '5m', target: 100 },   //  steady state
    { duration: '2m', target: 200 },   //  stress
    { duration: '5m', target: 200 },   //  steady at stress
    { duration: '2m', target: 0 },     //  ramp down
  ],
  thresholds: {
    'http_req_duration{max}': ['p(99)<500'],
    'http_req_failed': ['rate<0.01'],
  },
};

export default function () {
  const res = http.get('http://localhost:3000/api/v1/health');
  check(res, {
    'status is 200': (r) => r.status === 200,
    'duration < 500ms': (r) => r.timings.duration < 500,
  });
  sleep(1);
}
```

## 5. 扩容决策流程

```
指标触达预警线
    ↓
确认趋势（持续还是突增）
    ↓
估算增长时间线
  ├─ 3 个月内需要扩容 → 启动扩容流程
  └─ 6 个月以上 → 继续监控
    ↓
扩容方案评估
  ├─ 垂直扩容（升级配置）
  ├─ 水平扩容（增加实例）
  └─ 优化（缓存/压缩/降级）
    ↓
审批 → 执行 → 压测验证 → 上线
```

## 6. 成本控制

### 6.1 成本预警

| 层级 | 触发条件 | 动作 |
|------|----------|------|
| 绿色 | 费用 < 预估 80% | 正常运行 |
| 黄色 | 费用 > 预估 80% | 通知 + 分析原因 |
| 橙色 | 费用 > 预估 150% | 限制非核心用量 |
| 红色 | 费用 > 预估 200% | 触发限流 + 紧急审批 |

### 6.2 AI 成本控制

```javascript
// 日费用追踪
const dailyCostTracker = {
  claude: { used: 0, budget: 1000 },    // ¥1000/天
  openai: { used: 0, budget: 500 },     // ¥500/天
  ollama: { used: 0, budget: 200 },     // 硬件成本折算

  checkBudget(provider) {
    const tracker = this[provider];
    if (tracker.used > tracker.budget * 1.5) {
      return 'RED';    // 限流
    }
    if (tracker.used > tracker.budget) {
      return 'ORANGE'; // 告警
    }
    return 'GREEN';
  }
};
```

## 8. 关键阈值汇总

```
容量预警速查：
  CPU > 60%  → 关注
  CPU > 70%  → 启动扩容
  CPU > 80%  → 紧急处理

  内存 > 70% → 关注
  内存 > 75% → 启动扩容

  错误率 > 1% → 关注
  错误率 > 2% → 启动调查
  错误率 > 5% → 紧急处理

  P99 > 500ms → 关注
  P99 > 800ms → 启动优化
  P99 > 1000ms → 紧急处理
```
