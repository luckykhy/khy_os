[DESIGN-LAY-003] 仓库整理与巡检规范#

定位：管「存量杂物怎么清、每日怎么巡检」。新文件该放哪个目录、该怎么命名、谁能依赖，真源是 [DESIGN-LAY-002]（LAYOUT-001）与 [DESIGN-LAY-005]，本文不重复、不覆盖、不裁决，只补它们没管的下半段：已存在的生成物、临时物、产物如何回收。

结论：① 整理对象只有生成物 / 临时物 / 产物三类，源码、配置、运行时数据零触碰；② 只隔离、不删除，隔离区 .khyos/housekeeping/<日期>/，凭 manifest 原路撤回；③ 全仓 687 个 .html 孪生是 LAY-5 强制要求的合法产出，不是孤儿文件，不得清理——这是本规范最容易被误判的一条。

1. 红线#

每行均可写成守卫断言或评审 checklist 项。守卫列写「人工」表示暂无机械检查。

编号红线触发条件违规后果守卫
HK-1git 已跟踪文件一律不动整理动作命中 git ls-files 结果中止该动作并记入「已拒绝」organize.py
HK-2运行时数据只读触碰 .khy/、.khyos/（除隔离区子目录）中止；可能破坏正在运行的 khy-osorganize.py
HK-3只隔离，不删除整理流程出现 unlink/rmtree/del判违规；淘汰一律进隔离区人工确认人工
HK-4.html 孪生不得当孤儿清理以「无同名 .md」为由删 .html判违规；违反 LAY-5，CI 红灯verify_docs_site.js
HK-5不穿透软链与 junction遍历进入链接目标目录判违规；os.walk 默认会穿透，须显式规避organize.py
HK-6隔离区必须被 gitignore隔离区内容进入 git status判违规；污染工作区状态check-build-artifacts
HK-7单批限流 10 个一次运行移动超过 10 个文件中止后续批次，留待下次organize.py
HK-8不覆盖目标目标路径已存在同名文件自动加 _1 后缀；绝不覆盖organize.py

2. 整理对象白名单#

只有下表三处允许纳入整理范围；其余一律只读。

区域性质判定口径处理方式
.research-tmp/研究过程临时碎片未跟踪、非构建产物超 7 天 → 隔离
_产物/人工成果堆放区（语义：产出即冻结、不再维护，见 LAY-002 §3）未跟踪只报告，去向由人决定
根目录 .html 镜像docs:build 生成物未跟踪、有同名 .md只报告；若生成器可配置输出路径，统一收 docs/_generated/

明确排除：docs/、kernel/、scripts/、tests/、.ai/ 下的 .html —— 它们是 LAY-5 孪生或 Vite/Electron 入口（如 apps/*/index.html），不是垃圾。

3. 风险分级#

级别动作权限
L1 报告生成清单与建议，零改动默认，每次运行都做
L2 隔离移入 .khyos/housekeeping/<日期>/，保留 manifest需显式 --apply，且仅限白名单
L3 删除——永不执行，一律人工确认

4. 每日巡检流程#

06:00  organize.py --report   基线报告（零改动）
       └─ 人工确认后 → --apply  隔离白名单内超期临时文件
  • 脚本：scripts/maintenance/organize.py（仅标准库，无第三方依赖）
  • 报告：90-System/reports/khy-os-<日期>.md（在 agent 工作区，不污染本仓库）
  • 清单：90-System/manifests/khy-os-<日期>-manifest.json

安全兜底：git ls-files 基线为空时，脚本拒绝执行隔离 —— 宁可不干活，也不能凭「未跟踪」误判去搬文件。

5. 反例（易踩的坑）#

做法为什么错
用 scripts/docs/cleanup-orphan-html.js 全仓删孤儿 .html该脚本只应作用于 docs/；全仓跑会误删 apps/*/index.html 等入口文件，且直接删除违反 HK-3
用 os.walk 直接遍历仓库会穿透 junction，误入 .khy/ 运行时目录（HK-5）
把 687 个 .html 孪生当冗余清理它们是 LAY-5 强制的 md/html 孪生对（HK-4）
在仓库脏（大量未提交变更）时搬源码文件移动会产生删除+新增噪音，污染在途重构
用 \\\\?\\ 前缀路径做 relative_to 判定判定失效，会把仓库内链接误报为「越界」

6. 存量债登记（本文不执行，只登记）#

  • _产物/：khy-os不如Y-code_能力差距 存在 3 个并行版本（含 _对抗修复版、_最终对抗版），违反版本命名约定。

【2026-09-17 已处置】 3 个并行版本连同其余临时物共 36 项移入 .khyos/housekeeping/2026-09-17/from-_产物/，台账含 rollback。_产物/ 现已清空（organize.py 实测 _产物条目: 0）。

  • _产物/khy-Trajectory：junction 指向 D:\Portable\.khy（仓库外）；对比根目录 khy-Trajectory → D:\Portable\khy-os\.khy（仓库内，正常）。

【2026-09-17 复核：仍待人工裁定】 实测两者目标不同且内容不同——D:\Portable\.khy 含 api_keys.json、credentials/、custom_providers.json，是另一套独立运行时数据目录，非仓库内 .khy 的重复。按 HK-2（运行时数据只读）与 HK-5（不穿透软链），整理流程不触碰该链接；因链接本身不占空间，_产物/ 已视为清空。是否删除链接或改指仓库内目录，需项目所有者裁定。

  • .research-tmp/：150 个研究碎片，未跟踪且未被 gitignore，会持续出现在 git status。
