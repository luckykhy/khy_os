# [DESIGN-LAY-003] 仓库整理与巡检规范

<!-- RULES-REGISTRY: LAYOUT-004 -->


> **定位**：管「存量杂物怎么清、每日怎么巡检」。新文件该放哪个目录、该怎么命名、谁能依赖，真源是 `[DESIGN-LAY-002]`（LAYOUT-001）与 `[DESIGN-LAY-005]`，本文**不重复、不覆盖、不裁决**，只补它们没管的下半段：已存在的生成物、临时物、产物如何回收。
>
> **结论**：① 整理对象只有**生成物 / 临时物 / 产物**三类，源码、配置、运行时数据**零触碰**；② **只隔离、不删除**，隔离区 `.khyos/housekeeping/<日期>/`，凭 manifest 原路撤回；③ 全仓 687 个 `.html` 孪生是 **LAY-5 强制要求**的合法产出，**不是孤儿文件，不得清理**——这是本规范最容易被误判的一条。

## 1. 红线

> 每行均可写成守卫断言或评审 checklist 项。守卫列写「人工」表示暂无机械检查。

| **编号** | **红线** | **触发条件** | **违规后果** | **守卫** |
|---|---|---|---|---|
| HK-1 | git 已跟踪文件一律不动 | 整理动作命中 `git ls-files` 结果 | 中止该动作并记入「已拒绝」 | `organize.py` |
| HK-2 | 运行时数据只读 | 触碰 `.khy/`、`.khyos/`（除隔离区子目录） | 中止；可能破坏正在运行的 khy-os | `organize.py` |
| HK-3 | 只隔离，不删除 | 整理流程出现 `unlink`/`rmtree`/`del` | 判违规；淘汰一律进隔离区人工确认 | 人工 |
| HK-4 | `.html` 孪生不得当孤儿清理 | 以「无同名 `.md`」为由删 `.html` | 判违规；违反 LAY-5，CI 红灯 | `verify_docs_site.js` |
| HK-5 | 不穿透软链与 junction | 遍历进入链接目标目录 | 判违规；`os.walk` 默认会穿透，须显式规避 | `organize.py` |
| HK-6 | 隔离区必须被 gitignore | 隔离区内容进入 `git status` | 判违规；污染工作区状态 | `check-build-artifacts` |
| HK-7 | 单批限流 10 个 | 一次运行移动超过 10 个文件 | 中止后续批次，留待下次 | `organize.py` |
| HK-8 | 不覆盖目标 | 目标路径已存在同名文件 | 自动加 `_1` 后缀；绝不覆盖 | `organize.py` |

## 2. 整理对象白名单

> 只有下表三处允许纳入整理范围；其余一律只读。

| **区域** | **性质** | **判定口径** | **处理方式** |
|---|---|---|---|
| `.research-tmp/` | 研究过程临时碎片 | 未跟踪、非构建产物 | 超 7 天 → 隔离 |
| `_产物/` | 人工成果堆放区（语义：产出即冻结、不再维护，见 LAY-002 §3） | 未跟踪 | 只报告，去向由人决定 |
| 根目录 `.html` 镜像 | `docs:build` 生成物 | 未跟踪、有同名 `.md` | 只报告；若生成器可配置输出路径，统一收 `docs/_generated/` |

**明确排除**：`docs/`、`kernel/`、`scripts/`、`tests/`、`.ai/` 下的 `.html` —— 它们是 LAY-5 孪生或 Vite/Electron 入口（如 `apps/*/index.html`），**不是垃圾**。

## 3. 风险分级

| **级别** | **动作** | **权限** |
|---|---|---|
| L1 报告 | 生成清单与建议，零改动 | 默认，每次运行都做 |
| L2 隔离 | 移入 `.khyos/housekeeping/<日期>/`，保留 manifest | 需显式 `--apply`，且仅限白名单 |
| L3 删除 | —— | **永不执行**，一律人工确认 |

---

## 4. 每日巡检流程

```
06:00  organize.py --report   基线报告（零改动）
       └─ 人工确认后 → --apply  隔离白名单内超期临时文件
```

- 脚本：`scripts/maintenance/organize.py`（仅标准库，无第三方依赖）
- 报告：`90-System/reports/khy-os-<日期>.md`（在 agent 工作区，不污染本仓库）
- 清单：`90-System/manifests/khy-os-<日期>-manifest.json`

**安全兜底**：`git ls-files` 基线为空时，脚本拒绝执行隔离 —— 宁可不干活，也不能凭「未跟踪」误判去搬文件。

## 5. 反例（易踩的坑）

| **做法** | **为什么错** |
|---|---|
| 用 `scripts/docs/cleanup-orphan-html.js` 全仓删孤儿 `.html` | 该脚本只应作用于 `docs/`；全仓跑会误删 `apps/*/index.html` 等入口文件，且直接删除违反 HK-3 |
| 用 `os.walk` 直接遍历仓库 | 会穿透 junction，误入 `.khy/` 运行时目录（HK-5） |
| 把 687 个 `.html` 孪生当冗余清理 | 它们是 LAY-5 强制的 md/html 孪生对（HK-4） |
| 在仓库脏（大量未提交变更）时搬源码文件 | 移动会产生删除+新增噪音，污染在途重构 |
| 用 `\\\\?\\` 前缀路径做 `relative_to` 判定 | 判定失效，会把仓库内链接误报为「越界」 |
