设计 1 — P1 数据去重 + DEITA 质量分桶#

新增 services/backend/src/services/dataCuration.js（纯函数，零依赖，便于单测）：

  • shingleDedupe(records, { shingleN=6, threshold=0.6 })：对每条 record 的 instruction 取字符 shingle 多重集（N=6），用 Jaccard 系数判近重复，>threshold 视为重复，保留先出现者。返回 { kept, dropped, report }。O(n²) 但 shingle 数有上限（instruction ≤ 12000 字符 → ≤12000 个 shingle），对万级记录可行。
  • deitaScore(record)：三维确定性代理分（0..1），不依赖用户反馈：
    • diversity（0..1）：该 record 的 shingle 集合相对已留集合的新颖度（越大越多样）。
    • quality（0..1）：log(len(output))/log(32000)（长度对数）+ 信息密度（去空白/数字/标点后的字符占比）。
    • complexity（0..1）：代码块/公式/列表标记的加权计数（封顶 1）。
    • score = 0.35*quality + 0.40*complexity + 0.25*diversity（权重偏向复杂样本，符合 DEITA「复杂样本更有训练价值」的取向）。
  • trainValSplit(records, { valRatio=0.05, seed=42 })：确定性 LCG 切分，val 集按 score 降序取（val 保留高分样本做评测门基准）。
  • curateDataset(records, opts)：组合上面三步，返回 { train, val, report:{ dedup, scores, qualityBuckets } }。

接入 exportDataset：当 filter.curate !== false 时，先跑 curateDataset，把 report 附加到返回值（{ path, count, format, dropped, curation }），不改变现有 JSON 格式（下游训练脚本不变）。默认开启，可用 filter.curate=false 退回旧行为。

设计 2 — P2 多教师投票 + 拒采样蒸馏#

改 distill(opts)（modelTrainingService.js）：

  • 新增 teacherModels（string 数组）选项；teacherModel 保持向后兼容（单教师 = [teacherModel]）。
  • 题型配比协议：distill 把 prompts 按长度/是否含代码块/是否含数字分 3 桶（short/code/quant），默认配比 { short: 0.5, code: 0.3, quant: 0.2 }（opts.mixture 可覆盖）。
  • 多教师投票：每个 prompt 对每个 teacher 各生成 1 次响应（gw.generate(prompt, { preferredAdapter:'ollama', model: teacher, temperature:0.3 })）。同 prompt 多 teacher 响应用「两两 Jaccard 相似度」投票：相似度 ≥ voteThreshold（默认 0.5）才视为一致，取投票最多的响应作为学生训练数据。
  • 拒采样：单教师模式下，教师响应用 deitaScore（quality 维度）打分，低于 rejectThreshold（默认 0.25）拒掉，不进训练集。
  • 训练仍走 trainLocal（自动带 P0 的评测门 + 配方快照 + 结构化日志）。

改 CLI train distill（routerDispatchOps.js）：支持 --teacher a,b,c（逗号分隔多教师）+ --teacher-mixture short,code,quant。

设计 3 — P2 模型发现落地#

改 registerWithOllama（backend modelTrainingService.js）：注册成功后追加写 .khy/models-notify.json（{ added: modelName, at: ISO }），供前端下次 loadModels 时合并提示。不引入 WebSocket / 轮询——保持「下次打开页面才看到新模型」的既有节奏，只是把「新模型出现」这个事实落盘成可发现标记。

遗留 / 待人工决策#

  • 前端消费 models-notify.jsonl：标记已落盘，但 apps/ai-frontend 的「新注册」徽章 UI 需前端配合（读标记 → 合并到模型下拉 → 打「新」标），本设计只负责落盘 + 提供 readModelNotify，不碰前端（仓库规则：优先编辑后端既有文件，前端改动需单独评审）

  • ai-backend 侧 modelTrainingService 未同步：本设计只改 backend 侧（真源，数据实际落 .khy/）；ai-backend 侧写死 .khyquant 的死路径未动，两套 service 的收敛需单独立项（见 023 调研）
