## 设计 1 — P2 前端「新注册」徽章 UI（消费 `models-notify.jsonl`）

**后端注入 `isNew`**（`aiManagementServer.js`）：
- 新增 `readNewModels()`：读 `<dataHome>/models-notify.jsonl`，返回最近 7 天内 `event==='model:registered'` 的 `model` 名集合（用 `readModelNotify` 或直接读文件，带 TTL 过滤）。
- `curateModelList` 投影每个 model 时，若 `m.id` 在新模型集合里 → `out.push({ ..., isNew: true })`。字段随既有 `{ id, name, isDefault, ... }` 一并下发，前端 `normalizeModelEntry` 已透传未知字段，无需改前端请求逻辑。
- 7 天 TTL 是常量进 `constants`（不写死），可 env 覆盖。

**前端渲染**（`apps/ai-frontend`）：
- `utils/modelBadges.js` 新增 `newLabel()` / 徽章 helper。
- `AIChat.vue` 模型下拉的 `el-option` 内、`AIGateway.vue` 卡片内，当 `m.isNew === true` 时加一个 `el-tag`「新」徽章（与既有 `默认`/`最近` 同排）。纯展示，不引入轮询/WS。

## 设计 2 — Ollama 一键串联「export → register → distill」提示链路

**改** `routerDispatchOps.js` `train export` 分支：
- 删除误导性残留文案「注册到 Ollama: ollama create …」（实际已自动注册，该行误导用户手敲）。
- register 成功后，若导出的是可训练的 khy 模型（GGUF 成功 + register 成功），追加 next-step 提示：
  ```
  可继续蒸馏: khy train distill --teacher <该Ollama模型名> --prompts-json '[...]'
  该模型已注册到 Ollama，可直接作为蒸馏教师。
  ```
- 这是「串联」的用户侧闭环：export 产物（GGUF）→ 自动 register（Ollama）→ 提示可作为 distill 教师。服务层 `distill` 已支持 `teacherModels` 为 Ollama 名，链路无需新代码，只补提示。

## 设计 3 — ai-backend 侧 `modelTrainingService` 死路径收敛

**改** `services/ai-backend/src/services/modelTrainingService.js`：
- 整文件收敛为**薄转发层**（复用已有 `dataHome.js` 转发先例）：`module.exports = require(path.resolve(__dirname, '../../../backend/src/services/modelTrainingService'))`。
- ai-backend 版独有、backend 版缺失的 API（调研 §4 反向确认）需保留：若 ai-backend 版有 backend 没有的导出，用 spread 合并（backend 为主 + ai-backend 独有兜底）。调研结论 ai-backend 版是 backend 的旧简化拷贝，独有导出为 0，故纯转发即可。
- 该文件 `test/modelTrainingService.fetch.test.js` 引用它 → 转发后测试仍可用（backend 版功能超集）。
- 解决「同一份数据被两个不同路径各写一份」的数据分裂根因：ai-backend 与 backend 从此共用同一份 `resolveTrainingDir()` + `findPython()` + 全套 P0/P1/P2 能力（评测门/配方/日志/去重/蒸馏/notify）。
