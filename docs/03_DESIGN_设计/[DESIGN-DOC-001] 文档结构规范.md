# [DESIGN-DOC-001] 文档结构规范

> 本文档定义 khy-os 项目的文档结构标准，包括命名、分类、存储等。

---

## 1. 文档概述

### 1.1 设计原则

1. **唯一性**：每个文档有唯一的编号
2. **分类清晰**：文档按类别分类存储
3. **命名规范**：统一的命名格式
4. **版本控制**：所有文档纳入版本控制

### 1.2 文档分类

| 类别 | 编号前缀 | 说明 |
|------|---------|------|
| 立项 | INIT | 项目立项文档 |
| 概念 | CONCEPTS | 概念入门文档 |
| 设计 | DESIGN | 设计文档 |
| 实现 | IMPL | 实现文档 |
| 测试 | TEST | 测试文档 |
| 部署 | DEPLOY | 部署文档 |
| 运维 | OPS | 运维文档 |
| 管理 | MGMT | 项目管理文档 |
| 故事 | STORY | 学AI/故事文档 |

---

## 2. 文件命名规范

### 2.1 格式

```
[STAGE-TYPE-NUMBER] 中文名.md
```

### 2.2 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| STAGE | 阶段 | INIT, CONCEPTS, DESIGN, IMPL, TEST, DEPLOY, OPS, MGMT, STORY |
| TYPE | 类型 | ARCH, DOC, RPT, MAN, STD, PLAN, OTHER, PERF, SIZE |
| NUMBER | 编号 | 001, 002, 003... |
| 中文名 | 文档标题 | 仓库层级板块规范 |

### 2.3 示例

```
[DESIGN-ARCH-068] 仓库层级板块规范.md
[OPS-MAN-173] MCP工具接入快速上手.md
[IMPL-RPT-015] 修复记录时间线.md
```

## 5. 文档编号管理

### 5.1 编号分配规则

1. **唯一性**：每个编号只能使用一次
2. **连续性**：编号按顺序分配
3. **预留空间**：每个类型预留足够空间

### 5.2 编号范围

| 类型 | 编号范围 | 说明 |
|------|---------|------|
| ARCH | 001-099 | 架构文档 |
| DOC | 001-099 | 文档规范 |
| RPT | 001-099 | 报告文档 |
| MAN | 001-099 | 手册文档 |
| STD | 001-099 | 标准文档 |
| PLAN | 001-099 | 计划文档 |
| OTHER | 001-099 | 其他文档 |
| PERF | 001-099 | 性能文档 |
| SIZE | 001-099 | 体积文档 |

### 5.3 编号冲突处理

**禁止**：多个文档使用相同编号

**解决**：
1. 保留先创建的文档编号
2. 为新文档分配新编号
3. 更新索引文件

## 6. HTML 文档管理

### 6.1 原则

- **Markdown 为主**：主要文档使用 Markdown 格式
- **HTML 为辅**：HTML 为导出格式，不纳入版本控制

### 6.2 .gitignore 配置

```gitignore
# HTML 导出文件
docs/**/*.html
```
