# [DESIGN-ARCH-102] Khy TUI 统一规则手册

> **隶属**：本文属 **TUI 设计族**（20 编号 / 21 文件），总纲与 scope 裁决见 `[DESIGN-ARCH-122] TUI 设计族总纲`；规则冲突一律以 `[DESIGN-ARCH-102] Khy TUI 统一规则手册` 为准。

> **定位**：Khy 终端界面（TUI）的**唯一规则真源**。同一份文档服务两类读者：
> - **使用者** —— 查「我能做什么、看到的东西是什么意思、出问题怎么办」；
> - **开发者** —— 查「我必须遵守什么、违反会怎样、怎么验证」。
>
> 为此，本文每一条规则都写成**三面对照**：**【用户】** 用户看到/可以做的事 · **【开发】** 实现必须遵守的约束 · **【判据】** 可验证的检查方式。三面同一编号，说明与规范因此不可能分叉。
>
> **取代关系**：本文**取代** [DESIGN-ARCH-079]（界面规范）、[DESIGN-ARCH-103]（渲染架构重设计）、[DESIGN-ARCH-101]（交互规则细则）的**规则部分**。三份原文保留为**设计说明与调研证据**存档（§1.6 给出完整对照）。规则冲突一律以本文为准。
>
> **适用边界**：覆盖 `services/backend/src/cli/tui/` 全部渲染路径。不覆盖：AI 网关、会话持久化、桌面端（这些以各自真源为准）。
>
> **证据基准**：本文所有数值来自 2026-09-15 实际代码勘察；外部结论标注 issue 号。

## 1. 术语表（统一术语）

> **一物一名原则**：一个概念在本文中只有一个规范名。旧名一律停用（§1.4）。

### 1.1 区域术语

| 规范名 | 别名/代号 | 含义 |
|--------|-----------|------|
| **滚动区** | A 区 | 已提交历史（用户消息 / 助手消息 / 工具结果）。**只写不读，永不重绘** |
| **活动区** | B 区 | 唯一可变区：流式输出 / 进行中工具 / 审批 / Toast / 展开动作发生于此 |
| **固定框架** | C 区 | 输入框 + 状态行。不参与滚动 |
| **终端视口** | viewport | 终端当前可见的 `rows × cols` 网格 |
| **滚动历史** | scrollback | 已被推出视口、由终端模拟器缓存的内容。**程序不可修改** |

### 1.2 状态术语

| 规范名 | 含义 |
|--------|------|
| **忙碌** | busy —— 有回合在飞（已发起请求、未收到终态） |
| **停滞** | stalled —— 忙碌中超过 600ms 未收到新数据 |
| **空闲** | 非忙碌、无覆盖层、无待处理请求 |
| **等待用户决策** | awaitingUserChoice —— 权限审批 / 提问等待中 |
| **覆盖层激活** | 有全屏或半屏浮层（ModelPicker / PlanApproval / RewindPicker / FormFlow） |
| **未知尺寸** | 终端未报告 `columns`/`rows`（Windows conpty 常见） |

### 1.3 交互术语（**易混淆，务必区分**）

| 规范名 | 含义 | 对比 |
|--------|------|------|
| **选中** | 让**某个列表项**成为当前目标（focus） | 同组同时只有一个 |
| **选择** | **终端原生文本选择**（鼠标拖选复制） | 由终端提供，程序不得劫持 |
| **展开 / 收起** | 改变**同一元素**的可见内容量（details open/close） | 每元素独立，多个可同时展开 |
| **确认** | 对选中项执行动作（`Enter`） | — |
| **轮次 / 回合** | 一次用户提交 + 其后全部模型输出 | — |

> **为什么必须区分**：这对术语在旧文档中混用，是 §6.3「点击选中 vs 点击展开」规则长期无法收敛的根因。**选中**改变的是「谁是目标」，**展开**改变的是「显示多少」。

### 1.4 渲染术语

| 规范名 | 含义 |
|--------|------|
| **内容宽度** `contentWidth()` | 当前布局下可绘制的列数（看板激活时为 `cols − 看板宽`）。唯一宽度真源 |
| **内容高度** `contentHeight()` | sticky 化后的 `rows`。唯一行高真源 |
| **逻辑行** | 以 `\n` 分隔的行。`split('\n').length` 得到的计数 |
| **视觉行** | 终端软折后**实际占用**的行。与逻辑行不等价，是残影根因所在 |
| **chrome** | 固定、不参与滚动的行数总和（输入框 + 状态行 + Toast + 消息条 + 流式行 + 余量） |
| **帧高** | 一次渲染输出的总行数。硬约束为 ≤ `rows − 1`（H1） |
| **ED0 / ED2 / ED3** | 擦除序列。`ED0`=`ESC[J`（擦光标下方，安全）；`ED2`=`ESC[2J`（推进滚动历史，**禁用**）；`ED3`=`ESC[3J`（清滚动历史，**绝对禁用**） |
| **同步输出** | DEC 2026（BSU/ESU），让终端一次性呈现整帧，消除撕裂。只允许包一层（H3） |
| **行高签名** | 决定某元素占几行的输入哈希。**必须包含展开状态**（H5） |
| **软换行** | 应用不插 `\n`，由终端自行折行。散文段落采用（§6.9） |
| **硬折行** | 应用主动插入 `\n`。代码块/表格采用（§6.9） |
| **禁则（Kinsoku）** | 中文排版规则：部分标点不得位于行首或行尾（§6.9） |
| **带外绘制（rail）** | 用绝对坐标在 ink 渲染区外绘制看板的旧方案。**已废弃**（§10） |
| **尺寸粘性** | 终端瞬时未报告尺寸时，沿用上一有效值而非回落默认值 |

### 1.5 停用的旧名（**一律不再使用**）

| 停用名 | 改用 | 原因 |
|--------|------|------|
| Static 区 / 静态区 | **滚动区** | "静态"易误解为「静态文本」 |
| live 区 / Live Region | **活动区** | 与「直播」混淆 |
| chrome / 底栏组 | **固定框架** | 与浏览器 Chrome 混淆 |
| 右栏 / 侧边栏 / rail / Sidebar | **看板** | 四种叫法并存；`rail` 特指已废弃的带外绘制后端 |
| 提示条 / 通知 | **瞬态消息（Toast）** | — |
| 状态提示（误称 toast） | **瞬时提示（hint）** | 与 Toast 是两种不同机制 |
| 收起（当名词） | **折叠态** | 「收起」保留为动作，「折叠态」为状态 |

## 2. 核心设计原则

八条原则，是 §3 硬约束的上位依据。当约束之间发生冲突时，用原则裁决。

### P1 主屏优先，不切换备用屏
- **【用户】** TUI 在你**原来的终端**里运行：终端自带的滚轮翻历史、鼠标拖选复制、搜索功能**全部照常可用**。
- **【开发】** 禁止使用 alternate screen（`ESC[?1049h`）承载主界面。
- **【判据】** 全仓零 `?1049h`/`?47h` 发射（备用屏场景需显式豁免登记）。
- **为什么**：Gemini CLI 上线 alt-mode TUI 后因用户反对**一周内回滚**；Amp 转 alt mode 被批评「find 找不到屏外文本」。alt mode 破坏文本选择、原生滚动、搜索三个终端核心能力。

### P2 滚动区只写不读
- **【用户】** 已经滚上去的历史**不会变**（进度条不会在历史里跳、旧内容不会被擦）。
- **【开发】** 进入滚动区的内容**永不重绘**；活动区需要更新已呈现内容时，不得回写滚动区。
- **【判据】** 提交后 1000 帧内滚动区字节不变（快照比对）。
- **为什么**：终端的滚动历史程序**不可修改**——这是终端 50 年的设计决定，也是「全屏重绘导致闪烁」的根本来源。

### P3 活动区唯一可变，且有硬上限
- **【用户】** 界面不会突然「整屏跳动」或把历史推走。
- **【开发】** 只有 B 区可逐帧变化；其高度硬上限 = `rows − chrome − 1`（§4.3）。
- **【判据】** H1：任意状态帧高 ≤ `rows − 1`（属性测试，随机 shares 组合）。
- **违反后果**：帧高超限 → 触发 Ink fullscreen 分支 → **每帧重印全部历史**（实测 redraw span 2000+ 行）→ 剧烈抖动与残影。

### P4 宽度与高度各只有一个真源
- **【用户】** 输入框上下边框永远一样长；看板与主区之间不会错位。
- **【开发】** 宽度一律取 `contentWidth()`，高度一律取 `contentHeight()`；**组件内禁止读 `process.stdout`**（H8）。
- **【判据】** 静态扫描：`cli/tui/` 内零 `process.stdout.columns` / `.rows` 直读。
- **违反后果**：各组件按不同尺寸自行重排 → 上下边框不等长、看板与主区错位、折行点不一致。这是用户**直接可见**的界面缺陷，也是历史 bug 复现率最高的一类。

### P5 一个尺寸 = 一次原子重绘
- **【用户】** 拖动窗口大小时界面**干净重排**，不留上一尺寸的内容残片。
- **【开发】** resize 事件 → 120ms 防抖 → **一次**原子 ED0 重绘（§4.6）。禁止逐帧增量修补。
- **【判据】** resize 序列后的屏幕快照 == 相同尺寸冷渲染快照（逐 cell 比对）。
- **违反后果**：旧尺寸的内容残留在新尺寸画面上（**残影**）；逐帧增量修补还会持续放大光标账本误差，使问题从"偶发"变成"必现"。

### P6 键盘必备，鼠标增强
- **【用户】** 不用鼠标也能完成**全部**操作；鼠标让操作更顺手但不提供独占功能。
- **【开发】** 每个鼠标动作必须有等价键位（H9）；鼠标三档 `KHY_MOUSE=off|click|full`，默认 `click`。
- **【判据】** 键位表（§6.1）覆盖全部可点击元素（§6.3）。
- **违反后果**：两个方向都会出问题——缺等价键位则 SSH / tmux / 纯键盘用户**功能不可达**；反向过度依赖鼠标则劫持终端原生选择，用户**无法复制内容**（090 调研中明确反对的反模式）。

### P7 高度恒定，绝不 0→N 跳变
- **【用户】** 内容出现时不会「跳一下把上面的顶走」。
- **【开发】** 元素行数从出现到完成**恒定或单调增长**；禁止先渲染 0 行再补 N 行。
- **【判据】** 工具卡片行数轨迹断言（单调性）。
- **为什么**：这是 Claude Code / Codex / opencode / Pi 四项目共同遵守的防闪烁规则。

### P8 一条路径胜过两条
- **【用户】** 界面行为可预测，不会因配置不同变成"另一个软件"。
- **【开发】** 新增能力时**优先扩展既有路径**，而非新增分支；确需分支必须登记并给出退出条件。
- **【判据】** §10 废弃项只减不增；布局路径恒为 1（§4.4）。
- **违反后果**：分支组合爆炸。现状是 4 条布局路径 × 2 套看板实现 × 2 套状态栏，任一分支未回归，就会产生**只在特定配置下出现**的问题——这类缺陷最难复现、最难修，也是 215 个门控堆积的根源。

## 3. 硬约束（H 系列）

> 每条含【用户】【开发】【判据】三面。违反即阻断合并。

### H1 帧高 ≤ `rows − 1`
- **【用户】** 内容不会被挤到终端最后一行而触发莫名的整屏滚动。
- **【开发】** 任意状态下渲染总行数 ≤ `process.stdout.rows − 1`。chrome 由 §4.3 单一账本计算，组件**不得**自行估算。
- **【判据】** 属性测试：随机输入组合下恒成立。
- **违反后果**：触发 Ink fullscreen 分支 → 每帧全文重印（实测 redraw span 2000+ 行）→ 剧烈抖动。

### H2 零 `ESC[2J` / `ESC[3J`
- **【用户】** 你的终端历史**永远不会被程序清空**。
- **【开发】** 内联路径禁止发射 ED2/ED3；全量重绘一律 `ESC[1;1H` + `ESC[J`（ED0）。
- **【判据】** 全仓静态扫描零命中（CI 门）。
- **违反后果**：ink#935/#990、claude-code#2479 的用户强烈反弹事故。

### H3 同步输出只包一层
- **【用户】** 看不到「画了一半」的撕裂画面。
- **【开发】** DEC 2026（BSU/ESU）由 Ink 内置处理；**禁止**在应用层再加一层包裹。
- **【判据】** 渲染字节中 BSU/ESU 成对且不嵌套。
- **为什么**：双包裹会产生 `bsu+bsu+esu`，内层 `esu` **提前关闭同步** → 撕裂（GitLab duo #2747 实测）。

### H4 输入框上下边框等宽
- **【用户】** 输入框的上下两条边**永远一样长**，不会一长一短或断成两行。
- **【开发】** 两条边框由**同一个函数** `fitBorder(width)` 产出，用显示宽度 pad（CJK 安全）；宽度**只从 props 收**；dev 模式断言 `visWidth(top) === visWidth(bottom) === contentWidth`。
- **【判据】** 覆盖 `cols ∈ {40,79,80,119,120,121,200} × 输入长度 {0,1,79,80,1000} × {ASCII, CJK, emoji, 混合}` 全组合断言。
- **违反后果**：这是用户直接可见的质量问题——两条独立 `'─'.repeat()`（一为 `cols−1`、一为 `cols−1−5`）在宽度取值不一致时必然断裂。

### H5 展开态进入行高签名
- **【用户】** 展开一段长内容后，**再缩放窗口也不会留下残影**。
- **【开发】** 行高签名必须包含展开状态：`signature = hash(kind, wrapCell(text,width).length, expanded)`。状态变 → 签名变 → 布局重算。
- **【判据】** 回归断言：展开 → 签名变化 → 布局重算；展开后 resize 快照与冷渲染一致。
- **为什么**：dsh-TUI 实证——不纳入签名会让「陈旧行高喂给布局扫描」，**直接复现缩放残影**。

### H6 折行与计费同一函数
- **【用户】** 长中文段落、代码块的折行位置正确，不会溢出边界。
- **【开发】** 渲染与行数估算**必须调用同一个** `wrapCell()` / `visualRows()`；禁止"逐分支同源"的手写估算。
- **【判据】** `visualRows(t,w) === wrapCell(t,w).length`（属性测试，1000 组随机输入）。

### H7 门控数量 ≤ 40
- **【用户】** 配置项少而清晰，文档可穷举。
- **【开发】** `cli/tui/` 内唯一 `KHY_*` token ≤ 40；新增用户偏好一律进 `~/.khyquant/tui.json`，不再新增环境变量。
- **【判据】** `check-tui-gates.js` CI 门。
- **背景**：现状 215 个（⚠️ 严重超标）。

### H8 组件不得直读终端尺寸
- **【用户】** 窗口缩放时各组件行为一致，不会有的已重排、有的还是旧尺寸。
- **【开发】** 组件内禁用 `process.stdout.columns` / `.rows`；一律 `contentWidth()` / `contentHeight()`。行高同样走 sticky 缓存（现状仅列宽有）。
- **【判据】** 静态扫描零直读。

### H9 鼠标动作必有等价键位
- **【用户】** 不用鼠标、或在不支持鼠标的终端里，功能完全可用。
- **【开发】** 每个 `onClick`/`onMouseUp` 元素必须在键位表（§6.1）登记等价键。
- **【判据】** 可点击元素集合 ⊆ 键位覆盖集合（测试断言）。

### H10 单槽瞬时信息只有一条
- **【用户】** 提示信息不会叠成一堆。
- **【开发】** 同一槽位（输入框上方 / 看板内）同时只显示一条瞬时信息；新的覆盖旧的并重置 TTL。跨槽位（hint 与 Toast）可共存。
- **【判据】** 连续触发两次 hint，仅渲染一行。

## 4. 布局规范

### 4.1 三区模型

```
┌────────────────────────────────────────────────────────┐
│ A 滚动区（只写不读，永不重绘）                          │
│   已提交历史：用户消息 / 助手消息 / 工具结果            │
├────────────────────────────────────────────────────────┤
│ B 活动区（唯一可变，硬上限 rows − chrome − 1）          │
│   流式输出 / 进行中工具 / 审批 / Toast / 展开动作       │
├────────────────────────────────────────────────────────┤
│ C 固定框架（不参与滚动）                                │
│   ╭──────────────────────────────────────────╮          │
│   │ ❯ 输入内容…                               │ 3~N 行   │
│   ╰──────────────────────────────────────────╯          │
│   Khy · <cwd 简写> · <模型> · <上下文 %>      1 行       │
└────────────────────────────────────────────────────────┘
```

- **【用户】** 上半部分是你和 AI 的对话记录（固定不变），中间是当前正在发生的事，底部永远是输入框和状态行。
- **【开发】** 三区是**唯一**布局路径。窄/宽终端的唯一区别是 B/C 区右侧是否再切出看板（§4.4）。

### 4.2 尺寸公式（单一真源）

| 量 | 公式 | 说明 |
|----|------|------|
| `contentWidth()` | `cols − 看板宽`（看板激活时）否则 `cols` | 唯一宽度真源 |
| `contentHeight()` | sticky 化后的 `rows` | 唯一行高真源；**必须**有 sticky 缓存（⚠️ 现状缺失） |
| 看板宽 | `clamp(round(cols × 0.16), 24, 36)` | ⚠️ 删除 `ccLayout.sidebarWidth`（= `min(30, cols×0.25)`），两者 120 列时分别为 24 与 30 |
| 输入框宽 | `contentWidth()` | 从 props 收，不自取 |
| 输入框高 | `clamp(floor(rows/3), 3, 10)` | ⚠️ 现状为 `max(4, rows−10)` |

- **【判据】** 静态断言 `ccLayout.sidebarWidth === undefined`；组件无 `process.stdout` 直读。

### 4.3 chrome 账本（单一真源）

- **【开发】** chrome（固定不可滚动行数）由 `chromeBudget()` 一处计算：
  `chrome = 输入框行 + 状态行(1) + Toast 行 + 消息条行 + 智能体树行 + 流式行 + 余量(2)`
  `liveBudget = clamp(rows − chrome − 1, 3, …)`
- **【开发】** 组件**不得**各自估算 chrome（现状分散在 `ccLayout.messageAreaCap` / `liveRegionBudget` / `railBottomChrome` 三处，⚠️ 已造成不一致）。
- **【判据】** 所有调用点算出的 chrome 一致（单测）。

### 4.4 响应式（宽度分级）

| 级别 | 列数 | 布局 |
|------|------|------|
| 超窄 | `< 80` | 仅核心输入，无看板，看板功能走 `/tasks` 覆盖层 |
| 窄 | `80 – 119` | 单栏，无看板 |
| 标准 | `≥ 120` | 主区 + 看板（B/C 区右侧切出） |
| 宽 | `≥ 160` | 同上，看板取上限宽 |

- **【用户】** 窗口变窄时看板会**自动收起**，腾出空间给对话；变宽时自动回来。
- **【开发】** 阈值**只**读 `sidebarLayout.minCols()`（可配，默认 120）。⚠️ 删除 `ccLayout.shouldShowSidebar` 的硬编码 `>= 120`。

### 4.5 看板显隐与迟滞

**显示条件（全部满足）**：
1. `KHY_SIDEBAR` 未关（总闸）
2. 渲染后端未关（⚠️ 带外 rail 后端**默认改 off**，见 §10）
3. `cols ≥ minCols()`（默认 120）
4. `rows ≥ minRows()`（默认 24）
5. 主区剩余列 > 0
6. 无覆盖层激活
7. 未知尺寸 → 用 fallback（默认 80）+ 放宽阈值判定 → **显示**（否则 conpty 不报尺寸时看板永久隐藏）

**迟滞与防抖**：

| 机制 | 规则 |
|------|------|
| 双阈值 | 进入 ≥ 120，退出 ≤ 108（12 列死区）🆕 |
| 宽度量化 | 带内宽度量化到 4 的倍数 🆕 |
| resize 防抖 | 120ms ✅ |
| 缩放免疫 | cols/rows 同向变化且比率差 ≤ 0.15 → 判定为字体缩放，**不翻转**显隐 ✅ |
| 尺寸粘性 | 未知尺寸沿用上一有效值 ✅（`KHY_TERM_STICKY_DIMS`） |

- **【用户】** 在 119/120 边界反复伸缩窗口，看板不会闪烁式地反复出现消失。
- **【判据】** 边界序列快照测试。

### 4.6 缩放与重绘

```
resize / 尺寸变化
  → 120ms 防抖
  → ① sticky 化 cols 与 rows
  → ② 纯函数计算新布局（无 IO）
  → ③ ED0 全量重绘：ESC[1;1H + ESC[J
  → ④ DECSC/DECRC 包裹（光标零位移）
```

- **【开发】** 这是**唯一**的全量重绘触发点。软换行内容收费按 `visualRows()`（视觉行）而非逻辑行。
- **【用户】** 缩窗后不会留下上一尺寸的残片。
- **【判据】** resize 序列 `(120→80→200→119→120)` 后快照 == 冷渲染快照。
- **为什么必须 ED0**：ED2/ED3 污染滚动历史（H2）。

### 4.7 输入框布局

```
╭─────────────────────────────────────╮  ← 上边框（fitBorder 产出）
│ ❯ 输入内容…                          │  ← 输入行（多行时扩展）
╰─────────────────────────────────────╯  ← 下边框（同一函数产出）
```

- **【开发】** 折叠标记固定 1 行（`⋯ 上方 N 行`），与边框同属 chrome，一起计费。MIC 按钮移至**输入行内**，不再切割上边框。忙碌态**不改边框颜色**（改左侧 gutter 字符），避免 dim 默认前景在部分终端不可见。
- **【判据】** H4。

- **用途**：启动屏视觉的两份单一真源 —— `cli/tui/logoArt.js`（四叶草 + 字标 + tagline 的

### 6.2 鼠标约定

| 项 | 规则 |
|---|------|
| 三档 | `KHY_MOUSE=off`（不接管）/ `click`（默认，只开 1000+1006）/ `full`（额外开 1003 悬停）。⚠ **自绘选择开启时（`KHY_SELECT`，默认开）追踪档升级为 1002**：需要按住时的位移才能让选区跟手 |
| 触发时机 | 在**松开**时触发，命中松开点；拖出元素则取消 |
| **Shift + 任何鼠标操作** | **程序不拦截**（`isShift/isAlt/isCtrl` 一律放行，且判定**早于** motion/press/release 全部分支）|
| 滚轮 | 走应用内视口（`onWheel`）；未接线时回退终端原生滚动 |
| **【用户】** | 拖选复制、滚轮翻历史**始终可用**；`Shift+鼠标` 走终端原生选择 |

> ⚠ **§6.2 的「Shift 放行」原先是一句无法兑现的承诺（2026-09-17 修正）**：
> 修饰位此前被 `parseSgrMouse` 解析出来却从不检查，且 `return false` 在 ink 侧
> 被丢弃（`use-input.js:112-114`）—— 承诺在文档里，实现侧不存在。
>
> 现在能做到的是「**放行语义**」：不去吞它、也**不画自己的选区**（这是关键 ——
> Shift+拖动位移曾经漏进自绘选区分支，导致两套选区同时出现）。至于终端能否
> 真的接管 Shift+鼠标，取决于终端自身是否上报修饰序列 —— **部分终端不上报**，
> 那种情况下 Shift 与不按 Shift 无法区分。故本表措辞从「永远走终端原生选择」
> 收敛为「程序不拦截」，把终端侧的不确定性诚实标出。
>
> 追踪态下的**主通道是应用内自绘选择**（`KHY_SELECT`），不再依赖终端原生拖选。
> 详见 `[DESIGN-ARCH-119]` §4.2。

> **背景**：mouse tracking 是独占的——开启后终端**收不到**滚轮与拖按。**按下（press）
> 也是「事件」**：它正是原生拖选的起点，被吞掉后终端只剩一团无主位移。
> ⇒ 纪律:**「不报 X」不等于「不报 Y」**——1000 不报位移，但照样上报按下。

### 6.3 点击选中 vs 点击展开

> **一句话判据：点击后元素变高了 → 展开；点击后别的元素失焦了 → 选中。**

| 判据 | **点击展开** | **点击选中** |
|------|-------------|-------------|
| 状态变量 | `expanded`（每元素独立） | `selectedIndex`（同组唯一） |
| 改变什么 | 同一内容的可见量 | 哪个元素是目标 |
| 互斥性 | 多个可同时展开 | 同时只有一个选中 |
| 持久性 | 持久到用户收起 | 焦点移动即失效 |
| 视觉 | **元素高度增加** | 高亮反显，**高度不变** |
| 等价键 | `Ctrl+O` | `Enter` |
| 再点一次 | 收起（toggle） | 无变化（不 toggle） |

| 动作 | 展开 | 选中 |
|------|------|------|
| 点击空白区 | —— | **取消选中**，无副作用 |
| 单选列表 | —— | 单击移焦点，**双击/Enter 才确认** |
| 消息区 | —— | 需先 `v` 进选择模式 |

**展开/收起状态机**：
- 初始：**全部折叠**（工具恒 1 行摘要）
- 点击折叠元素 → 展开；点击展开元素 → 收起
- `Ctrl+O`：**全局**三态循环（全收起 → 全展开 → 仅最新）
- `Esc`：输入非空→清输入；否则收起**最近一个**展开项；否则退栈
- **两条硬规则**：① 展开时不自动收起其它元素 ② **完成时绝不自动收起**（四项目共识）
- 流式中的元素**可点击展开**（dsh-TUI 曾漏掉 streaming 分支）

### 6.4 Spinner（加载指示器）

| 项 | 规则 |
|---|------|
| **出现** | `忙碌 && !等待用户决策 && !覆盖层激活 && 未 suspend`（**全部满足**）✅ |
| 字形 | Braille `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`；帧间隔 **160ms**（LOW_POWER 320ms）⚠️ |
| 文本 | `detail` **优先于** `label`（detail 更具体，如 `读取 src/index.js`）✅ |
| 进度 meta | `· <时长> · ~<tokens> tok`，**仅当 elapsed > 30s** 才显示 ✅ |
| 停滞 | **>600ms** 无新数据 → 字形转红 + `⏳ 等待中 · <detail>` + 文案黄灰**每 600ms** 呼吸 ✅ |
| **消失** | 回合成功/失败/中断/覆盖层唤起。**必须伴随终态内容出现** |
| 高度 | **恒 1 行**（含 meta 追加、含停滞态） |
| reduced-motion | 静态 `●`，无动画 |

- **【用户】** 看到 `⠹` 表示在工作；`⏳ 等待中` 表示还在等（不是卡死）；超过 30 秒才显示已用时和 token 数，短回合保持干净。
- **【判据】** `elapsedSec=0 && tokens=0` 时不出现悬挂的 ` · `；29.9s 不显 meta、30.0s 显；极短回合不留空白行。

### 6.5 反馈（Toast）

**复制反馈文案**（优先级自上而下，命中即返回）：

| 优先级 | 条件 | 文案 |
|--------|------|------|
| 1 | `lines > 1` | `copied N lines` |
| 2 | `bytes > 1024` | `copied N.NKB` |
| 3 | 其余 | `copied N chars` |

- 计数口径：`lines` = 逻辑行；`chars` = **code point**（`[...text].length`，emoji 计 1 而非 2）✅；`bytes` = UTF-8 字节。
- **【用户】** 复制后底部出现 `✓ copied 42 chars`（英文，对齐上游规范）。
- 失败文案按原因给出**修复建议**：gate / native / osc52:tty / oversize（附 KB 数与解除方法）/ 全空。
- 边界：复制**空文本** → **不显示任何反馈**（不是 `copied 0 chars`）；1 字符 → `copied 1 chars`（复数不变）；多行且 >1KB → 报 **lines**（不报 KB）。

**其它 Toast**：成功 3s / 错误 5s / 警告 4s / 信息 3s。

**placeholder**（输入框占位，四级阶梯，自上而下）：

| 优先级 | 条件 | 显示 |
|--------|------|------|
| 1 | plan 复核态 | 复核提示 |
| 2 | 有可编辑排队消息 且 提示未用尽 | 「按 ↑ 编辑排队消息」（上限 **3 次**）✅ |

- **【用户】** 默认**尾随最新内容**；你一向上滚就**自动暂停**，底部出现「已暂停，N 条新消息，按 G 回底」；按 `G`/`End` 恢复尾随。
- **【开发】** 三态单一真源 `scrollActions.js`；偏移量恒 clamp 到 `[0, total − viewport]`。
- **【判据】** 上滚即暂停；`G` 恢复；暂停期间新消息计数正确。

### 6.8 覆盖层

- **【用户】** 全覆盖时（模型选择、计划审批等）看板隐藏、输入框隐藏，但**错误信息不会被吞**（Toast 保留）。
- **【开发】** 优先级见下；退出覆盖层后恢复**原判定**（不重新计算，避免二次跳变）。

**显示优先级（高 → 低）**：
1. 覆盖层（独占） 2. 权限审批（独占输入框区） 3. 错误 Toast 4. 警告 Toast 5. hint 6. 成功/信息 Toast 7. Spinner 8. placeholder

### 6.9 中文换行

> **两条路径，务必区分。**

| 内容类型 | 换行方式 | 断行位置 | 插 `\n`？ | 复制后 |
|----------|---------|---------|-----------|--------|
| **散文段落** | **终端软换行** | 终端在列边界断，**不遵守禁则** | ❌ | 一整段（干净）✅ |
| **代码块 / 表格** | **应用硬折行** | 词边界 + **CJK 禁则** | ✅ | 保留换行 |

**散文（软换行）**：
- 应用不插 `\n`，交给终端折行；行高**必须**按 `visualRows()`（视觉行）计费，不能用逻辑行。
- **已知限制（明确接受）**：终端软折**不遵守中文禁则** → 句号可能落行首。这是换取"复制干净"的代价。**禁止**用插入零宽字符/空格规避——那会污染复制内容。

**代码块/表格（硬折行）**：
1. Tab → 4 空格
2. 切分为「空白 / 非空白」交替串
3. **含 CJK 的 token 装不下** → 与当前行合并后**字符级切分**，把当前行填满（中英混排时不整句下移）
4. **纯拉丁 token** → 保持**整词换行**，绝不词中折断（命令 flag、标识符、路径段都完整）
5. token 自身 > limit → 字符级硬切
6. 换行点落在空白 → **丢弃该空白**（续行不以空格开头）

**禁则（Kinsoku）**：
- **行首禁则**：`，。、；：！？）】》〉」』”’…—` + ASCII `,.;:!?)]}` —— 不得出现在折行后的行首
- **行尾禁则**：`（【《〈「『“‘` —— 不得留在行尾
- 实现：记录 `lastBreak`（最近合法断点），溢出时优先在此断，否则硬断；最多两趟收敛（防死循环）
- 物理下限：单字符宽 > limit → 独占一行（允许超宽），**绝不丢字符**

**宽度度量**：组合符 0 / CJK·全角·Emoji 2 / 其余 1。
- ⚠️ **三处缺陷待修**：① **变体选择符 `U+FE0F` 未计 0 宽** → `❤️` 被算 3 列实际 2 列，折行点与光标每行偏 1 列；② Emoji 区间缺棋牌(`0x1F000–0x1F2FF`)、扩展符号(`0x1FA70–0x1FAFF`)、国旗、ZWJ 序列；③ 组合符区间仅 `0x0300–0x036F`。
- **修法**：迁到 `string-width`（即 H6 的 `wrapCell.js`）。

- **【判据】** `visualRows(t,w) === wrapCell(t,w).length`（1000 组随机输入）；禁则回归：连续句号不落行首、`（` 不悬行尾、`limit=1` 不死循环。

| 中文句号跑到行首 | 散文走终端软换行，**不应用禁则**（已知限制） | 属已知取舍；需要严格排版请让 AI 用代码块输出 |
| 复制带有硬换行 | 代码块/表格本就含换行；散文不应含 | 散文出现此现象属缺陷，提交 bug |
| 终端历史被清空 | ED2/ED3 发射（H2 违规） | 严重，提交 bug |
