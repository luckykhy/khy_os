自 2026-09-15 起，本文的规则条款不再维护，全部并入 [DESIGN-ARCH-102] §6（交互约定）与 §7（使用手册）。
本文保留作为该次规则梳理的过程记录与详细证据存档（含每类规则的完整边界情况表、16 处 hint 触发点全表、CJK 折行算法逐步说明、6 处冲突的裁定论证）。

0. 通用仲裁原则#

这四条适用于本文所有规则，是消歧义的底层依据。

#原则含义
G1同槽位单条同一屏幕位置（同一槽位）同一时刻只显示一条瞬时信息。新信息覆盖旧信息并重置其 TTL，绝不堆叠。
G2必有 TTL所有瞬时信息都有自动消失时限，绝不永久驻留（Spinner 除外——它的存续由「是否有回合在飞」决定，而非时间）。
G3键盘等价每一个鼠标可触发动作都必须有等价的键盘动作。鼠标是增强，键盘是必备（可发现性与无障碍）。
G4高度恒定任何交互引起的显示变化，不得让元素行数从 0 跳到 N（必须恒定或单调增长）。这是 [DESIGN-ARCH-103] §4.3 R1-4 帧高纪律的行为侧对应规则。

0.1 显示优先级（从高到低）#

同一位置出现多个候选时，按下表取最高者，其余隐藏：

级别内容是否独占屏幕
1覆盖层（ModelPicker / PlanApproval / RewindPicker / FormFlow / KhyOsView）独占：隐藏看板、隐藏输入框、Spinner 降级
2权限审批 Prompt（CcPermissionPrompt / PermissionsPrompt）独占输入框区域
3错误 Toast（5s）否
4警告 Toast（4s）否
5hint（1.5s）否
6成功 / 信息 Toast（3s）否
7Spinner（随回合存续）否
8placeholder（空闲态）否

跨槽位可共存：hint 位于输入框上方、Toast 位于消息区底部，两者位置不同，可同时存在（G1 只约束同槽位）。

1. Spinner（加载指示器）#

1.1 出现条件（全部满足才显示）#

#条件说明
1有回合在飞（busy === true）唯一的根本触发条件
2未被覆盖层占用（!_overlayOwnsLive）✅ App.js:5763 的条件链
3非等待用户决策态（!awaitingUserChoice）✅ 同上；等待用户选择时由 Prompt 接管
4终端未 suspend（未进入交互式子命令 / shell 视角）✅

不在任何「空闲轮询」中显示 Spinner。仅在发起 AI 请求到收到终态响应之间存续。

1.2 显示内容（三层，自左向右）#

层内容来源
L1 字形Braille 旋转 ⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏帧间隔 160ms（⚠️ 见 §8 冲突 1）；KHY_TUI_LOW_POWER=1 → 320ms
L2 文本detail 优先于 label（detail 更具体）detail 来自网关，形如 读取 src/index.js；label 是阶段描述，形如 分析约束与计划
L3 进度 meta· <时长> · ~<tokens> tok✅ 仅当 elapsed > 30s 才显示（spinnerMeta.shouldShowTimerAndTokens，门控 KHY_SPINNER_META_GATE）；格式走 ccFormat（90s→1m 30s、1234→~1.2k tok）

reduced-motion（KHY_REDUCED_MOTION=1）：字形固定为静态 ●，不启动动画 interval；L2/L3 内容不变。

1.3 停顿（stalled）状态#

项规则
触发距上次收到流式 chunk > 600ms
表现L1 字形颜色转 red；L2 替换为 ⏳ 等待中 · <detail>
呼吸效果⏳ 等待中 文案颜色在 yellow ↔ gray 间每 600ms 交替，表明"在等，不是死了"
结束收到新 chunk → 立即恢复常规表现，颜色回到 yellow
高度恒定 1 行（停顿不增加行数，遵守 G4）

1.4 消失条件#

场景Spinner 行为同时必须发生
回合正常结束立即消失流式内容提交进 A 区（滚动区），工具折叠为摘要行
回合失败立即消失出现错误 Toast 或错误卡片
用户中断（Ctrl+C）立即消失出现 Interrupted 提示
覆盖层被唤起隐藏由覆盖层接管显示
进程退出随会话清理消失退出清理同步写（fs.writeSync）

硬规则：Spinner 消失必须伴随终态内容出现，不得出现「Spinner 没了但什么都没出现」的空窗（G4 的直接推论）。

1.5 边界情况#

场景期望行为
极短回合（<200ms 完成）Spinner 可能来不及渲染出可见帧。不得因此产生空白行；该回合视为"瞬时完成"
elapsedSec = 0 且 tokens = 0meta 为空串，不出现悬挂的 · 分隔符 ✅（已实现：meta.length ? ... : ''）
elapsedSec = 29.9s不显示 meta
elapsedSec = 30.0s显示 meta；出现不得改变行高（1 行内追加）
tokens = 0 但 elapsedSec = 45只显示时长：⠹ 读取文件 · 45s
detail 为空、label 为空仅显示字形（⠹ ），不留多余空白
终端 cols 极窄（< 20）允许截断，绝不折行（1 行硬约束）
reduced-motion静态 ●，无 interval，停顿呼吸效果也禁用
停顿中途收到 chunk立即恢复，stalled 置 false，呼吸 interval 被清理

2.2 成功文案规则#

单一真源 ccFormatters.formatCopyFeedback(text)。按优先级自上而下，命中即返回：

优先级条件文案示例
1lines > 1copied N linescopied 3 lines
2bytes > 1024copied N.NKBcopied 1.5KB
3其余copied N charscopied 42 chars

计数口径：

  • lines = text.split('\n').length（逻辑行）
  • chars = [...text].length（code point，非 UTF-16 码元）→ emoji 计 1 而非 2 ✅（已修，对齐 Claude Code CHANGELOG 的 emoji 过计数修正）
  • bytes = Buffer.byteLength(text, 'utf8')

展示方式：✓ 图标（绿色）+ 空格 + 文案，单行，紧随消息区底部 toast 槽位。

2.3 失败文案#

单一真源 copyReply.describeClipboardFailure(reasons)，按原因出具含修复建议的文案：

reason文案方向

native系统剪贴板工具不可用（列出平台工具名）
osc52:ttyTTY 环境下不发 OSC 52（避免污染画面）
oversize超过上限，附实际 KB 数与 KHY_CLIPBOARD_MAX_BYTES=0 解除建议
全空无可用通道

2.4 边界情况#

场景期望行为
复制空文本formatCopyFeedback('') → '' → 不显示任何反馈（不得显示 copied 0 chars）
复制 1 个字符copied 1 chars（复数不变，对齐 CC 原文案）
单行但 2KBcopied 2.0KB（优先级 2 先于优先级 3）
多行且 > 1KB报 copied N lines（优先级 1 最高，不报 KB）——刻意取舍：行数比体积更能帮用户确认复制范围
1025 字节(1025/1024).toFixed(1) = 1.0KB → 显示 copied 1.0KB（舍入边界，接受）
3 个 emoji 😀😀😀copied 3 chars ✅
中英混排 20 字copied 20 chars（CJK 按 1 个 code point 计，非 2 列）
复制超过 KHY_CLIPBOARD_MAX_BYTES（默认 100000）不执行复制 + 走 oversize 失败文案
OSC 52 在 Windows Terminal已知不支持且曾有冻结 bug → 必须走原生双通道（clip.exe / powershell）

3. 提示（hint / placeholder / 悬停 tooltip）#

先澄清一件事：Khy 当前没有"悬停 tooltip"系统（全仓 tooltip 仅出现于 App.js 的注释与 promptPlaceholder.js 的文件名）。现有的是两类不同性质的提示：瞬时的 hint 与静态的 placeholder。悬停 tooltip 属 §3.3 新定。

3.1 hint（瞬时提示）✅#

性质：showHint(text) → 单槽状态 + 1500ms TTL，渲染为 dimColor 的 Text，位置在输入框上方的 live 区预留行（App.js:5760，紧邻 streaming 状态行之前）。

触发条件与文案总表：

#触发条件文案来源

2Ctrl+D 首次按下再按一次退出同上
3用户主动停止语音听写已停止语音听写App.js:1023
4静音自动停止听写检测到静音，已自动停止听写同上
5语音停止失败语音停止失败：<reason>App.js:1025
6语音功能不可用语音输入不可用：<reason>App.js:1049,1070

8图片成功附加已附加图 N（Enter 发送，Esc 清除）App.js:1365
9图片被删除<label>已删除，剩余 N 张App.js:1380

规则：

  • 单槽覆盖：新 hint 覆盖旧 hint，并重置 1.5s 计时（G1）
  • 空串即隐藏：hint === '' → 不渲染（hint ? ... : null）
  • 不堆叠：绝不出现两行 hint
  • 高度：占用 live 区的预留行，出现/消失不改变其它元素位置（G4）

⚠️ 语言混用：hint 全部为中文，而复制 Toaster 为英文（copied N chars）。裁决：并存，分工不同——

  • hint = 即时操作反馈（中文，面向用户当下动作）
  • 复制 Toast = CC 规范文案（英文，对齐上游 [DESIGN-ARCH-087] §1）

3.2 placeholder（输入框占位）✅#

性质：静态文本，非瞬时。四级优先级阶梯（单一真源 resolvePromptPlaceholder()，门控 KHY_PROMPT_PLACEHOLDER_LADDER 默认开）。

优先级条件显示备注
1reviewing（plan 复核态）reviewText最高优先，历史行为不变
2queueEditable && !queueHintExhausted && queueHintText形如「按 ↑ 编辑排队消息」提示上限 QUEUE_HINT_MAX_SHOWS = 3 次
3busybusyText（默认空串）刻意留空：忙碌时输入框不显示引导语，避免与 Spinner 抢注意力
4空闲defaultText默认引导串

规则：

  • 只有在输入框为空（value.length === 0）时才显示 placeholder —— 有内容即隐
  • 排队提示计数 只增不减，达 3 次后该档永久失效（会话内）
  • 显式 honest-NA：CC 的 viewing-teammate 档与 example-command 档不做（khy 无对应 substrate，绝不臆造）

3.3 悬停 tooltip 🆕（opt-in）#

项规则
触发条件鼠标悬停在可交互元素上 持续 ≥ 400ms（不是立即——避免移动过程中连续闪烁）
前置门槛需 KHY_MOUSE=full（因悬停依赖 1003 位移追踪，见 [DESIGN-ARCH-103] §4.5）
内容被悬停元素的「完整名称 + 等价快捷键」，形如 展开工具输出（Ctrl+O）
位置元素下方 1 行；若下方空间不足则改为元素上方
消失条件① 鼠标移出元素 ② 发生点击 ③ 悬停后 2s 无操作
高度约束浮层绘制，不占布局 —— 出现/消失绝不改变任何元素行高（G4）
硬约束tooltip 绝不遮挡输入框。下方空间不足且上方也不足时 → 不显示（宁可不显示，不遮挡）

为什么默认不开：1003 追踪是 60~120Hz 事件洪流，持续占用终端输入带宽（mouseButtons.js 头部已论证）。悬停 tooltip 是可选增强，不是必备能力。

3.4 边界情况（提示类通用）#

场景期望行为
hint 为空串不渲染，不占行
hint 连续触发（两次语音失败）第二条覆盖第一条，TTL 重置为 1.5s
hint 与覆盖层同时激活覆盖层优先：hint 隐藏（§0.1 优先级 1 > 5）
placeholder 与 hint 同时存在可共存：placeholder 在输入框内，hint 在输入框上方，位置不同
busy 态 placeholder 为空串输入框不显示引导语（刻意）
tooltip 目标被覆盖层遮住不显示 tooltip
tooltip 触发后元素被移出视口立即消失
悬停时间 399ms 后移出不显示（未达阈值）

4. 点击选择 vs 点击展开#

这是本次需求中最容易混淆的一对交互。核心区分标准如下。

4.1 判别原则（互斥判据）#

看点击后状态变化的性质，而不是看元素类型：

判据点击展开（Expand）点击选择（Select）
状态变量expanded: boolean（每个元素独立一份）selectedIndex / focusedId（同一组只有一份）
改变的是什么改变同一内容的可见量（details open/close）改变哪个元素是当前目标（focus/selection）
语义「同一个东西，多显示一点」「我选定的目标换成了它」
互斥性多个元素可同时处于展开态同组同一时刻只有一个选中
持久性持久到用户收起 / 会话结束焦点移动即失效
视觉表现元素高度变化（行数增加）高亮反显 / 前缀标记，高度不变
等价键盘Ctrl+OEnter（提交）/ Tab·↑↓（移动焦点）
幂等性再点一次 = 收起（toggle）再点已选项 = 无变化（不 toggle）

一句话判据：点击后元素变高了 → 展开；点击后别的元素失焦了 → 选择。

4.2 点击展开的适用场景#

元素收起态（恒 1 行）展开态等价键状态
工具卡片（shell/bash）→ Shell: npm test参数 + 输出（≤12 行预览帽 + … (truncated, N lines)）Ctrl+O✅ 键盘已有 / 🆕 鼠标
工具卡片（generic：Read/Grep 等）→ Read: src/a.js输出（≤3 行；showGenericToolOutput 默认关）Ctrl+O🆕 鼠标
长行（单行 > 1000 字符）前 1000 + … 已折叠 N 字符（点击展开）全文Ctrl+O🆕
思考块▸ 思考 (N 行)全文Ctrl+T✅ 键盘 / 🆕 鼠标

6. 中文段落自然换行#

6.1 两条渲染路径（最关键的区分）#

内容类型换行方式断行位置是否插 \n复制行为
散文段落（助手正文、用户消息、引用块）终端软换行（应用不干预）终端在列边界断开，不遵守禁则❌ 不插无硬换行符 ✅
代码块 / 表格 / 预格式化应用硬折行词边界 + CJK 禁则✅ 插入含硬换行符 ✅

为什么散文走软换行：[DESIGN-ARCH-079] §11 的结论——Ink 的硬换行会插入字面 \n，导致复制长文本时换行符破坏粘贴（opencode 正确、Claude Code 与 Ink 均有此问题）。软换行让终端处理折行，复制时终端会合并软折行 → 得到完整段落。

6.2 散文：终端软换行 🆕（门控默认改 on）#

规则说明
应用输出不插 \n，交给终端 DECAWM 自动折行
行高计费必须按 visualRows(text, width)（= ceil(显示宽度 / width)）计，绝不能用 text.split('\n').length
门控KHY_SOFT_WRAP（现状默认 off，[DESIGN-ARCH-103] §4.3 R1-6 改为默认 on）

已知限制（明确接受并公示）：终端软换行不遵守中文禁则——句号 。、逗号 ， 等可能落在行首。这是"换取复制干净"的代价。

  • 不在散文层插入零宽字符或空格去规避：那会污染复制内容（正是软换行要解决的问题）。
  • 若用户需要严格的禁则排版 → 该内容应放进代码块（走 6.3 的硬折行路径）。
