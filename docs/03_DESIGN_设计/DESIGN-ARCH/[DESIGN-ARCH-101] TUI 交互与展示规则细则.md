## 0. 通用仲裁原则

这四条适用于本文所有规则，是消歧义的底层依据。

| # | 原则 | 含义 |
|---|------|------|
| **G1** | **同槽位单条** | 同一屏幕位置（同一槽位）同一时刻只显示一条瞬时信息。新信息**覆盖**旧信息并**重置其 TTL**，绝不堆叠。 |
| **G2** | **必有 TTL** | 所有瞬时信息都有自动消失时限，**绝不永久驻留**（Spinner 除外——它的存续由「是否有回合在飞」决定，而非时间）。 |
| **G3** | **键盘等价** | 每一个鼠标可触发动作都必须有等价的键盘动作。鼠标是增强，键盘是必备（可发现性与无障碍）。 |
| **G4** | **高度恒定** | 任何交互引起的显示变化，**不得**让元素行数从 0 跳到 N（必须恒定或单调增长）。这是 [DESIGN-ARCH-103] §4.3 R1-4 帧高纪律的行为侧对应规则。 |

### 0.1 显示优先级（从高到低）

同一位置出现多个候选时，按下表取最高者，其余隐藏：

| 级别 | 内容 | 是否独占屏幕 |
|------|------|--------------|
| 1 | 覆盖层（ModelPicker / PlanApproval / RewindPicker / FormFlow / KhyOsView） | **独占**：隐藏看板、隐藏输入框、Spinner 降级 |
| 2 | 权限审批 Prompt（`CcPermissionPrompt` / `PermissionsPrompt`） | **独占输入框区域** |
| 3 | 错误 Toast（5s） | 否 |
| 4 | 警告 Toast（4s） | 否 |
| 5 | hint（1.5s） | 否 |
| 6 | 成功 / 信息 Toast（3s） | 否 |
| 7 | Spinner（随回合存续） | 否 |
| 8 | placeholder（空闲态） | 否 |

**跨槽位可共存**：hint 位于**输入框上方**、Toast 位于**消息区底部**，两者位置不同，可同时存在（G1 只约束同槽位）。

## 1. Spinner（加载指示器）

### 1.1 出现条件（全部满足才显示）

| # | 条件 | 说明 |
|---|------|------|
| 1 | **有回合在飞**（`busy === true`） | 唯一的根本触发条件 |
| 2 | **未被覆盖层占用**（`!_overlayOwnsLive`） | ✅ `App.js:5763` 的条件链 |
| 3 | **非等待用户决策态**（`!awaitingUserChoice`） | ✅ 同上；等待用户选择时由 Prompt 接管 |
| 4 | **终端未 suspend**（未进入交互式子命令 / shell 视角） | ✅ |

> **不在任何「空闲轮询」中显示 Spinner**。仅在发起 AI 请求到收到终态响应之间存续。

### 1.2 显示内容（三层，自左向右）

| 层 | 内容 | 来源 |
|---|------|------|
| **L1 字形** | Braille 旋转 `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` | 帧间隔 **160ms**（⚠️ 见 §8 冲突 1）；`KHY_TUI_LOW_POWER=1` → 320ms |
| **L2 文本** | `detail` **优先于** `label`（detail 更具体） | `detail` 来自网关，形如 `读取 src/index.js`；`label` 是阶段描述，形如 `分析约束与计划` |
| **L3 进度 meta** | `· <时长> · ~<tokens> tok` | ✅ **仅当 elapsed > 30s 才显示**（`spinnerMeta.shouldShowTimerAndTokens`，门控 `KHY_SPINNER_META_GATE`）；格式走 `ccFormat`（`90s`→`1m 30s`、`1234`→`~1.2k tok`） |

**reduced-motion**（`KHY_REDUCED_MOTION=1`）：字形固定为静态 `●`，不启动动画 interval；**L2/L3 内容不变**。

### 1.3 停顿（stalled）状态

| 项 | 规则 |
|---|------|
| **触发** | 距上次收到流式 chunk **> 600ms** |
| **表现** | L1 字形颜色转 **red**；L2 替换为 `⏳ 等待中 · <detail>` |
| **呼吸效果** | `⏳ 等待中` 文案颜色在 **yellow ↔ gray 间每 600ms 交替**，表明"在等，不是死了" |
| **结束** | 收到新 chunk → 立即恢复常规表现，颜色回到 yellow |
| **高度** | **恒定 1 行**（停顿不增加行数，遵守 G4） |

### 1.4 消失条件

| 场景 | Spinner 行为 | 同时必须发生 |
|------|--------------|--------------|
| 回合正常结束 | 立即消失 | 流式内容**提交进 A 区**（滚动区），工具折叠为摘要行 |
| 回合失败 | 立即消失 | 出现错误 Toast 或错误卡片 |
| 用户中断（Ctrl+C） | 立即消失 | 出现 `Interrupted` 提示 |
| 覆盖层被唤起 | 隐藏 | 由覆盖层接管显示 |
| 进程退出 | 随会话清理消失 | 退出清理同步写（`fs.writeSync`） |

> **硬规则**：Spinner 消失**必须伴随终态内容出现**，不得出现「Spinner 没了但什么都没出现」的空窗（G4 的直接推论）。

### 1.5 边界情况

| 场景 | 期望行为 |
|------|----------|
| 极短回合（<200ms 完成） | Spinner 可能来不及渲染出可见帧。**不得**因此产生空白行；该回合视为"瞬时完成" |
| `elapsedSec = 0` 且 `tokens = 0` | meta 为空串，**不出现**悬挂的 ` · ` 分隔符 ✅（已实现：`meta.length ? ... : ''`） |
| `elapsedSec = 29.9s` | **不显示** meta |
| `elapsedSec = 30.0s` | **显示** meta；出现不得改变行高（1 行内追加） |
| `tokens = 0` 但 `elapsedSec = 45` | 只显示时长：`⠹ 读取文件 · 45s` |
| `detail` 为空、`label` 为空 | 仅显示字形（`⠹ `），不留多余空白 |
| 终端 cols 极窄（< 20） | 允许截断，**绝不折行**（1 行硬约束） |
| reduced-motion | 静态 `●`，无 interval，停顿呼吸效果也禁用 |
| 停顿中途收到 chunk | 立即恢复，`stalled` 置 false，呼吸 interval 被清理 |

## 2. 复制成功反馈

### 2.1 三条通道（按入口分流）

| 入口 | 通道 | TTL | 说明 |
|------|------|-----|------|
| CC 模式 `Ctrl+Y`（复制最近助手回复） | **Toast** | 成功 3s / 失败 5s | ✅ 门控 `KHY_CC_COPY_TOAST`；显式 `0` → 回退中文旧文案 |
| legacy `/copy`、`/share` | **hint** | 1.5s | ✅ 走同一 `ccClipboard` 出口 |
| vim `y`（仅写寄存器） | **无反馈** | — | 纯寄存器操作，不触系统剪贴板即不提示 |

### 2.2 成功文案规则

单一真源 `ccFormatters.formatCopyFeedback(text)`。**按优先级自上而下，命中即返回**：

| 优先级 | 条件 | 文案 | 示例 |
|--------|------|------|------|
| 1 | `lines > 1` | `copied N lines` | `copied 3 lines` |
| 2 | `bytes > 1024` | `copied N.NKB` | `copied 1.5KB` |
| 3 | 其余 | `copied N chars` | `copied 42 chars` |

**计数口径**：
- `lines` = `text.split('\n').length`（逻辑行）
- `chars` = `[...text].length`（**code point**，非 UTF-16 码元）→ emoji 计 1 而非 2 ✅（已修，对齐 Claude Code CHANGELOG 的 emoji 过计数修正）
- `bytes` = `Buffer.byteLength(text, 'utf8')`

**展示方式**：`✓` 图标（绿色）+ 空格 + 文案，单行，紧随消息区底部 toast 槽位。

### 2.3 失败文案

单一真源 `copyReply.describeClipboardFailure(reasons)`，按原因出具**含修复建议**的文案：

| reason | 文案方向 |
|--------|----------|
| `gate` | 剪贴板功能被禁用 |
| `native` | 系统剪贴板工具不可用（列出平台工具名） |
| `osc52:tty` | TTY 环境下不发 OSC 52（避免污染画面） |
| `oversize` | 超过上限，附实际 KB 数与 `KHY_CLIPBOARD_MAX_BYTES=0` 解除建议 |
| 全空 | 无可用通道 |

### 2.4 边界情况

| 场景 | 期望行为 |
|------|----------|
| 复制**空文本** | `formatCopyFeedback('')` → `''` → **不显示任何反馈**（不得显示 `copied 0 chars`）|
| 复制 **1 个字符** | `copied 1 chars`（**复数不变**，对齐 CC 原文案）|
| 单行但 2KB | `copied 2.0KB`（优先级 2 先于优先级 3）|
| **多行且 > 1KB** | 报 `copied N lines`（优先级 1 最高，**不报 KB**）——刻意取舍：行数比体积更能帮用户确认复制范围 |
| 1025 字节 | `(1025/1024).toFixed(1)` = `1.0KB` → 显示 `copied 1.0KB`（舍入边界，接受）|
| 3 个 emoji `😀😀😀` | `copied 3 chars` ✅ |
| 中英混排 20 字 | `copied 20 chars`（CJK 按 1 个 code point 计，非 2 列）|
| 复制超过 `KHY_CLIPBOARD_MAX_BYTES`（默认 100000） | **不执行复制** + 走 `oversize` 失败文案 |
| OSC 52 在 Windows Terminal | 已知不支持且曾有冻结 bug → 必须走**原生双通道**（clip.exe / powershell）|

## 3. 提示（hint / placeholder / 悬停 tooltip）

> **先澄清一件事**：Khy **当前没有"悬停 tooltip"系统**（全仓 `tooltip` 仅出现于 App.js 的注释与 `promptPlaceholder.js` 的文件名）。现有的是**两类不同性质的提示**：瞬时的 `hint` 与静态的 `placeholder`。悬停 tooltip 属 §3.3 新定。

### 3.1 hint（瞬时提示）✅

**性质**：`showHint(text)` → 单槽状态 + **1500ms TTL**，渲染为 `dimColor` 的 `Text`，位置在**输入框上方的 live 区预留行**（`App.js:5760`，紧邻 streaming 状态行之前）。

**触发条件与文案总表**：

| # | 触发条件 | 文案 | 来源 |
|---|----------|------|------|
| 1 | `Ctrl+C` **首次**按下 | 再按一次退出 | `App.js:804` 双击确认机制 |
| 2 | `Ctrl+D` **首次**按下 | 再按一次退出 | 同上 |
| 3 | 用户主动停止语音听写 | 已停止语音听写 | `App.js:1023` |
| 4 | 静音自动停止听写 | 检测到静音，已自动停止听写 | 同上 |
| 5 | 语音停止失败 | 语音停止失败：`<reason>` | `App.js:1025` |
| 6 | 语音功能不可用 | 语音输入不可用：`<reason>` | `App.js:1049,1070` |
| 7 | 开始听写 | 语音听写中：内容将进入输入框（再次点击 MIC 或静音自动停止） | `App.js:1061` |
| 8 | 图片成功附加 | 已附加图 `N`（Enter 发送，Esc 清除） | `App.js:1365` |
| 9 | 图片被删除 | `<label>`已删除，剩余 `N` 张 | `App.js:1380` |
| 10 | 图片粘贴不可用 | 图片粘贴不可用 | `App.js:1346` |
| 11 | 剪贴板无图片 | 剪贴板没有图片（也不是图片路径） | `App.js:1359` |
| 12 | 读取剪贴板图片失败 | 读取剪贴板图片失败：`<err>` | `App.js:1369` |
| 13 | 无可回溯对话 | 无可回溯的对话 | `App.js:3425` |
| 14 | 回溯功能不可用 | 回溯不可用 | `App.js:3429` |
| 15 | 回溯执行失败 | 回溯失败 | `App.js:3439` |

**规则**：
- **单槽覆盖**：新 hint 覆盖旧 hint，并**重置 1.5s 计时**（G1）
- **空串即隐藏**：`hint === ''` → 不渲染（`hint ? ... : null`）
- **不堆叠**：绝不出现两行 hint
- **高度**：占用 live 区的**预留行**，出现/消失**不改变**其它元素位置（G4）

**⚠️ 语言混用**：hint 全部为**中文**，而复制 Toaster 为**英文**（`copied N chars`）。**裁决：并存**，分工不同——
- hint = **即时操作反馈**（中文，面向用户当下动作）
- 复制 Toast = **CC 规范文案**（英文，对齐上游 `[DESIGN-ARCH-087] §1`）

### 3.2 placeholder（输入框占位）✅

**性质**：静态文本，非瞬时。四级**优先级阶梯**（单一真源 `resolvePromptPlaceholder()`，门控 `KHY_PROMPT_PLACEHOLDER_LADDER` 默认开）。

| 优先级 | 条件 | 显示 | 备注 |
|--------|------|------|------|
| 1 | `reviewing`（plan 复核态） | `reviewText` | 最高优先，历史行为不变 |
| 2 | `queueEditable && !queueHintExhausted && queueHintText` | 形如「按 ↑ 编辑排队消息」 | 提示上限 **`QUEUE_HINT_MAX_SHOWS = 3`** 次 |
| 3 | `busy` | `busyText`（**默认空串**） | **刻意留空**：忙碌时输入框不显示引导语，避免与 Spinner 抢注意力 |
| 4 | 空闲 | `defaultText` | 默认引导串 |

**规则**：
- 只有在**输入框为空**（`value.length === 0`）时才显示 placeholder —— 有内容即隐
- 排队提示计数 **只增不减**，达 3 次后该档永久失效（会话内）
- 显式 `honest-NA`：CC 的 `viewing-teammate` 档与 `example-command` 档**不做**（khy 无对应 substrate，绝不臆造）

### 3.3 悬停 tooltip 🆕（opt-in）

| 项 | 规则 |
|---|------|
| **触发条件** | 鼠标悬停在可交互元素上 **持续 ≥ 400ms**（不是立即——避免移动过程中连续闪烁） |
| **前置门槛** | 需 `KHY_MOUSE=full`（因悬停依赖 1003 位移追踪，见 [DESIGN-ARCH-103] §4.5） |
| **内容** | 被悬停元素的「**完整名称** + **等价快捷键**」，形如 `展开工具输出（Ctrl+O）` |
| **位置** | 元素**下方 1 行**；若下方空间不足则改为元素**上方** |
| **消失条件** | ① 鼠标移出元素 ② 发生点击 ③ 悬停后 2s 无操作 |
| **高度约束** | **浮层绘制，不占布局** —— 出现/消失绝不改变任何元素行高（G4） |
| **硬约束** | **tooltip 绝不遮挡输入框**。下方空间不足且上方也不足时 → **不显示**（宁可不显示，不遮挡） |

**为什么默认不开**：1003 追踪是 60~120Hz 事件洪流，持续占用终端输入带宽（`mouseButtons.js` 头部已论证）。悬停 tooltip 是可选增强，不是必备能力。

### 3.4 边界情况（提示类通用）

| 场景 | 期望行为 |
|------|----------|
| hint 为空串 | 不渲染，不占行 |
| hint 连续触发（两次语音失败） | 第二条覆盖第一条，TTL 重置为 1.5s |
| hint 与覆盖层同时激活 | **覆盖层优先**：hint 隐藏（§0.1 优先级 1 > 5） |
| placeholder 与 hint 同时存在 | **可共存**：placeholder 在输入框内，hint 在输入框上方，位置不同 |
| busy 态 placeholder 为空串 | 输入框**不显示**引导语（刻意） |
| tooltip 目标被覆盖层遮住 | 不显示 tooltip |
| tooltip 触发后元素被移出视口 | 立即消失 |
| 悬停时间 399ms 后移出 | 不显示（未达阈值） |

## 4. 点击选择 vs 点击展开

这是本次需求中**最容易混淆**的一对交互。核心区分标准如下。

### 4.1 判别原则（互斥判据）

**看点击后状态变化的性质，而不是看元素类型**：

| 判据 | **点击展开**（Expand） | **点击选择**（Select） |
|------|------------------------|------------------------|
| 状态变量 | `expanded: boolean`（**每个元素独立一份**） | `selectedIndex` / `focusedId`（**同一组只有一份**） |
| 改变的是什么 | 改变**同一内容的可见量**（details open/close） | 改变**哪个元素是当前目标**（focus/selection） |
| 语义 | 「同一个东西，多显示一点」 | 「我选定的目标换成了它」 |
| 互斥性 | **多个**元素可同时处于展开态 | 同组同一时刻**只有一个**选中 |
| 持久性 | 持久到用户收起 / 会话结束 | 焦点移动即失效 |
| 视觉表现 | **元素高度变化**（行数增加） | 高亮反显 / 前缀标记，**高度不变** |
| 等价键盘 | `Ctrl+O` | `Enter`（提交）/ `Tab`·`↑↓`（移动焦点） |
| 幂等性 | 再点一次 = 收起（toggle） | 再点已选项 = 无变化（不 toggle） |

> **一句话判据**：**点击后元素变高了 → 展开；点击后别的元素失焦了 → 选择。**

### 4.2 点击展开的适用场景

| 元素 | 收起态（恒 1 行） | 展开态 | 等价键 | 状态 |
|------|-------------------|--------|--------|------|
| 工具卡片（shell/bash） | `→ Shell: npm test` | 参数 + 输出（≤12 行预览帽 + `… (truncated, N lines)`） | `Ctrl+O` | ✅ 键盘已有 / 🆕 鼠标 |
| 工具卡片（generic：Read/Grep 等） | `→ Read: src/a.js` | 输出（≤3 行；`showGenericToolOutput` 默认关） | `Ctrl+O` | 🆕 鼠标 |
| 长行（单行 > 1000 字符） | 前 1000 + `… 已折叠 N 字符（点击展开）` | 全文 | `Ctrl+O` | 🆕 |
| 思考块 | `▸ 思考 (N 行)` | 全文 | `Ctrl+T` | ✅ 键盘 / 🆕 鼠标 |
| 任务项 | `→ 修复 Bug A` | 详情 + 耗时 | `Enter` | 🆕 |
| 已完成任务组 | `✓ 12 已完成` | 展开列表 | `Enter` | 🆕 |

**展开的实现纪律**（[DESIGN-ARCH-103] §4.5 的四条硬约束）：
1. 折叠在**进入布局引擎之前**完成（纯叶子 `foldLongLines()`）：保留 markdown/diff 行边界、代理对不劈半、短文本走零分配快路径
2. **展开状态必须进"行高签名"** —— 否则布局扫描拿到陈旧行高，直接复现缩放残影
3. **流式中的元素也支持点击展开**（dsh-TUI 曾漏掉 `streaming` 分支导致行为不一致）
4. 遵守 §0 G4 高度恒定 + §4.4 的"不自动折叠"

### 4.3 点击选择的适用场景

| 元素 | 单击行为 | 提交行为 | 备注 |
|------|----------|----------|------|
| 单选列表（`CcSelectable` / `ModelPicker` / `RewindPicker`） | **选中**（移动焦点到该项） | **双击** 或 `Enter` 才提交 | 单击仅移动焦点，防止误操作 |
| 多选列表（`CcMultiSelectList`） | 切换勾选态 | `Enter` 确认整组 | 视觉用 `[x]` / `[ ]` |
| 任务项 | 选中（进入焦点） | `Enter` 展开详情 | 与 §4.2 协同：**选中**是焦点动作，**展开**是 details 动作 |
| 斜杠补全菜单（`CompletionMenu`） | 选中 | `Tab` / `Enter` 补全 | — |
| 消息区 | **默认不可点选** | — | 需先按 `v` 进入选择模式（避免误触） |
| 权限审批选项 | 选中 | 单击即执行（该场景下**选中与提交合并**） | 因为有 `Esc` 可退出，且属高频路径 |

**点击空白区域的统一规则**：**取消选择**，不展开任何东西，不产生任何副作用。

### 4.4 展开 / 收起逻辑（状态机）

**初始态**：全部元素**收起**（工具恒 1 行摘要）。

```
                 点击收起元素 / Ctrl+O
    ┌─────────┐ ─────────────────────────► ┌─────────┐
    │  收起   │                            │  展开   │
    └─────────┘ ◄───────────────────────── └─────────┘
                 点击展开元素 / Ctrl+O / Esc
```

| 动作 | 行为 |
|------|------|
| **点击收起元素** | 展开该元素（仅该元素） |
| **点击展开元素** | 收起该元素 |
| `Ctrl+O` | **全局**三态循环：全部收起 → 全部展开 → 仅最新一个展开 → 全部收起 |
| `Esc`（输入框非空） | 清空输入（**不清**任何展开态） |
| `Esc`（输入框为空） | 收起**最近一个**展开项；若无展开项 → 用于中断 / 退栈 |
| 元素从 live 区提交进 A 区 | **展开态随内容一起冻结**（提交后不再可变） |

**五条硬规则**：

1. **展开时不自动收起其它元素**（多元素可同时展开）
2. **完成时绝不自动收起**（对齐 Claude Code / Codex / opencode / Pi 四项目共识的 Rule 2）
3. **同组内不互斥**（展开互不干扰）
4. **展开状态持久**：直到用户主动收起或会话结束
5. **展开态参与行高签名**（见 §4.2 纪律 2）

### 4.5 命中测试与鼠标档位

| 项 | 规则 |
|---|------|
| 命中机制 | 复用 `mouseButtons.hitTest()`（yoga 累计坐标 + 静态区跳过）✅ 基建已有 |
| 触发时机 | 在**松开**（`onMouseUp`）时触发，命中松开点；拖出元素则取消（对齐 opencode 语义）✅ |
| 热区 | 折叠标记行**整行可点**（不是只点文字） |
| `Shift + 点击` | **永远走终端原生选择**，不触发展开/选择。这是 xterm 标准行为，必须在帮助菜单公示 |
| 滚轮 | 一律 `fireNative()` → 交回终端原生滚动 |
| `KHY_MOUSE=off` | 全部鼠标交互禁用，仅键盘可用 |

### 4.6 边界情况

| 场景 | 期望行为 |
|------|----------|
| 点击正在展开动画中的元素 | **幂等**：不重复触发，不叠加动画 |
| 展开后内容超过 live 区预算 | 元素内部滚动，**绝不撑破帧高**（G4） |

## 5. 右侧任务看板显示时机

### 5.1 显示条件（**全部**满足才显示）

| # | 条件 | 默认值 | 门控 |
|---|------|--------|------|
| 1 | 总闸未关 | ON | `KHY_SIDEBAR`（`0/false/off/no` 关） |
| 2 | 渲染后端未关 | ON | `KHY_SIDEBAR_RAIL`（⚠️ `[DESIGN-ARCH-103]` 后**默认改 off**，回退 in-tree 看板） |
| 3 | **列数 ≥ 最小列数** | **120** | `KHY_SIDEBAR_MIN_COLS` |
| 4 | **行数 ≥ 最小行数** | **24** | `KHY_SIDEBAR_MIN_ROWS` |
| 5 | 主区仍剩余可用列（`mainColumnCols(cols) > 0`） | 隐含 | 防止用户把宽度调到占满整屏 |
| 6 | 未被覆盖层占用 | 隐含 | §0.1 优先级 1 |
| 7 | 未知尺寸时用 fallback 尺寸 + **放宽阈值** | fallback 80 列 | `KHY_TERM_FALLBACK_COLS` / `KHY_SIDEBAR_MIN_COLS_FALLBACK`（默认 80） |

> **条件 7 的用意**：Windows conpty / PowerShell 可能**从不报告终端尺寸**。此时若仍用 120 列硬门槛，看板会**永久隐藏**。故未知尺寸时按 `fallbackCols`（默认 80）与放宽阈值（默认 80）判定 → **显示**。

### 5.2 隐藏条件（**任一**满足即隐藏）

| # | 触发 |
|---|------|
| 1 | 列数降到「最小列数 − 死区」以下（见 §5.3） |
| 2 | 行数 < 最小行数（默认 24） |
| 3 | 用户显式切换：`Ctrl+T`（Legacy）或看板聚焦键（默认 `b`） |
| 4 | 覆盖层激活（ModelPicker / PlanApproval / RewindPicker / FormFlow） |
| 5 | 终端宽度不足以同时容纳主区最小宽度 |
| 6 | `KHY_SIDEBAR=0` 或 `KHY_SIDEBAR_RAIL=0` |

### 5.3 迟滞与防抖（防抖动是硬要求）

| 机制 | 规则 | 目的 |
|------|------|------|
| **进入/退出双阈值** | 进入需 **≥120**，退出需 **≤108**（12 列死区）🆕 | 消除 119↔120 边界的反复翻转 |
| **宽度量化** | 带内宽度量化到 4 的倍数 🆕 | 带内 1~3 列抖动**不改变**窄化值 → 不触发全树 reflow |
| **resize 防抖** | **120ms** ✅ | 拖拽 resize 期间不逐帧重算 |
| **缩放免疫** | cols/rows **同向**变化且比率差 **≤ 0.15** → 判定为字体缩放（zoom），**不翻转**显隐判定 ✅ | Ctrl+滚轮缩放不误判为窗口变化 |
| **尺寸粘性** | 未知尺寸时**沿用上一有效值** ✅（`KHY_TERM_STICKY_DIMS` 默认开） | conpty 帧间 `120 → undefined → 120` 抖动不引发翻转 |
| **全屏启发** | 当前尺寸 ≈ 会话最大尺寸（容差 2）才进入"全屏"判定 ✅ | 终端无法读 OS 的"窗口已最大化"信号，用会话内最大值近似 |

### 5.4 边界情况

| 场景 | 期望行为 |
|------|----------|
| 恰好 **120 列** | **显示** |
| **119 列** | **仍显示**（处于死区内，维持上次判定） |
| **108 列** | **隐藏** |
| **110 列**（从 121 降下来） | 仍显示（死区内）；从 100 升上来 | 仍隐藏（死区内）→ 死区是**双向**的 |
| conpty 报 `undefined` | 沿用 sticky 值，**不隐藏** |
| 首次启动即报 `undefined` | 用 fallback（80）+ 放宽阈值（80）判定 → **显示** |
| 列数 = 100，但 `KHY_SIDEBAR_MIN_COLS=100` 已设 | **显示**（阈值可配） |
| 终端 120 列但仅 20 行 | **隐藏**（行数门槛优先于列数门槛） |
| 看板被覆盖层遮挡后退出覆盖层 | **恢复原判定**（不重新计算，避免二次跳变） |
| 窄终端按 `Ctrl+T` | 显示 hint，文案中引用**同一 `minCols()`** 数值（不得硬编码 120）|
| **任务列表为空** | **显示 1 行「暂无任务」占位，不隐藏** 🆕（见下方裁决） |
| 用户把 `KHY_SIDEBAR_WIDTH` 设为 ≥ 终端宽度 | 隐藏（`width >= cols` → 无空间）|

> **裁决：空看板显示占位而非隐藏**。
> 现状 `railGeometry` 在 `height <= 0` 时返回 `off`（"empty board → reserve nothing"），但 `railLayout` 注释又提到「暂无任务」占位——两者语义冲突（§8 冲突 4）。
> **本次裁决：显示 1 行「暂无任务」占位**。理由：隐藏会导致**主区宽度跳变**（看板占用的 24~36 列瞬间还给主区）→ 触发全树一次 reflow → 正是 [DESIGN-ARCH-103] §4.3 R1-2 要消除的残影诱因。宽度稳定性优先于"节省 1 行"。

## 6. 中文段落自然换行

### 6.1 两条渲染路径（**最关键的区分**）

| 内容类型 | 换行方式 | 断行位置 | 是否插 `\n` | 复制行为 |
|----------|----------|----------|-------------|----------|
| **散文段落**（助手正文、用户消息、引用块） | **终端软换行**（应用不干预） | 终端在**列边界**断开，**不遵守禁则** | ❌ 不插 | 无硬换行符 ✅ |
| **代码块 / 表格 / 预格式化** | **应用硬折行** | **词边界 + CJK 禁则** | ✅ 插入 | 含硬换行符 ✅ |

> **为什么散文走软换行**：[DESIGN-ARCH-079] §11 的结论——Ink 的硬换行会插入字面 `\n`，导致**复制长文本时换行符破坏粘贴**（opencode 正确、Claude Code 与 Ink 均有此问题）。软换行让终端处理折行，复制时终端会合并软折行 → 得到完整段落。

### 6.2 散文：终端软换行 🆕（门控默认改 on）

| 规则 | 说明 |
|------|------|
| 应用输出 | **不插 `\n`**，交给终端 DECAWM 自动折行 |
| 行高计费 | **必须**按 `visualRows(text, width)`（= `ceil(显示宽度 / width)`）计，**绝不能**用 `text.split('\n').length` |
| 门控 | `KHY_SOFT_WRAP`（现状默认 off，[DESIGN-ARCH-103] §4.3 R1-6 改为**默认 on**） |

**已知限制（明确接受并公示）**：终端软换行**不遵守中文禁则**——句号 `。`、逗号 `，` 等**可能落在行首**。这是"换取复制干净"的代价。
- **不在散文层插入零宽字符或空格去规避**：那会污染复制内容（正是软换行要解决的问题）。
- 若用户需要严格的禁则排版 → 该内容应放进**代码块**（走 6.3 的硬折行路径）。

### 6.3 代码块 / 表格：硬折行 + 禁则 ✅

算法（单一真源 `_wrapRawToWidth(raw, maxWidth, measureFn)`）：

| 步 | 规则 |
|----|------|
| 1 | Tab → **4 个空格** |
| 2 | **Tokenize** 为「空白 / 非空白」交替串：`text.match(/\s+|\S+/g)` |
| 3 | 逐 token 累计宽度；`curW + tokW <= limit` → 追加到当前行 |
| 4 | **含宽字符（CJK）的 token 装不下剩余空间** → 与当前行**合并**后走 `_hardSplitToken` 字符级切分，**把当前行填满**（避免中英混排时整句被推到下一行） |
| 5 | **纯拉丁 token**（无宽字符）→ 保持**整词换行**，**绝不词中折断**（命令 flag、标识符 `FullName`、路径段都不切） |
| 6 | token 自身宽度 **> limit** → 与当前行合并后**字符级硬切**（长路径 / hash / 无空格 CJK 串） |
| 7 | 换行点若落在**空白** → **丢弃该空白**，续行不以空格开头 |

**禁则（Kinsoku）** —— 仅在字符级切分（`_hardSplitToken`）内生效：

| 规则 | 字符集（`_NO_BREAK_BEFORE`，**不得出现在折行后的行首**） |
|------|--------------------------------------------------------|
| **行首禁则** | `，。、；：！？）】》〉」』”’…—` + ASCII `,.;:!?)]}` |

| 规则 | 字符集（`_NO_BREAK_AFTER`，**不得留在行尾**） |
|------|----------------------------------------------|
| **行尾禁则** | `（【《〈「『“‘` |

**实现要点**：
- 扫描时记录 `lastBreak` = 最近一个**合法**断点（同时满足「当前字符不在 `_NO_BREAK_BEFORE`」且「前一字符不在 `_NO_BREAK_AFTER`」）
- 溢出时优先在 `lastBreak` 断开，否则在当前位置 `i` 硬断
- **最多两趟收敛**：在禁则合法点切分后，携带的余量可能仍溢出 → 第二趟在 `i` 硬切（防死循环）

**物理下限**：单字符宽度 **> limit**（如 `limit = 1` 时的中文）→ 该字符**独占一行**，允许超宽输出。**绝不丢字符，绝不死循环**。

### 6.4 宽度度量 `_charDisplayWidth`

| 类别 | 宽度 |
|------|------|
| 组合符 `U+0300–U+036F` | **0** |
| CJK / 全角 / Emoji（12 个区间：CJK 统一表意、扩展 A/B、韩文、全角标点、假名、注音、相容表意、`0x1F300–0x1F9FF` 等） | **2** |
| 其余 | **1** |

**⚠️ 已知缺陷（需修，迁到 `wrapCell.js` / `string-width`）**：

| # | 缺陷 | 后果 |
|---|------|------|
| 1 | **变体选择符 `U+FE0F` 未计为 0 宽** | `❤️`（`U+2764` + `U+FE0F`）算作 2+1=**3 列**，实际渲染 2 列 → 折行点与光标每行偏 1 列 |
| 2 | **Emoji 区间不全** | 缺 `0x1F000–0x1F2FF`（麻将/多米诺/扑克）、`0x1FA70–0x1FAFF`（扩展符号）、区域指示符（国旗）、ZWJ 序列 |
| 3 | **组合符区间不全** | 仅覆盖 `0x0300–0x036F`，缺 `0x1AB0–0x1AFF`、`0x20D0–0x20FF` |

### 6.5 边界情况

| 场景 | 期望行为 |
|------|----------|
| 连续 80 个中文句号**无空格** | 每字符可断，但 `。` 受**行首禁则**保护 → **句号不落行首** |
| 中文段落内含**长 URL** | URL 是纯拉丁 token 且 > limit → 走**字符级硬切**（可读性差但守住边界，不溢出） |
| `（` 恰好落在行尾 | 受**行尾禁则**保护 → **提前断开**，`（` 移到下一行 |
| 混排 `abc中文中文中文` | 该 token 含宽字符 → 走字符级切分，**填满当前行**（不整句下移） |
| `limit = 1` + 单个中文 | **独占一行**（允许超宽），不死循环、不丢字符 |
| 含 emoji + VS16 | ⚠️ 当前**多算 1 列**（缺陷 1） |
| 行末空格 | **丢弃**（续行不以空格开头） |
| 全角空格 `U+3000` | 被 `\s` 匹配 → 按空白处理 ✅ |
| 宽度为 0 的字符（组合符） | 不触发折行，不占列 ✅ |
| 空字符串 / 纯空白行 | 返回 `['']`，仍渲染**一个空行**（代码块内不塌缩）✅ |
| `maxWidth <= 0` | `Math.max(1, maxWidth)` 兜底为 1，不抛错 ✅ |
| 表格单元格内长中文 | 走同一 `_wrapRawToWidth`（`markdownTableWrap.js` 复用） |

### 6.6 复制行为对照

| 内容 | 复制到编辑器后的形态 |
|------|---------------------|
| 散文段落 | **一整段**（无硬换行符），由编辑器自行折行 |
| 代码块 | **保留原换行**（硬 `\n`） |
| 表格（默认 `minimal` 无框模式） | 纯文本、无框线、列间以空格对齐 |
| 表格（`KHY_TABLE_BORDERS=full`） | **会带走框线字符**（`╭─╮│╰─╯`）——已知取舍 |

| 组件 | 覆盖层激活时 |
|------|--------------|
| 右侧任务看板 | **隐藏** |
| Spinner | 隐藏（除非覆盖层自身需要 loading） |
| hint | 隐藏 |
| 输入框 / 输入框边框 | **隐藏** |
| placeholder | 不适用（输入框已隐藏） |
| Toast | **保留**（错误信息不能被覆盖层吞掉） |
| 鼠标展开/选择 | 不适用（覆盖层独占事件） |

### 7.3 高度不变量（G4 的落地检查）

| 组件 | 行数不变量 |
|------|-----------|
| Spinner | **恒 1 行**（含 meta 追加、停顿状态） |
| hint | **恒 1 行**（出现/消失不移动其它元素） |
| Toast | 每条恒 1 行 |
| 工具卡片 | 收起恒 1 行；展开为 `1 + min(内容行, 12)`；**绝不 0→N 跳变** |
| 输入框 | `3 ~ min(10, floor(rows/3))` 行 |
| 任务看板 | 内容自适应，但**空内容时仍占 1 行**（§5.4 裁决） |

以下六处现状**互相矛盾或与文档不符**，本文明确定为目标行为，需在实施时统一。前五项已在 [DESIGN-ARCH-103] 登记，此处给出**行为侧**的最终裁定。

| # | 冲突 | 现状 | **裁定** |
|---|------|------|----------|
| 1 | **Spinner 帧间隔三源** | `ccTimers.js` 写 `80`；`perfTunables.spinnerFrameMs()` 默认 **160**（LOW_POWER 320）；`[DESIGN-ARCH-079] §12.6.1` 写「默认 80ms」 | **以 `perfTunables` 的 160ms 为准**。`ccTimers.js` 的 `spinner.interval` 是**陈旧第三源**——它自称"唯一合法的计时器常量来源，禁止硬编码"，但 `Spinner.js` 实际绕过它走 `perfTunables`。需删除 `ccTimers.spinner` 或改为引用 `perfTunables` |
| 2 | **看板宽度两公式** | `sidebarLayout.sidebarWidth` = `clamp(round(cols×0.16), 24, 36)` vs `ccLayout.sidebarWidth` = `min(30, floor(cols×0.25))` → **120 列时 24 vs 30** | **只留 `sidebarLayout` 一处**，删除 `ccLayout.sidebarWidth` 并加回归断言 |

| 6 | **`mouseButtons` 默认值文档/实现矛盾** | 头部注释写「默认全平台关」，`autoDetectTerminal()` 四条分支**全部 `return true`** → 实际默认**开** | 改为三档 `KHY_MOUSE=off\|click\|full`，**默认 `click`**；未知终端**不接管**（兜底改 `false`）| ✅ **已修，但曾被绕过**（2026-09-18 复核）：兜底值确实已改 `false`，`mouseButtonsEnabled({})` 实测不再接管；然而 legacy 模式下 `app.js` 的备屏合成判定 `mouseButtonsEnabled(...) \|\| (ALT_SCREEN_ENABLED && !_explicitOff)` 又把结果绕回「默认接管」（`ALT_SCREEN_ENABLED` 默认 `1`）。该绕行已由 `[DESIGN-ARCH-119]` 第二层（应用内自绘选择）**实质化解** —— 接管不再是「用不了拖选」的原因，因为拖选改由应用自绘、不再依赖终端原生。用户显式退路：`KHY_SELECT=0` / `KHY_MOUSE=off`。详见 `[DESIGN-ARCH-119]` §二 缺陷 C、§七 风险 6 |
