# [DESIGN-MEM-002] 记忆时机指南

> 本指南定义何时应该创建记忆、何时不应该创建记忆，以及如何管理记忆生命周期。

---

## 1. 记忆创建原则

### 1.1 核心原则

- **价值优先**：只记住对未来有持久价值的信息
- **避免冗余**：不重复记录已存在的信息
- **及时性**：在信息新鲜时记录，而非事后回忆
- **结构化**：使用标准格式，便于检索和管理

### 1.2 记忆 vs 忘记

| 应该记住 | 应该忘记 |
|---------|---------|
| 用户核心偏好和习惯 | 一次性的临时请求 |
| 项目架构和约定 | 具体的调试过程细节 |
| 重要的技术决策 | 中间的失败尝试 |
| 反复出现的问题模式 | 一次性的错误信息 |
| 关键的配置和设置 | 临时的测试数据 |

## 2. 最佳记忆时机

### 2.1 用户交互时

**时机 1：用户明确表达偏好**
```
用户："我喜欢简洁的回复，不要太多解释"
→ 记忆：用户偏好简洁回复风格
```

**时机 2：用户纠正 AI 行为**
```
用户："不要用英文注释，用中文"
→ 记忆：代码注释使用中文
```

**时机 3：用户分享工作习惯**
```
用户："我习惯先写测试再写代码"
→ 记忆：用户采用 TDD 开发方式
```

### 2.2 项目开发时

**时机 4：发现项目约定**
```
发现：项目使用 2 空格缩进，单引号
→ 记忆：项目代码风格规范
```

**时机 5：解决复杂问题后**
```
解决：通过特定配置解决了部署问题
→ 记忆：部署配置解决方案
```

**时机 6：重要的技术决策**
```
决策：选择 PostgreSQL 而非 MySQL
→ 记忆：数据库选择及原因
```

### 2.3 系统配置时

**时机 7：关键配置变更**
```
变更：修改了 API 端点地址
→ 记忆：生产环境配置
```

**时机 8：环境设置完成**
```
完成：配置了开发环境
→ 记忆：开发环境搭建步骤
```

## 3. 记忆触发机制

### 3.1 自动触发

系统会自动捕获以下模式：

- **显式记忆请求**："记住..."、"请记住"、"remember this"
- **稳定偏好表达**：连续 3 次表达相同偏好
- **项目约定发现**：检测到代码风格、架构模式

### 3.2 手动触发

使用命令手动创建记忆：

```bash
# 快速记忆
/remember 用户偏好简洁回复

# 结构化记忆
/remember --type feedback --name "回复风格" --desc "用户偏好简洁回复" 用户希望回复简洁，避免过多解释

# 项目记忆
/remember --type project --name "代码风格" --desc "项目代码规范" 使用 2 空格缩进，单引号，分号结尾
```

### 3.3 最佳实践

**DO（应该做的）：**
- 在信息新鲜时立即记录
- 使用描述性的名称和摘要
- 选择正确的记忆类型
- 定期回顾和更新记忆

**DON'T（不应该做的）：**
- 记录一次性的临时信息
- 重复记录已存在的信息
- 使用模糊或不完整的描述
- 记录过时或不再相关的信息

## 4. 记忆类型选择指南

### 4.1 用户类型（user）

**适用场景：**
- 用户身份信息
- 核心偏好和习惯
- 长期工作方式

**示例：**
```yaml
---
name: user-language-preference
description: 用户语言偏好设置
type: user
tier: permanent
updated: 2026-09-04T00:00:00.000Z
---

## 语言偏好
- 界面语言：简体中文
- 代码注释：中文
- 文档语言：中文
- 交流语言：中文
```

### 4.2 反馈类型（feedback）

**适用场景：**
- 交互风格偏好
- 错误反馈模式
- 输出格式要求

**示例：**
```yaml
---
name: feedback-response-style
description: 回复风格偏好
type: feedback
tier: cross_session
updated: 2026-09-04T00:00:00.000Z
---

## 回复风格
- 详细程度：简洁
- 格式偏好：列表和代码块
- 语言风格：直接、技术性
- 避免事项：过多解释、情感化表达
```

### 4.3 项目类型（project）

**适用场景：**
- 项目架构和约定
- 技术栈选择
- 开发流程

**示例：**
```yaml
---
name: project-khy-os-architecture
description: khy-os 项目架构约定
type: project
tier: cross_session
updated: 2026-09-04T00:00:00.000Z
---

## 项目架构
- 目录结构：L0-L6 分层架构
- 代码风格：2 空格缩进，单引号
- 命名规范：camelCase（JS），snake_case（Python）
- 错误处理：try/catch + printError()
```

### 4.4 参考类型（reference）

**适用场景：**
- 外部资源链接
- API 文档
- 知识库引用

**示例：**
```yaml
---
name: reference-api-documentation
description: 关键 API 文档链接
type: reference
tier: cross_session
updated: 2026-09-04T00:00:00.000Z
---

## API 文档
- OpenAI API：https://platform.openai.com/docs
- Anthropic API：https://docs.anthropic.com
- khy-os 内部 API：./docs/api/
```

## 5. 记忆生命周期管理

### 5.1 记忆保鲜期

| 类型 | 默认保鲜期 | 说明 |
|------|-----------|------|
| user | 3650 天 | 用户身份信息几乎永不过期 |
| feedback | 540 天 | 反馈偏好可能随时间变化 |
| reference | 365 天 | 外部资源可能更新 |
| project | 180 天 | 项目可能重构或迁移 |

### 5.2 记忆更新时机

**需要更新记忆的情况：**
- 用户偏好发生变化
- 项目架构发生重构
- 外部资源链接失效
- 技术栈发生重大变更

**更新方法：**
```bash
# 更新现有记忆
/remember --type feedback --name "回复风格" --desc "新的回复风格偏好" 更新后的内容

# 或者直接编辑记忆文件
编辑 .khy/memory/feedback_response-style_xxxxxxxx.md
```

### 5.3 记忆清理时机

**应该清理记忆的情况：**
- 记忆内容已过时
- 记忆信息不再相关
- 记忆存在重复
- 记忆内容错误

**清理方法：**
```bash
# 预览清理
npm run memory:clear

# 执行清理
npm run memory:clear:apply

# 恢复误删的记忆
npm run memory:restore
```

## 6. 记忆质量保证

### 6.1 记忆质量指标

- **准确性**：记忆内容是否正确
- **时效性**：记忆是否仍然相关
- **完整性**：记忆是否包含足够信息
- **唯一性**：记忆是否与其他记忆重复

### 6.2 记忆质量检查

```bash
# 检查记忆系统健康状态
khy memory project

# 运行记忆蒸馏（去重和清理）
khy memory distill

# 查看蒸馏报告
khy memory distill --apply
```

### 6.3 记忆优化建议

1. **定期回顾**：每月检查一次记忆系统
2. **及时更新**：发现过时记忆立即更新
3. **避免冗余**：合并相似记忆，删除重复
4. **结构化存储**：使用标准格式，便于检索

## 7. 常见问题解答

### Q1: 什么时候应该创建记忆？

**A:** 当信息满足以下条件时：
- 对未来工作有持久价值
- 会反复使用或参考
- 不容易从其他地方获取
- 代表用户的稳定偏好或项目的关键约定

### Q2: 什么时候不应该创建记忆？

**A:** 当信息是：
- 一次性的临时请求
- 可以从代码或文档中直接获取
- 过时或不再相关
- 过于具体或细节化

### Q3: 如何避免记忆膨胀？

**A:** 遵循以下原则：
- 只记住核心信息，不记录过程细节
- 定期运行记忆蒸馏清理过期记忆
- 使用结构化格式，避免冗长描述
- 合并相似记忆，减少重复

### Q4: 记忆写错了怎么办？

**A:** 有几种修复方式：
- 直接编辑记忆文件
- 使用 `/remember` 命令覆盖
- 运行记忆蒸馏清理错误记忆
- 从归档中恢复正确的记忆

## 9. 最佳实践总结

### 9.1 记忆创建

1. **及时性**：在信息新鲜时立即记录
2. **准确性**：确保记忆内容正确无误
3. **结构化**：使用标准格式和分类
4. **描述性**：提供清晰的名称和摘要

### 9.2 记忆管理

1. **定期维护**：每月检查记忆系统
2. **及时更新**：发现过时信息立即更新
3. **避免冗余**：合并相似记忆，删除重复
4. **质量保证**：运行蒸馏清理低质量记忆

### 9.3 记忆使用

1. **主动回忆**：在需要时主动检索记忆
2. **上下文关联**：将相关记忆关联起来
3. **验证准确性**：使用前验证记忆是否仍然有效
4. **反馈改进**：根据使用效果改进记忆策略
