[DESIGN-GIT-001] Git 工作流规范#

本文档定义 khy-os 项目的 Git 工作流标准，包括分支策略、提交信息、PR 流程等。

1. 分支策略#

1.1 分支命名#

格式：<type>/<area-id>/<description>

类型：

类型说明示例
feat新功能feat/ARCH-072/add-api-versioning
fix修复 bugfix/MEM-001/fix-memory-leak
docs文档更新docs/update-readme
chore维护任务chore/update-dependencies
dev开发中dev/zhangsan/experiment

区域 ID：

  • 使用设计文档编号：ARCH-072、MEM-001 等
  • 或无区域编号：feat/add-login

描述：

  • 使用小写字母
  • 使用连字符分隔
  • 简洁明了（不超过 50 个字符）

1.2 分支类型#

类型说明生命周期
main主分支永久
develop开发分支永久
feature功能分支临时
release发布分支临时
hotfix热修复分支临时

1.3 分支保护#

main 分支保护规则：

  • 禁止直接推送
  • 必须通过 PR 合并
  • 至少 1 个批准
  • 所有检查必须通过
  • 分支必须是最新的

2. 提交信息规范#

2.1 格式#

<type>(<scope>): <subject>

<body>

<footer>

2.2 类型#

类型说明
feat新功能
fix修复 bug
docs文档变更
style代码格式（不影响功能）
refactor重构
perf性能优化
test测试
chore构建/工具变更
ciCI 配置变更
revert回滚

2.3 范围#

  • 使用模块名或区域 ID
  • 例如：auth、api、ARCH-072

2.4 主题#

  • 使用祈使句
  • 不超过 50 个字符
  • 首字母小写
  • 不以句号结尾

2.5 正文#

  • 说明变更的原因和内容
  • 每行不超过 72 个字符
  • 使用祈使句

2.6 页脚#

  • 引用 Issue：Closes #123
  • 破坏性变更：BREAKING CHANGE: ...

2.7 示例#

feat(auth): add JWT token refresh

Add refresh token endpoint to allow users to obtain new access tokens
without re-authenticating. This improves user experience by reducing
the need to login frequently.

Closes #456

3.1 PR 模板#

- [ ] 性能优化
- [ ] 测试

## 测试

- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 手动测试通过

## 检查清单

- [ ] 代码符合规范
- [ ] 添加了必要的测试
- [ ] 更新了文档
- [ ] 所有检查通过

3.2 PR 大小#

  • 建议不超过 400 行变更
  • 超过 1000 行的 PR 应该拆分

3.3 PR 审查#

审查要求：

  • 至少 1 个批准
  • Code Owner 审查（如适用）
  • 所有检查通过

审查清单：

  • [ ] 代码符合风格规范
  • [ ] 逻辑正确
  • [ ] 错误处理完善
  • [ ] 测试覆盖充分
  • [ ] 文档已更新
  • [ ] 无安全漏洞

4. 合并策略#

4.1 合并方式#

方式说明使用场景
Squash压缩为单个提交功能分支合并到 main
Rebase变基合并保持线性历史
Merge合并提交保留完整历史

4.2 默认策略#

  • 功能分支合并到 main：Squash
  • 发布分支合并到 main：Merge

4.3 合并前检查#

  • [ ] 所有 CI 检查通过
  • [ ] 至少 1 个批准
  • [ ] 分支是最新的
  • [ ] 无冲突

5. 发布流程#

5.1 版本号#

遵循语义化版本（SemVer）：

  • MAJOR：不兼容的 API 变更
  • MINOR：向下兼容的功能性新增
  • PATCH：向下兼容的问题修正

5.2 发布步骤#

  1. 创建 release 分支：release/v1.2.0
  2. 更新版本号
  3. 更新 CHANGELOG
  4. 运行完整测试
  5. 合并到 main
  6. 创建 Git Tag：v1.2.0
  7. 合并回 develop

5.3 热修复#

  1. 从 main 创建 hotfix 分支：hotfix/v1.2.1
  2. 修复问题
  3. 更新版本号
  4. 合并到 main 和 develop
  5. 创建 Git Tag：v1.2.1

7. 代码审查规范#

7.1 审查者职责#

  • 及时审查（建议 24 小时内响应）
  • 提供建设性反馈
  • 关注代码质量和安全性
  • 确保测试覆盖

7.2 作者职责#

  • 及时响应审查意见
  • 解释设计决策
  • 修复发现的问题

7.3 审查重点#

  • 代码正确性
  • 安全性
  • 性能
  • 可维护性
  • 测试覆盖
