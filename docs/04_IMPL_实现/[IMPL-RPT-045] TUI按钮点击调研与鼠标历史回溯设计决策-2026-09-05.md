# TUI 按钮点击调研与鼠标/历史回溯设计决策

**日期**：2026-09-05  
**影响范围**：khy TUI 交互层（mouseButtons / arrowRouting / scrollbackPreserve）  
**需求来源**：用户调研 ratatui GitHub 示例后询问"在 khyos 中可以用哪种方案实现 TUI 按钮点击"  

---

## 一、用户需求

用户要求实现 TUI 按钮点击，同时满足三个约束：

1. **上下键历史回溯不受影响**：输入框中 `↑/↓` 必须无条件调用历史记录（与 Claude Code Chat context 一致）
2. **鼠标正常滚动 scrollback**：不能因开启鼠标追踪而吞掉滚轮事件
3. **无残影噪音**：不触发 ink fullscreen 重刷，不重复渲染 banner

---

## 二、调研结论

### ratatui 方案不可移植到 khyos

| 方面 | ratatui（Rust） | khyos（Node.js / ink） |
|------|----------------|----------------------|
| 框架 | ratatui crate（原生终端渲染） | ink（React 渲染为 ANSI 序列） |
| 鼠标 | 需 `EnableMouseCapture` + SGR 解析 | 已有 `mouseButtons.js` 封装层 |
| 方向键 | 需自实现 context 状态机 | 已有 `arrowRouting.js` 统一路由 |
| 无残影 | 需自行管理 buffer | 已有 `scrollbackPreserve` + `liveHeightClamp` |

**结论**：khyos 的架构早已覆盖上述三个需求，不需要引入 ratatui 方案。

## 三、khyos 现有实现详解

### 3.1 方向键历史回溯（arrowRouting.js）

**核心设计**：context 栈，单一真源，优先级由数组顺序定义。

```
CONTEXTS = ['shellView', 'executing', 'idle', 'editing']

idle:    { up: 'history:previous', down: 'history:next' }
editing: { up: 'history:previous', down: 'history:next' }  // 无条件，与 CC 对齐
```

App.js 收到动作名后统一转发给 `textInput.onInput()`，`useTextInput` 内部实现：
- 第一次 `↑` 暂存当前草稿
- `↓` 走过最新一条时还原草稿
- 多行缓冲区视为**一条**历史（含换行）

**关键文件**：`services/backend/src/cli/tui/arrowRouting.js`

### 3.2 鼠标滚动（mouseButtons.js + App.js）

**二态门控策略**（参照 Claude Code 实测验证）：

```
默认状态：SGR 1000 模式
  - 只报按钮按下/松开，不报位移/滚轮
  - 原生拖选完全保留
  - 滚轮不被本进程截获

1500ms 无键入后：切换到 SGR 1006
  - 鼠标点击生效（onClick/onMouseUp/onMouseOver）
  - 滚轮事件被截获（需主动转发）

任何键入后立即切回原生模式
  - 打字时滚轮/拖选不受影响
```

**环境门控**：
- `KHY_MOUSE_BUTTONS`：默认关，`1/true/on/yes` 开点击层
- `KHY_MOUSE_HOVER`：默认关，开则有 1003 悬停事件流（60~120Hz 洪流）
- `KHY_MOUSE_NATIVE_MS`：默认 1500ms，可覆盖二态切换窗口

**关键文件**：`services/backend/src/cli/tui/mouseButtons.js`（`enableBytes` / `disableBytes`）

### 3.3 无残影噪音（scrollbackPreserve + liveHeightClamp）

两条防线：

**防线一**：`scrollbackPreserve`
- Banner 只渲染一次，值稳定 → React.memo 跳过重渲 → 不重复进 scrollback

**防线二**：`liveHeightClamp` + `StreamingBlock` reserve
- Live 区高度始终 < terminal 行数
- 防止 ink 触发 `clearTerminal` 全屏重刷（残影根因）
- 宽终端 sidebar 决策由 `sidebarLayout` 纯叶子处理

**关键文件**：
- `services/backend/src/cli/tui/scrollbackPreserve.js`
- `services/backend/src/cli/tui/ink-components/liveHeightClamp.js`

## 五、设计取舍记录

khyos 没有照搬 ratatui 的完整自定义 widget 体系，而是选择了更轻量的方案：

| 取舍 | 原因 |
|------|------|
| 按钮仅两个（麦克风 + 图片×） | 等价键位覆盖：Alt+M 麦克风、Esc 清除图片 |
| 鼠标点击默认全关 | 换掉「滚动+拖选复制」两个高频能力不划算 |
| 悬停高亮默认全关 | 1003 事件洪流占用终端输入带宽 |
| 方向键无条件绑定历史 | 与 CC Chat context 对齐，避免「吞键」历史 bug |
