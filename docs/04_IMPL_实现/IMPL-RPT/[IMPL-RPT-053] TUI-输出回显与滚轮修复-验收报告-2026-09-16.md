## 二、四个根因（全部经无头 harness 实证，非推断）

### A. 转录被 ink 的 fullscreen 清屏抹掉，且会**自锁**

`ink.js:320` 的 `isFullscreen = stdout.isTTY && outputHeight >= stdout.rows` 只是**判定**；
真正决定清屏的是 `this.lastOutputHeight >= this.options.stdout.rows` —— **上一帧**的高度。

一旦某帧高度 ≥ rows，`lastOutputHeight` 就永远 ≥ rows，**此后每帧都清屏**。
在备用缓冲区（`\x1b[?1049h`，无回滚缓冲）下，清屏 = 转录整片消失。

- 实证：legacy 100×24 忙态帧 = 24 行 = rows → 每帧 `clear=true`
- 根因：`spinnerH` 记成 1 行，实际渲染 3 行
  （ink 的边框语义是「设了 `borderStyle` 就四边全画」，只写 `borderBottom` 不会关掉其余三边）
- 修后：23 行，`clear=false`

### B. chrome 账本漏计三项（Preview 布局）

`_viewportHeight` 的账本没扣：忙态 spinner 的真实 3 行、Preview 独有的标题栏 1 行 + 底部分隔线 1 行。

- 实证：preview 130×40 忙态帧 = 45 行 > 40
- 修后：38 行，`clear=false`
- 同时把 `previewLayoutMode` 的判定**前移**到 `_viewportHeight` 之前 —— 账本必须知道本帧走哪套 chrome

### C. 视口永远停在**顶部**

历史判据 `scroll >= maxScroll` 判「之前在底部」，但调用方 state 初值是 `0`。
内容一旦长过视口，`0 >= maxScroll` **恒假** → 视口永远显示最早那几行。

- 修法：引入**贴底哨兵** —— `null` / `undefined` / 负数 = 追随最新内容；数字 = 固定偏移；
  滚回最底时回写 `null` 自动恢复跟随（不需要额外 sticky 标志位）
- 真源落在 `ink-components/Viewport.js` 的 `resolveViewportOffset` / `applyStickyViewportAction`（纯叶子、可单测），
  App 里不再另抄一份

### D. 滚轮被终端合成为 ↑/↓

备用缓冲区下终端把滚轮事件变成 ↑/↓ 字节送进 stdin，被 `arrowRouting` 绑成
`history:previous` / `history:next` → 表现为「滚一下召回一条输入历史」。

- 修法：接管 SGR 鼠标协议（滚轮 = 按钮 64/65，修饰位 shift/meta/ctrl 加在低位 → `button & ~28` 剥掉），
  在应用内消化滚轮，终端一个字节都收不到，方向键无从合成

1. **`node .khyos/diag/headless-frames.js <cols> <rows>` 的第 4 个参数（消息条数）不起作用** ——
   消息条数走环境变量 `KHY_DIAG_NMSGS`。默认只有 2 组（4 条消息），内容不超视口，
   **看不到贴底行为，会误判成「贴底没生效」**。必须 `KHY_DIAG_NMSGS=40`。
2. **等待时间硬编码 3500ms**，窄/矮终端下 boot 序列没跑完就收帧，只抓到启动画面
   （100×24 实测只出 4 帧、末帧是 boot screen）。已改为 `KHY_DIAG_WAIT` 可调（默认仍 3500）。
3. `node --test <目录>` 在本 Node 版本（22.22.2）下**不扫描目录**，必须写 glob。
4. `global.__inkInst.lastOutputHeight` 读不到（恒 `undefined`）→ 改用「数帧文本行数」间接判定。
