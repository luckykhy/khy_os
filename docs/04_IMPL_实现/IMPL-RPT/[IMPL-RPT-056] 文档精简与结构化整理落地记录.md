## 3. 收敛范式（本轮确立，可复用）

本仓「收敛一族文档」的**标准动作**不是物理合并，而是：

1. **一篇总纲**（唯一导航入口 + scope 裁决真源 + 代码耦合表 + 生成层边界）
2. **逐篇「隶属」头**（指向总纲）
3. **零路径改动**（DR7：手册编号被代码当路径常量用，禁移动/重命名）

原因：DR1 禁删、DR7 禁移。物理合并的收益是文件数，风险是运行时静默失效——不划算。
B3 / B4a / B5 / B6 四批全部走此范式，共 5 篇总纲（`ARCH-122`、`OPS-MAN-207/208/209`）。

> **生成层边界**（B4a 发现）：`scripts/restore/*.js --gen-doc` 产出 18 篇带「请勿手改」banner 的文档，
> 手改会被下次生成覆盖。故 B4a 只给 5 篇**手写**还原文档加头；`096` 同理跳过。
> 要给生成层文档加导航，必须改生成器——已列 followup。

## 7. B9 按标签归夹（全仓分文件夹）

**指令**：不止 OCR/重复件，而是「所有文档都按 `[TAG-XXX]` 标签放到不同子文件夹」。

**做法**：
- 遍历全仓可移动 `.md`，按 `[TAG-XXX]` 标签归入其阶段目录下的 `[TAG-XXX]/` 子文件夹；
- 族规模 ≥3 篇 → 独立成夹；≤2 篇 → 并入「其它」桶（如 `其它设计/`、`其它规范/`）；
- **DR7 红线**：被代码当路径常量引用的 46 篇（移动范围）留根目录不移动——门禁红不可擅移；
- 合并 38 篇重复件（同簇整合）、HK-3 隔离 38 篇冗余件（**只隔离不删除**，隔离区 `_dup_quarantine/`）。

**链接修复（B9 不可分割的收尾）**：物理移动使 377 篇文档旧相对路径全部失效。
- 初版修复器（v2）用「循环内复用原文本偏移」重写，对 URL 长度变化（如 `%5B`→`[`、`%20`→空格）的链接发生 **offset-mutation 交错污染**，损坏 10 个多链接文件；
- 修正版修复器（`_b9_links_fix.py`）改用**逆序偏移落地 + 子串/文件名双匹配**，并应用前备份到 `_linkfix_bak/`；统一重写 **924 处 / 97 文件**断裂链接；
- 损坏文件最终核验 = **0**（8 个从 git HEAD 恢复、1 个无历史文档手工修复、其余经修正器修复）；
- 剩余 **11 处断链全部为既有损坏**（目标在仓内不存在：`COMMUNICATION-PROTOCOL.md`、`[DESIGN-PROMPT-002]`、`[DESIGN-ARCH-011]` 编码链接、`platform/packages/agent-sdk/docs/*` 外部路径、`postmortem-template.md`、`drill-schedule.md` 模板缺件）——B9 与修复均未新增断链。
