## 一、目标

在网页端提供「渠道 API 文档」板块：一处记录各 AI 渠道的 **端点 URL + API Key**（加密落库），
一处说明各 Agent 客户端（Claude Code、CommandCode、ZCode、Codex、Cursor、Cline、Continue.dev）
**如何配置这些 Key**（环境变量名 / 配置文件路径 / 可复制代码块）。

---

## 二、设计要点

1. **一张表**：`channel_apis`，Sequelize 模型，启动时由既有 `sequelize.sync()` 自动建表，不引入 DDL 迁移文件（沿用 `GuiEvalTask` / `WebFrontendEvalTask` 的模式）。
2. **刻意不建 User 关联**：渠道 Key 是全机共享的凭证注册表，不是按用户切分的资源；访问控制放在路由层的 `admin` 门禁上。
3. **AES-256-GCM**：`iv:authTag:ciphertext` 三段 base64 单字段存储；密钥经 SHA-256 归一化为 32 字节，因此 env 里可以放任意长度口令。
4. **密钥真源单一**：`KHY_CHANNEL_KEY_SECRET`。未设置时回退到「按主机名派生」的稳定密钥并打一条 warning——回退的边界是诚实的：拿到数据库文件的人在本机同样能解出明文，强度提升真正来自显式配置这个 env。
5. **明文只有一个出口**：`POST /:id/reveal`。列表与详情恒返回脱敏（前 4 + `****` + 后 4）；reveal 额外写一条 JSONL 审计，参数键名用 `masked_value`（而非 `masked_key`），避免被 `SENSITIVE_KEYS` 脱敏器抹掉。
6. **配置指南是数据，不是文案**：7 个 Agent 的 steps / envVars / configFile / docsUrl 收敛在服务层 `AGENT_CONFIG_GUIDES`，前端与 REST 共用同一份。端点不写死字面量，由 `getProviderPresets()` 派生，预设缺失时降级为空串而非硬编码兜底。
7. **seed 幂等**：按 `channel_name` 查重，已存在则保留用户改动；重复启动不会覆盖用户编辑。
8. **前端不落地明文**：reveal 结果只存在组件内存的 `revealed` map 里，不写 localStorage / sessionStorage；页面刷新即失。

### 基线说明（第 8 项为何非绿）

以下失败在本次改动之前即已存在，且均不涉及本次新增/修改的文件；遵循「不做超出范围的事」未顺手修：

- **`check:layout` 的 5 项 error**：根目录白名单外的 `tmp_files.txt`；`docs/design/` 与 `docs/_维护记录/` 缺 `00_INDEX_*`；44 份阶段文档未入主索引；`dist-electron` / `electron` / `tests` 三个顶层目录未登记层级清单；`extensions/scripts/khy-alpine-iso` 不合规 `provides` 契约。
- **后端 `npx eslint src/ --max-warnings 0`**：输出约 500KB，21 errors + 100 warnings，全部落在 `src/adapters/im/*`、`src/agents/built-in/*` 等未触碰文件（`eqeqeq`、`no-unused-vars`、`no-empty`、`import/order`）。
- **前端 `npx eslint src/ --max-warnings 0`**：1 error + 4 warnings，分布在 `src/api/notify.js`、`src/composables/useConfigSync.js`（含唯一 error：`'getAll' is not defined`）、`src/main.js`、`src/services/crossPlatform/shared/crossLauncher.js`——4 个文件本次均未触碰。
- **一处口径问题**：`npx eslint src/` 默认只扫 `.js`/`.cjs`/`.mjs`，**静默跳过 `.vue`**（实测 `npx eslint src/views/Layout.vue` 单独执行报 17 个 `vue/attributes-order`，而 `npx eslint src/` 对 Layout.vue 零命中）。因此第 8 项按字面执行在本仓库当前配置下无法变绿，且它此前从未真正覆盖过 `.vue` 文件。

### 本次修掉的一个真实缺陷

`router/index.js` 的 `detectRouterBase()` 原启发式为 `pathname.match(/^\/admin\/[^/]+/i)`，会把 `/admin/channel-apis` 解析成 router base `/admin/channel`，导致新页面 404。改为捕获段名并用 `IN_APP_ADMIN_SEGMENTS` 排除已注册的站内段，同时保留 `/admin/<seg>/...` 子路径部署的兼容能力。

## 六、遗留与后续建议

1. **`detectRouterBase()` 与 `/admin/<seg>` 命名耦合**：以后每新增一个 `/admin/xxx` 站内页都要往 `IN_APP_ADMIN_SEGMENTS` 补一段。建议改为「已注册路由优先匹配」的显式判定，消除白名单。
2. **`eslint src/` 不覆盖 `.vue`**：CI 门禁实际存在盲区。建议把前端 lint 脚本显式带上 `src/**/*.vue`。
3. **前端既有 lint 失败**：`useConfigSync.js` 的 `'getAll' is not defined` 是真 bug（error 级），建议单独立任务修。
4. **`check:layout` 5 项预存 error**：`tmp_files.txt` 应删或收容；`dist-electron` / `electron` / `tests` 三个顶层目录需登记进 [DESIGN-ARCH-068] 第一节再改脚本；`khy-alpine-iso` 需补 `provides` / `script` 声明。
5. **密钥轮换**：当前无轮换工具。如需「换密钥后旧密文仍可读」，需引入 envelope（DEK/KEK 双层）结构；当前设计是「换 env 即失效」，已通过在列表上以「是否有密文」而非「能否解密」判定 `has_key` 来避免误导用户。
