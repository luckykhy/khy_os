[IMPL-RPT-042] 交互过程与输出结构化：持久化字段与机器可读输出#

实现报告 · 遵循 [MGMT-STD-001] 文档铁律 · 对应设计归 docs/03_DESIGN_设计/，本目录索引见 00_INDEX_实现-分类索引.md

  • 日期：2026-07-27
  • 范围：会话回合的结构化持久化字段（_timeline / _toolCalls / _turnStats）、khy -p 机器可读输出的增量字段（tool_calls / turn_stats / timeline）、session export --detailed 与 session analyze 子命令，以及相关 TUI 展示门控。
  • 状态：定稿（单元测试 + 整体回归通过）

一、背景与目标#

此前一个回合里「模型说了什么、调了哪些工具、每步耗时多少」只存在于终端滚动输出中，落盘的 JSONL/快照只有扁平的 role+content，机器消费方（脚本、CI、二次分析）拿不到结构化过程数据。本次改造在不破坏任何旧数据与旧输出字节的前提下，把回合过程结构化：写侧新增三个可选持久化字段，读侧新增机器可读输出与分析命令。

二、三个可选持久化字段（JSONL transcript + JSON 快照）#

写入点：services/backend/src/services/sessionPersistence.js 的 appendMessage。三个字段全部是 present-only：调用方未挂载（或挂载了空数组/空对象）时，写出的 JSONL 行与旧格式字节一致；旧 reader 按「忽略未知字段」的既有增量契约（同 _khyTrace）直接兼容。

注意存储位置差异：live TUI 回合的新字段经 aiSession.attachTurnArtifacts 挂到内存消息后由 _persistLiveSession 落盘——已追加过的行不会重写，因此已存在回合的字段落在 JSON 快照（{bucket}/{sessionId}.json 的原始消息透传）；JSONL 的 append 路径同样支持带字段写入（新追加的行直接携带）。

2.1 _timeline — 有序回合时间线#

模型文本、思考与工具步骤的真实交错顺序（连续文本段合并，工具收拢为 tools 组）：

"_timeline": [
  { "type": "text", "text": "先看一下配置文件" },
  { "type": "thinking", "text": "……", "durationMs": 800 },
  { "type": "tools", "tools": [
    { "name": "Read", "paramsSummary": "{\"file_path\":\"a.js\"}", "status": "done" }
  ] },
  { "type": "text", "text": "配置没问题，结论是……" }
]
字段含义
typetext（模型正文）/ thinking（思考段）/ tools（连续工具组）
text该段文本内容（text/thinking 段）
durationMs思考段真实耗时毫秒，仅实测到才有
tools[].name工具名
tools[].paramsSummary参数一行摘要，200 字符截断（不存完整参数/结果，防存储膨胀）
tools[].statusdone / error；无结果时整个键缺席（不虚构）

2.2 _toolCalls — 工具调用摘要#

从工具循环权威日志（toolCallLog）蒸馏，从不保存完整工具结果：

"_toolCalls": [
  { "seq": 1, "name": "Read", "paramsSummary": "{\"file_path\":\"a.js\"}", "durationMs": 42, "status": "done" },
  { "seq": 2, "name": "Bash", "paramsSummary": "{\"command\":\"ls\"}", "durationMs": 7, "status": "error", "error": "boom" }
]
字段含义
seq回合内调用序号（从 1 起）
name / paramsSummary工具名 / 参数摘要（200 字符截断）
durationMs实测耗时毫秒，日志未带真实耗时则缺席
statusdone / error
error失败时的一行摘要（200 字符截断），成功时缺席

2.3 _turnStats — 回合统计#

"_turnStats": { "elapsedMs": 1235, "tokens": 567, "toolCount": 2 }

诚实省略规则（与 turnStats.js 同一红线）：不可得的量整键缺席、绝不补零。elapsedMs/tokens 仅实测大于 0 才写；toolCount 仅当真实提供了日志数组才写（空数组是事实「零工具运行」→ toolCount: 0）；三个量都缺时整个 _turnStats 缺席。

三、khy -p 机器可读输出的增量字段#

实现：services/backend/src/cli/printOutputFormat.js 的 buildResultMessage。--output-format json 与 stream-json 的终端 result 消息在旧键序完全不动的尾部追加：

字段出现条件内容
tool_calls本次运行携带 toolCallLog 数组时（空数组也输出 []，是「零工具」的事实；降级/旧结果整键缺席）同 _toolCalls 结构
turn_stats至少有一个真实量时同 _turnStats 结构
timeline仅 --include-timeline 开启时（开启但无数据 → []，门控消费方恒见键）同 _timeline 结构

--include-timeline 标志：裸标志即开启；--include-timeline=true|false（或 1|0）显式指定；未知值按 --output-format 同样式报错。

khy -p "统计 src 下 js 文件数量" --output-format json
khy -p "同上" --output-format stream-json --include-timeline

四、session export --detailed 与 session analyze#

实现：services/backend/src/cli/handlers/session.js；命令别名登记于 aliases.js（会话分析 / 分析会话 / huihuafenxi → session analyze），schema 与 bin/khy.js 已同步接线。

4.1 导出：khy session export <序号|ID> --format json --detailed#

restore 读侧白名单会剥离 artifact 字段；--detailed（仅 json 格式生效）从原始快照按 uuid（退化到同下标+同角色）把 _timeline/_toolCalls/_turnStats 重新贴回导出消息。不带该标志时导出字节与旧输出一致。

4.2 分析：khy session analyze <序号|ID> [--json]#

按人类用户消息切回合，聚合每回合耗时/工具/tokens（来源为原始快照；旧会话无 artifact 字段时诚实降级为仅回合切分）。人类可读输出示例：

  会话分析：重构数据层
  ID sess-a1b2c3d4 · 共 6 条消息

  共切分出 2 个回合，累计耗时 46.6 秒，累计调用工具 5 次，累计消耗 8123 tokens。

  回合 1 帮我看看 dataHome 的解析逻辑
      耗时 12.3 秒，调用工具 2 次（Read、Grep），消耗 3011 tokens，回合已完成
  回合 2 把缓存路径改成可覆盖的
      耗时 34.3 秒，调用工具 3 次（Read、Edit、Bash），消耗 5112 tokens，回合已完成

--json 输出 { ok, action: "analyze", sessionId, metrics, rounds }，其中 rounds[] 为 { index, userInput, elapsedMs, tools, tokens, status }（不可得的量为 null/[]，不补零）。

中文别名等价用法：

khy 会话分析 1
khy 分析会话 sess-a1b2c3d4 --json
khy huihuafenxi 1 --json

五、jq 使用示例#

# 单次运行：提取每个工具的耗时
khy -p "检查依赖" --output-format json | jq '.tool_calls[] | {name, durationMs}'

# 单次运行：回合累计 tokens
khy -p "检查依赖" --output-format json | jq '.turn_stats.tokens'

# 会话分析：每回合耗时与工具清单
khy session analyze 1 --json | jq '.rounds[] | {index, elapsedMs, tools}'

# 会话分析：全会话累计 tokens
khy session analyze 1 --json | jq '.metrics.totalTokens'

# 详细导出：跨消息累加所有工具调用耗时（缺字段的旧消息自动跳过）
khy session export 1 --format json --detailed --json
jq '[.messages[]._toolCalls // [] | .[] | .durationMs // 0] | add' <导出文件>.json

# 详细导出：找出最慢的一次工具调用
jq '[.messages[]._toolCalls // [] | .[]] | max_by(.durationMs // 0)' <导出文件>.json

六、向后兼容承诺与门控清单#

兼容红线（均有单元测试锁定）：

  1. 旧数据降级：无 artifact 字段的历史会话，所有 reader（restore/export/analyze）照常工作，analyze 诚实降级为仅回合切分并明示「旧版本记录」。
  2. 无新标志时输出字节不变：不带 --include-timeline 的 -p 输出不含 timeline 键；不带 --detailed 的导出与旧字节一致；appendMessage 未挂载新字段时 JSONL 行与旧格式字节一致。
  3. 旧 reader 读新数据不崩溃：新字段遵循「未知字段忽略」的既有增量契约。

相关门控（全部默认开，0/false/off/no 关闭即逐字节回退旧渲染）：

门控作用
KHY_TUI_SECTION_GAPTUI 转录/流式区段间空行分隔（sectionGap.js 叶子，StreamingBlock 与 Transcript 同步翻转）
KHY_TOOL_HEADER_DURATION工具头行内联耗时标记（如 (45ms) / (1.2s)），仅实测数据、从不估算
KHY_TOOL_RESULT_TRUNCATION_TAG工具结果体截断标记 [已截断 shown/total 字]，真实计数
