## 一、设计要点

### 1. 门禁要能「只减不增」，而不是「全绿」

前端 lint 存量是 1690 个 warning（其中 1661 个是 `vue/attributes-order` 纯格式项）。
一次性 `--fix` 能清掉，但会在约 50 个文件的模板里重排属性，产生一个巨大的无关 diff。
因此沿用仓库既有的基线预算模式：**error 硬 0，warning 记录实测值并只允许下降**。
这样门禁立刻生效（新增 error 立即失败），而格式债被显式登记、不阻塞功能改动。

### 2. 判定逻辑必须可脱离框架单测

`detectRouterBase()` 的旧实现靠 `IN_APP_ADMIN_SEGMENTS` 白名单排除站内 `/admin/*` 页面。
每加一个站内页就要补一段白名单，漏补就整站 404 且无报错。
把「已注册路由优先匹配」抽成无依赖的纯函数（`src/router/adminBase.js`），
`routes` 只在调用点注入，于是能用 `node --test` 直接测，不需要 Vue / vue-router / 浏览器。

### 3. 密钥轮换的正确形态是「密钥环 + 增量重包」，不是「换一把锁」

换 env 会让旧 KEK 包封的 DEK 永久解不开，等于静默丢 Key。
单纯的双层 envelope 并不解决这个问题——DEK 还是被同一个 KEK 包着的。
真正解开的两点：
- **密钥环**：主 KEK + 退役 KEK 有序列表，解密按序尝试。轮换过渡期新旧密文都读得通，
  老数据不需要迁移即可上线。
- **DEK 按记录独立**：正是为了让「重包」可以一条记录一条地做，而不是停机全库重加密。

两者缺一不可：只有环则永远清不掉退役 KEK；只有 envelope 则换 env 照样丢数据。

### 4. 迁移留下的兼容性缺口要如实报告，不能靠测试侧硬改

`src/services/domain/**` 迁移把 139 个服务目录清空成只剩 barrel `index.js`。
barrel 只做了**属性级**兼容，深路径全断。测试侧 556 处深导入中招。
其中 372 处能从 barrel 的 `exports.x = require('<新路径>')` 反推正确目标并机械改写；
另 193 处指向**全树不存在的模块**（barrel 是空壳、basename 检索无命中）——
这些源文件被删除且未迁移，改测试无用，必须先恢复源码。

实现中的一个真 bug 是自查发现的：DEK 是 32 字节随机二进制，**不是合法 UTF-8**，
若经 utf8 字符串搬运会被替换字符破坏字节——解包「成功」却拿到错误的 DEK。
已改为 `_gcmOpenBuf()` 返回 `Buffer`，DEK 走二进制路径，明文走字符串路径。

## 四、未完成与边界（如实登记）

1. **jest 基线未清零，465 个套件仍失败。** 分类见 `tests/DEBT.md`：
   139 其它（含约 30 个语法损坏的测试文件）/ 99 测试作用域错误 / 91 迁移遗留 /
   80 断言失败 / 33 API 签名漂移 / 19 双 runner 皆死 / 4 硬超时。
2. **P0 硬阻塞：193 个深路径指向全树不存在的模块**（`desktopControl/*`、`memoryEngine/*`、
   `wasm-sandbox/*`、`dualTrack/*`、`contextScope/*`、`auditTrajectory/*`、`evoEngine/*`、
   `trajectoryReplay/*` 等），barrel 为空壳、全树 basename 检索无命中。
   源文件被删且未迁移，测试侧无法修复，**需先恢复源码**。
   这是本轮无法推进 jest 基线的根本原因，不是修得不够多。
3. **「moduleDirectories」这个归因是错的。** `jest --showConfig` 实测
   `moduleDirectories: ["node_modules"]`、`moduleNameMapper: []`、`roots: ["<rootDir>"]`
   全为默认值，解析配置无任何异常。真正根因是 domain 迁移的兼容性缺口。
   另有一条独立缺陷：`tests/cli/extensions/extensionManager.test.js` 用
   `../../src/cli/extensions/extensionManager`，从它所在目录算出来是 `tests/src/...`
   ——**相对深度本身就错**，该修的是测试文件而非 jest 配置。
4. **1661 个 `vue/attributes-order` 未清零**，需一次独立的模板属性排序 `--fix` 任务。
   刻意不并入本轮，避免在无关模板里制造大 diff。
5. **密钥轮换机制已实现但未在生产执行。** 生产库现有密文仍是 v1 格式；
   升级后新写入变 v2，旧 v1 记录靠 v1 分支继续可读，`needsRewrap` 不会为 v1 记录
   报 true（它挂在主 KEK 上，环下标为 0）。**若确实要执行一次真实轮换**，需：
   把当前 `KHY_CHANNEL_KEY_SECRET` 写入 `KHY_CHANNEL_KEY_SECRET_PREVIOUS`、
   设置新主密钥，然后对每条记录跑 `reEncryptApiKey` 再迁回。
   **本轮未实现逐条重包的批处理入口**（没有 DB 层迭代器、没有 CLI 子命令），
   这是下一个该补的东西。
6. **`tests/DEBT.md` 的 P3（113 个断言失败 + 签名漂移）需人工逐个判读代码**，
   无法机械批量修。
