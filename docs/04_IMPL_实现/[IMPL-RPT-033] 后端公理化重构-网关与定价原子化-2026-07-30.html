[IMPL-RPT-033] 后端公理化重构：网关依赖与定价原子化#

实现报告 · 遵循 [MGMT-STD-001] 文档铁律 · 对应设计归 docs/03_DESIGN_设计/，本目录索引见 00_INDEX_实现-分类索引.md

  • 日期：2026-07-30
  • 范围：services/backend/src 后端公理化重构（多批次合并交付）——纯函数原子层抽取（_envParse.js / _modelIdParse.js）、定价数学纯叶抽取（tokenPricing.js + tokenUsageService.js 薄委托）、AI 网关依赖分组注入 + fail-fast（aiGatewayGenerateMethod.js）、proxyServer.js 死码清理、token 用量文件路径 portable-aware。
  • 状态：定稿（新增单测 + 整体回归通过，三维评审 0 blocker / 0 major / 1 minor）

一、背景与动机#

后端网关与用量统计代码在长期演进中积累了几类结构债：

  1. 重复的私有 helper：_parseMs（env 毫秒解析）在 aiGateway.js 与 adapters/relayApiAdapter.js 各有一份逐字节相同的副本；normalizeModelId（模型 ID 规范化）在 gateway/cli 层存在两组各两份逐字节相同的副本。副本漂移是静默行为分叉的温床。
  2. 定价数学与 I/O 壳混杂：tokenUsageService.js 同时承担定价常量表、成本公式、token 估算（纯数学）与磁盘持久化、会话累加器、chalk 渲染（I/O 与可变状态），纯数学部分无法独立单测。
  3. 依赖注入静默崩坏：aiGatewayGenerateMethod.js 经 setAiGatewayGenerateMethodDeps 注入 30 余项宿主 helper，全部为旧扁平形态且无校验——任何一项漏注入都不会在注入期报错，而是在 generate() 对应路径上以 TypeError 静默崩坏（可能被外层 try/catch 吞掉）。
  4. 死码：proxyServer.js 内存在 4 个全仓零引用的 helper 函数，虚增巨石体积。
  5. 路径语义过时：token 用量文件固定写入 ~/.khyquant/token_usage.json，便携部署（portable）场景下数据逃逸出安装目录。

本轮重构的公理是「接口恒等」：所有抽取/收敛/清理对既有消费方保持导出签名、返回结构、调用点字节级不变；唯一的新行为（fail-fast 抛错）只在「原本就已静默坏掉」的缺依赖场景下触发。

二、改动概览#

2.1 env 数值解析单一真源（_envParse.js，Batch 2）#

  • 新建 services/backend/src/services/gateway/_envParse.js，收敛两处逐字节相同的 _parseMs(raw, fallback, min = 0)（原 aiGateway.js:287、adapters/relayApiAdapter.js:151）。
  • 语义契约与被收敛副本逐字节一致：raw ?? fallback → parseInt(..., 10) → 非有限或 <= 0 回退 fallback → Math.max(min, parsed) 抬底、无上限钳制；纯函数、不读 process.env（env 读取留在调用方）。
  • 刻意不收敛的变体已在文件头登记：_parsePositiveInt 在 aiGateway.js（默认 max=16）与 relayApiAdapter.js（默认 max=8）默认参数不同，属函数语义差异，非严格等价，不合并；_adapterUtils.parsePositiveInt（max=Infinity）、_parseNonNegativeInt（全仓单实例）等同理。
  • 各消费方保留同名本地绑定（const _parseMs = require('./_envParse')._parseMs;），调用点逐字节不变。

2.2 模型 ID 规范化单一真源（_modelIdParse.js，Batch 2）#

  • 新建 services/backend/src/services/gateway/_modelIdParse.js，收敛两组互不等价的 normalizeModelId 副本：
    • 变体 A normalizeModelIdTrimQuotes（trim + 去首尾引号、保留内部空白）：原 gateway/proxyServer.js:861 与 cli/handlers/proxy.js:137，body 逐字节相同。
    • 变体 B normalizeModelIdCompact（trim + 去首尾引号 + 剥除全部空白）：原 gateway/modelDiscovery.js:69 与 gateway/adapters/_ideTokenMixin.js:136，body 逐字节相同。
  • A 与 B 互不等价（B 额外剥除内部空白），故并列导出、绝不合并；adapters/claudeAdapter.js 的 parseModelId（解析 model::mode 后缀）为全仓唯一实例，不收敛。
  • 各消费方保留同名本地绑定，调用点逐字节不变。

2.3 token 定价纯叶抽取 + 壳薄委托（tokenPricing.js，Batch 3）#

  • 新建 services/backend/src/services/tokenPricing.js——纯定价/换算数学叶子（零 I/O、零可变状态、确定性、可单测），从 tokenUsageService.js 抽取：
    • 常量表 TOKEN_PRICING（USD / 1M tokens）与汇率 USD_TO_CNY（与提取前字面量逐字节一致）；
    • resolveProviderPricing（table[provider] || table.default 查表语义原样保留，含原型链命中等历史行为）；
    • calculateCost / estimateCost / sumRecordsCost（getSessionCost 的求和内核）/ estimateTokens。
  • 价格表与汇率一律作参数注入、缺省取内置常量；读取外部价格配置（如 ai_gateway_pricing.json）属 I/O，永远留给调用方。不做四舍五入——舍入/展示精度是壳与渲染层的职责。
  • tokenUsageService.js 以原签名薄委托本叶子（TOKEN_PRICING / USD_TO_CNY 为同一对象身份的 re-export），消费方（cli/router、routerDispatchOps、replSession、useQueryBridge、aiChatCore、gateway/customerQuotaEnforcer 等）行为逐字段恒等。
  • 刻意不提取清单已在叶子文件头登记：loadUsageData/saveUsageData（fs）、recordUsage/_sessionUsage（可变累加器）、todayKey/monthKey（时钟）、formatUsageReport 等（chalk 渲染壳）均留在壳内。

2.4 AI 网关依赖分组注入 + fail-fast（aiGatewayGenerateMethod.js）#

  • setAiGatewayGenerateMethodDeps 的注入契约升级为 DEP_GROUPS 五个语义分组（分组表即 setter 契约的单一真源）：
    • validation（10 项）：入参解析 / 错误分类 / 适配器谓词（_parseMs、_parsePositiveInt、classifyError 等）；
    • failover（12 项）：级联恢复 / 中止 / 模型与池路由（createLinkedAbortController、normalizeModelForAdapter 等）；
    • languageRecovery（7 项）：khy 中文一致性恢复；
    • ocrRescue（3 项）：视觉 OCR 兜底（_appendVisionKeyOffer、extractImageOcrDetails、tryRateLimitOcrRescue）;
    • diagnostics（3 项）：_advDiag / _modelSwitch / _traceAudit 三个 set-once 模块 let。
  • fail-fast 校验：35 项中仅 diagnostics 三项可选（方法体内全程 if (x) 守卫、可合法为 null），其余 32 项为必选（方法体内均为裸调用）。setter 对合并后模块状态做一次性校验，缺失必选项时在注入期立即点名抛错（注入 aiGatewayGenerateMethod 依赖失败:必选 32 项中已注入 N 项、缺失 M 项(组名.项名, ...)），把「运行到对应路径才静默崩坏」提前为「注入期显式失败」；注入齐备时行为零变化。
  • 旧扁平形态兼容：setter 同时接受分组形态（生产注入点 aiGateway.js 已改为分组传入）与旧扁平形态（测试桩逐项增量覆盖），两种形态到达模块 let 的绑定值逐项一致；未知键静默忽略，旧测试桩传入不破。
  • 遗留注入项 extractImageOcrTexts 已移除（Batch 5）：方法体内零调用；源函数仍在 aiGateway.js 供 rate-limit OCR 兜底内部使用。

2.5 proxyServer 死码清理#

  • 删除 services/backend/src/services/gateway/proxyServer.js 内 4 个全仓零引用的 helper：reservoirGetDegraded、withFallbackMeta、extractOpenAIContent、sanitizeIpHeaders。
  • 删除后全仓（services/backend）对这四个标识符检索为 0 命中；纯减法、无行为影响。

2.6 token 用量路径 portable-aware#

  • tokenUsageService.js 的用量文件解析改为惰性双层：_usageFile() 优先经 utils/dataHome.getAppHome() 解析到应用数据家目录下的 token_usage.json（便携部署时数据留在安装目录内）；dataHome 不可用时回退 _legacyUsageFile()（~/.khyquant/token_usage.json，legacy 位置）。

三、行为不变性与回归保障#

  • 导出面恒等：tokenUsageService.js 的 21 个导出键（recordUsage … TOKEN_PRICING、USD_TO_CNY、_fmtTokenCount）逐一保持不变；TOKEN_PRICING / USD_TO_CNY 与叶子内常量为同一对象身份。
  • 调用点逐字节等价：_parseMs / normalizeModelId* 的所有消费方以同名本地绑定接入单一真源，调用处代码零改动。
  • fail-fast 仅覆盖既有静默故障域：依赖注入齐备时 generate() 行为零变化；OCR 告诫链路（覆盖率/截断/语言/旋转/分辨率）的三个网关注入点行为保持不变。
  • 新增 4 个测试文件：
    • services/backend/tests/gateway/envParse.test.js
    • services/backend/tests/gateway/modelIdParse.test.js
    • services/backend/tests/gateway/aiGatewayGenerateMethodDepsFailFast.test.js
    • services/backend/tests/services/tokenPricing.test.js
  • 回归基线：整体 Jest 失败套件名集合零新增（基线 133 → 本轮后 131，只减不增）；scripts/check-agent-rules.js 对触及文件零新增 error；三维评审（正确性/一致性/可维护性）结论 0 blocker / 0 major / 1 minor。
