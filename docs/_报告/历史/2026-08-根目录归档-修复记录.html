2026-08 根目录归档：修复记录#

一、修掉的两个问题#

1. khy 启动时 CLI 卡死#

项内容
症状敲 khy 后卡住，登录输入框不出现，无法输入任何内容
根因登录流程里 await bootstrap({ silent: true }) 去初始化数据库；数据库未配置/未启动时该调用无超时保护，整个 CLI 被阻塞
修法去掉 bootstrap() 依赖，改用纯文件系统的 loadOrCreateDefaultAdminCredentials()（同步、不碰数据库），立即返回
落点services/backend/bin/khy.js、services/backend/src/services/credentialGenerator.js

同批修掉的次生问题：自动登录失败后走 auth.register()，而注册需要数据库连接，后端未起时同样会挂死 —— 加了 10 秒注册超时 + 提示「后端可能未运行」。这条链路的现行行为见 [OPS-MAN-175] 首次运行自动登录与凭据。

2. /model 菜单长时间无响应#

项内容
症状CLI 里输入 /model 后长时间无输出，像卡死
根因构建模型清单要逐个探测所有启用的适配器，单适配器默认超时 8 秒（生成探测 25 秒），且 Promise.all 同步等全部完成 —— 3 个不通的适配器就能累到 70 秒以上，期间没有任何整体超时兜底
修法① 加多层超时（整体 45s / 探测 30s / 构建 20s）；② 单适配器超时降到 4 秒；③ 加「快速失败」模式跳过耗时初始化；④ 每一步打印进度提示，让「卡在哪」可观测
落点services/backend/src/cli/handlers/gatewayModelChoices.js、src/cli/handlers/gateway.js

加进度提示这一条是这次修复里最有复用价值的部分：探测阶段现在会依次打印「正在初始化网关 → 正在同步 switch-center → 正在初始化网关适配器 → 正在刷新适配器 → 正在获取适配器状态 → 检测各通道连通性」。再遇到疑似卡死，记下最后一条提示就能定位到具体阶段，不必再猜。

二、相关环境开关（已核实存在于代码）#

归档时逐个核对过，下表五个变量在代码中真实生效：

变量作用定义处
KHY_MODEL_QUICK_FAIL快速失败模式，跳过耗时初始化gatewayModelChoices.js:164
KHY_MODEL_OVERALL_TIMEOUT_MS模型清单构建的整体超时gatewayModelChoices.js:267
KHY_MODEL_BUILD_TIMEOUT_MS构建阶段超时gatewayModelChoices.js:694
KHY_MODEL_PROBE_TIMEOUT_MS单适配器连通性探测超时gateway.js:2087
KHY_MODEL_PROBE_GENERATION_TIMEOUT_MS生成能力探测超时gateway.js:2097

/model 慢的时候，缩短探测超时通常比禁用适配器更划算：

$env:KHY_MODEL_QUICK_FAIL = "true"
$env:KHY_MODEL_PROBE_TIMEOUT_MS = "2000"
khy

不想进菜单也可以绕开：gateway status 看通道状态、gateway config 直接配。

遗留：这五个开关尚未登记进 flag registry（scripts/ci/check-flag-registry.js 的真源表），因此也不在 [OPS-MAN-058] 环境开关与文档命名规范 的清单里。补登记是独立一项工作，不在本次归档范围内。
