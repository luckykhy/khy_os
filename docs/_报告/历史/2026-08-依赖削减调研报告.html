Khy-OS 依赖削减调研报告#

调研日期：2026-08-14

1. 范围与方法#

覆盖 Python 启动层、Node.js 后端、两个 Vue 前端，以及 C/ASM + MoonBit 内核。

证据命令：

npm ls --all --json
npm dedupe --dry-run --workspace=services/backend
npm explain <package>
du -sb node_modules apps/ai-frontend/node_modules apps/ai-frontend/dist kernel/build
grep -rE "require\(|from |import\(" <source trees>
npm run build --prefix apps/ai-frontend
npm test -- --runInBand

Python 环境只有 Microsoft Store redirector，不是真实解释器；因此本轮只能审计 manifest 和源码 import，不能生成 wheel/sdist 或测安装体积。software/khyquant/frontend 初始 lockfile 与 manifest 不同步；阶段二已修复 lockfile 并建立 clean-install/build 基线。

3.4 Rust / MoonBit / Kernel#

  • 仓库没有 Cargo.toml，因此没有 Cargo 第三方 crate 树。
  • kernel/moonbit/moon.mod.json 的 deps 为空，MoonBit 达到零第三方包依赖。
  • 构建工具依赖为 gcc/clang、ld/lld、nasm、MoonBit compiler、QEMU/GRUB/Limine；属于工具链而非运行时依赖。
  • 内核构建物已有：ISO 5.66 MiB、binary 828.4 KiB。P2 可做 section/strip/map 分析，但不能以牺牲调试性和启动正确性为代价。

4. 分类清单#

可用标准库替代#

  • axios -> Node 20 / browser fetch（渐进迁移）
  • node-cron -> calibrated setTimeout
  • dotenv -> Node --env-file 仅适用于简单加载；项目还使用 parse() 与多文件覆盖，需保留小 parser 或渐进迁移
  • Python requests -> urllib.request（仅简单请求路径）
  • tqdm -> 简单 stderr progress（ML optional）
  • loguru -> logging（ML optional）
  • pyyaml -> 仅当配置可迁 JSON/TOML；不要自研 YAML parser

可合并去重#

  • 删除 backend 的直接 @alcalzone/ansi-tokenize，使用 Ink 自带版本
  • 删除 ai-backend 的未使用 ioredis，统一 Redis 客户端为 redis
  • workspace 中 @khy/shared 声明/链接修复，避免 invalid + duplicate install
  • 统一 string-width / ansi 系列版本（受 Ink/inquirer 兼容约束）
  • 统一 frontend 的 Vue / Axios / Element Plus 版本，通过 workspace 锁定

可自研极简实现#

  • 日志文件轮转：Node fs + size/date policy（先基准与并发测试）
  • 简单 CLI table/progress（仅非 Ink 路径）
  • 定时任务：wall-clock-aware timer
  • HTTP JSON wrapper：在内置 fetch 上封装 timeout/retry/proxy contract

建议保留#

  • 密码/JWT/WebAuthn/TLS/URL 安全路径
  • Sequelize/pg、HTML parser、ZIP、QR、WebSocket server
  • Vue/Ink/React、图编辑器、终端模拟、交易图表
  • ML/数据科学依赖作为 optional profile
  • DOMPurify 与 Markdown parser 的安全组合

P2：性能/架构优化，体积未必下降#

  • logger 热路径批量写、轮转与 backpressure 基准

  • 前端路由 chunk 与重组件 prefetch 策略
  • 内核 binary section/map/strip 分析
  • Express -> node:http 仅针对新建的窄接口，不做全量重写

6. 阈值与逐项验收#

每项改造都记录：

  1. manifest direct runtime dependency count
  2. clean-install lockfile package count（能执行时）
  3. node_modules / dist / wheel / binary bytes
  4. 受影响测试 + build + CLI smoke
  5. CLI 冷启动或前端 build/chunk 指标

性能回退超过 5% 时停止该项并报告，不进入下一项；5% 内需说明噪声与采样次数。
