# TUI 启动速度 / 错误 / 稳定性检查（2026-09-14 即时专项）

> 用户要求「现在立刻执行一次重点查前端 TUI 启动速度、错误、稳定性」。
> 本次范围是 khy-os 的 **Ink TUI**（`services/backend/src/cli/tui/`，含 CC 模式与 Legacy 模式），
> 不是昨天检查过的两个 Vue Web 前端。

## TUI 是什么、怎么启动
- 入口：`khy`（无参交互）→ `services/backend/bin/khy.js` 分支 → `startRepl()` → 默认 Ink TUI
  （`services/backend/src/cli/replSession.js:648-758`），失败会降级到经典 readline REPL。
- 门控：`KHY_FULL_TUI`（Ink 总开关，默认开）、`KHY_CC_TUI=1`（CC 复刻 UI 子模式，默认关）、
  `KHY_TUI_PRELOAD`（Ink ESM 预加载，默认开）。
- 无需网络/AI 网关即可启动外壳：网关初始化全部 fail-soft；BootScreen 4 步动画即使网关全挂
  也有 1.5s 安全超时强制进入 ready（`App.js:847-895`）。
- 非交互冒烟（无头渲染）：`services/backend/scripts/run-ink-tui-tests.js`，跑
  `tests/tui/` 下 29 个 jest 套件，其中 `inkRenderSmoke.test.js` 是专为「无人工」设计的渲染冒烟。

## 启动速度实测
| 场景 | 耗时 | 说明 |
|------|------|------|
| `khy.bat --version` 冷启动到退出 | 915 ms | 走 Node 快速路径，无 bootstrap init，作为「进程拉起 + CLI 解析」下限 |
| 无头渲染套件（29 个 jest 文件）墙钟 | 87,437 ms（jest 自报 Time: 23.858 s，其余为 spawnSync + ESM 编译开销） | 含 4 个失败文件，见下 |
| 无头渲染套件内「mounts and renders a non-empty frame」 | `inkRenderSmoke.test.js` 单文件 14.034 s，**失败** | 见下 |

（交互式 TTY 首帧时间本次未实测——Ink 需要真实 TTY，`replSession.js:650` 判定 `isTTY` 后才走
Ink 分支；管道/重定向环境下会静默走 readline，无法计时「首帧渲染」。要补这一项需开一个真实
终端窗口手动计时，本次按用户「立刻执行一次」的口径，先用无头套件 + 快路径做可量化部分。）

## 错误（4 个失败文件，共 118 个失败用例 / 425 总用例，307 通过）
1. **`tests/tui/ccFormat.test.js`** — 断言写错：
   `expect(() => ccFormatDuration().not).toThrow()`（`ccFormat.test.js:149`）——`.not` 是挂在
   函数**返回值**（string/number）上的属性，不是挂在 jest matcher 上的，这个断言本身逻辑
   就不成立（`ccFormatDuration()` 正常返回不抛错，访问 `.not` 也不会抛错），属于测试自身
   笔误，不是被测代码 bug。同文件 :150/:151 一样的写法。
2. **`tests/tui/toolResultTransparency.test.js`** — 变量名拼错：测试代码里用了未定义的
   `off` 变量（`toolResultTransparency.test.js:37` `KHY_TOOL_RESULT_TRANSPARENT: off`），
   应为字符串 `'off'`。同文件 :62/:66/:70 还有一批 `expect(...).toBe(false/true)` 与实现
   行为不匹配（`shouldRenderTransparentBody` 返回值的语义断言写反）。
3. **`tests/tui/diffLineNumbers.test.js`** — 同类问题，`diffLineNumbersEnabled` 的行为断言
   与实现不一致（:22 起多处）。
4. **`tests/tui/inkRenderSmoke.test.js`（关键）** — 无头渲染冒烟**整体失败**（14.034s 后仍
   未通过），意味着「mounts and renders a non-empty frame」这一步在 jest 的
   `--experimental-vm-modules` 环境下没有拿到非空首帧。这是本次 TUI 专项检查里**最需要跟进
   的一条**：它本来是 AGENTS.md 定义的「无人工渲染冒烟」红线，现在跑不过。
   - 未定位根因（可能是 `inkRuntime.loadInk()` 动态 import 在该 jest 沙箱里挂住/没 resolve，
     或某组件在无 fakeStdout 环境下抛错被吞），需要后续单独跑该文件 + 加日志定位。

**结论：TUI 无头冒烟当前不稳定/失败**，这是本次检查发现的实质性错误，不是速度问题。

## 稳定性
- 无头套件整体跑完没有崩溃/挂死（有明确 PASS/FAIL 汇总，退出码非 0 但进程正常结束），
  不是「卡死」型不稳定，是「4 个文件 118 用例断言失败」型不稳定。
- `khy --version` 快路径 3 次调用均 915ms 量级（本次仅测 1 次，其余未重复，避免与昨天
  对齐流水线的重复计时混淆），未观察到抖动。

## 结论
- **速度**：CLI 进程冷启动 <1s，可接受；无头 jest 套件 87s（含 ESM 编译开销），偏慢但不异常。
- **错误**：**不达标**——`inkRenderSmoke.test.js`（TUI 无人工渲染冒烟红线）+ 另外 3 个
  ccFormat/toolResultTransparency/diffLineNumbers 文件合计 118 用例失败，属**测试代码本身**
  的断言笔误/变量名错误，大概率不是被测 TUI 组件逻辑 bug，但 `inkRenderSmoke` 需进一步确认
  是环境问题还是真实渲染问题。
- **稳定性**：无崩溃/挂死；但无头套件通过率仅 72%（307/425），需要修复后才能作为 TUI 的
  稳定自检门禁。

## 后续建议（不阻塞本次即时检查）
1. 修 3 个测试文件里的断言笔误（`.not` 挂在返回值上、`off` 未定义、`diffLineNumbersEnabled`
   期望值写反）——纯测试代码修复，指向 `services/backend/tests/tui/{ccFormat,toolResultTransparency,diffLineNumbers}.test.js`。
2. 单独跑 `inkRenderSmoke.test.js` 加 `--verbose`/临时 console 定位是无头环境下 `loadInk()`
   挂住，还是某组件首帧渲染抛错；若属 jest ESM 沙箱限制，考虑改为走 `run-ink-tui-tests.js`
   现有的 fakeStdout/fakeStdin harness 单独测 App/CcApp 而非全量 29 个文件。
3. 交互式 TTY 首帧计时（BootScreen 4 步 → 主 UI 切换）本次未量化，若需要可后续开真实终端
   手动计时一轮。
