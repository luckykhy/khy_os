前端启动速度 / 错误 / 稳定性检查（2026-09-14 即时专项）#

用户要求「现在立刻执行一次重点查前端启动速度、错误、稳定性」，本文件是即时专项结果，
不属于每日 13:00 对齐流水线（那个已降级为 khy 单侧自检，见任务单顶部说明）。

测试对象#

  • apps/ai-frontend（khy-ai-frontend，Vite + Vue 3，默认端口 8090，AI_FRONTEND_PORT 可覆盖）
  • software/khyquant/frontend（quant-trading-frontend，Vite + Vue 3 + PWA，默认端口 8080）

启动速度实测（dev server，pnpm run dev / dev-no-browser）#

测量口径：cmd /c "cd <dir> && pnpm run <script>" 后台启动，轮询 http://127.0.0.1:<port>/
直至 200，记录墙钟（含 pnpm 加载 + predev 钩子 + Vite ready + 首次 HTTP 探测），3 次取平均；
另做一轮「清理 node_modules/.vite 缓存后冷启动」量化首次真实体验。

前端场景耗时稳定性（3 次连续 200）备注
ai-frontend冷启动（首轮）8.2s稳定predev sync-md-vendor 输出「optional asset missing: khyos-muya.js/css/MANIFEST.json」告警，跳过不阻断
ai-frontend热启动 R22.4s稳定Vite 自报 ready 739ms
ai-frontend热启动 R32.4s稳定Vite 自报 ready 712ms
ai-frontend清缓存冷启动2.5s稳定Vite 自报 ready 631ms（node_modules/.vite 重建很快，说明依赖预构建缓存有效）
khyquant 前端R12.4s稳定Vite 自报 ready 738ms
khyquant 前端R22.5s稳定Vite 自报 ready 678ms
khyquant 前端R32.4s稳定Vite 自报 ready 721ms

速度结论：两个前端热启动均 ~2.4s、冷启动 2.5~8.2s，无异常慢轮次；Vite 自身 ready 时间稳定在 0.6~0.8s（热）/4.6s（ai-frontend 首轮全量预构建）。

错误检查#

  • dev server 运行全程无 JS 错误、无编译报错、无端口冲突（8080/8090 均一次绑定成功）。
  • ai-frontend predev 有 3 条「optional asset missing」warn（非错误，属设计上的可选项缺失提示）。
  • 生产构建（并行子代理实测）：
    • ai-frontend build 退出码 0，仅 2 条来自 @vueuse/core 的 Rollup #__PURE__ 依赖噪音警告，无业务代码错误。
    • khyquant 前端 build 退出码 0，除同类 2 条噪音外，有 1 条真实体积告警：vendor-element 单 chunk 1056 kB（gzip 322 kB）超过 600 kB 阈值（vite.config.js 里 chunkSizeWarningLimit: 600），建议后续用 manualChunks 或按需动态 import 拆分 element-plus。

稳定性检查#

  • 每个前端启动后连续 4 次 HTTP 探测（首轮 + 3 次复探）全部 200，无闪断、无 5xx。
  • 测试（并行子代理实测）：
    • ai-frontend：39 个测试文件，506/506 通过，0 失败。
    • khyquant 前端：24 个测试文件，302/302 通过，0 失败。
  • 仓库根 coverage_baseline_backend.log（后端基线，非本次前端专项范围，顺带记录）：2026-09-11 一次后端 jest 运行中出现 cache.test.js 3 例 5s 超时、groundTruthRatGuard.test.js 1 例 Date.now().toBeTruthy 写错断言、toolUseLoop.verificationGate.test.js 期望 2 次编辑实际 1 次——这些是后端测试问题，与前端启动无关，但既然做稳定性普查一并登记，见「后续建议」。

结论#

  • 速度：达标。热启动 2.4s 量级，冷启动 2.5~8.2s，未观察到 >10s 的异常轮次。
  • 错误：前端无阻断性错误；唯一需跟进的是 khyquant 前端 vendor-element chunk 超阈值（构建层面，不影响运行）。
  • 稳定性：达标。连续探测无闪断，两侧前端单测全绿。

后续建议（不阻塞）#

  1. khyquant 前端：把 element-plus 拆成独立按需 chunk（vite.config.js rollupOptions.output.manualChunks 已列 vendor-element，但实际产物仍是整包 1056 kB——检查是否 optimizeDeps.include 里的 element-plus 整包引入导致未生效按需拆分）。
  2. 顺带修 3 条后端 jest 失败用例（tests/routes/cache.test.js 超时、tests/groundTruthRatGuard.test.js:102 误写 expect(Date.now().toBeTruthy() - t < 1000)、tests/toolUseLoop.verificationGate.test.js 断言不匹配）——属于 1 点夜班组覆盖范围，不在本次前端专项内。
