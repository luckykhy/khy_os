问题#

1,617 条 console.log/info/warn/error 直接输出，无统一格式：

  • 可能泄露 API key、token、密码等敏感信息
  • 无日志级别控制
  • 无结构化输出
  • 生产环境无法关闭

对抗方案#

方案 A：引入 winston 日志框架

  • 优点：成熟、功能完善
  • 缺点：增加依赖、改动大

方案 B：创建轻量级 logger 工具

  • 优点：零依赖、改动小
  • 缺点：功能有限

方案 C：统一 logger + 渐进迁移

  • 创建 utils/logger.js 统一接口
  • 新代码强制使用
  • 旧代码渐进迁移

最终推荐：方案 C

二、错误消息不友好#

问题#

  • 技术术语多（如 "EADDRINUSE"、"ENOENT"）
  • 无修复建议

  • 中英文混杂

对抗方案#

方案 A：创建错误码体系

  • 统一错误码 + 用户友好消息 + 修复建议
  • 优点：专业、可维护
  • 缺点：工作量大

方案 B：仅包装关键错误

  • 仅包装用户可见的错误
  • 优点：改动小
  • 缺点：不完整

方案 C：错误码 + 渐进包装

  • 定义错误码体系
  • 关键路径优先包装

最终推荐：方案 C
