# 防止 khy-os「越改越差」——写入前拦截 + 逐文件棘轮

日期：2026-09-17
性质：方案提案（**Phase 0 与 L1 已编码落地**；L2/L3 待实施）
作者：诊断会话实测输出

---

## 0. 结论先行

**不要再新增检查器。**

本仓库已有 **74 个检查器、73 条规则、91.8% 可执行覆盖**（`npm run rules:coverage` 实测）。
数量不是缺口。缺口在两处结构性位置上：

| 缺口 | 现状 | 后果 |
|------|------|------|
| **位置错** | 所有拦截都发生在写入**之后** | 小模型一次 pass 改 40 个文件，全部落盘后才有声音 |
| **分母错** | 棘轮以**全仓**为分母 | 容忍度是实际值的 5.6 倍，只能拦「翻倍级」恶化 |

「越改越差」的机制不是缺檢查器，是**劣化发生在检查之前**，且**单次劣化量在噪声以下**。

## 1. 五条实测证据

> 全部为 2026-09-17 本机实跑结果，可复核。

### 证据 1 — 弱模型护栏的「拒绝」没有消费者（最关键）

`services/backend/src/services/toolUseLoopCore.js:10733` 注释原文：

> `// ... 事后顾问不硬拦(编辑已发生), 与 selfEditAdvisory 一致的 best-effort 姿态。`

`npm run check:weak-model-guard` 实测（0 error / **1 warning**）：

```
[WARN ] guard-declared-deny-unconsumed services/backend/src/services/toolUseLoopCore.js:1
  护栏调用点 toolUseLoopCore.js 只投递提醒文案（humanLine/aiNote），从不读取拒绝信号
  （allow / require-strong-review）：SECURITY-003 声明的「拒绝」实际只是事后提醒，编辑已发生。
```

即：**SECURITY-003 名义上是"拒绝"，实际是"事后唠叨"**。这正是「小模型搞破坏」的直接通道。

### 证据 2 — 棘轮只能拦「翻倍级」恶化

`scripts/ci/debt-ledger.json` 的 `_why` 自述：

> 容忍度是实际的 5.6x……红着的门等于没有门。

今日实测台账：开放条目 9 条，累计债务 **15934 处**。典型一例：

```
standards.consoleLog     4584 → 3000   dueBy 2026-12-31
standards.fileLines       352 →  300   dueBy 2026-12-31
standards.functionLines  2144 → 1600   dueBy 2026-12-31
standards.nestingDepth   8703 → 8707   ← target 反而比 measured 更差（靠 targetPending 字段声明豁免）
```

目标全在年底。以 `consoleLog` 为例：全仓 4584 条，小模型一次加 8 条 → 4592，**漂移 0.17%**，
在全仓棘轮下完全不可见。这就是「N 次微小劣化累积成灾难」的数学原因。

### 证据 3 — PR 门禁有 4 处 `continue-on-error`，红灯已常态化

`.github/workflows/pr-gate.yml`：

| 行 | 步骤 | 状态 |
|----|------|------|
| L68  | Check change safety (strict)      | `continue-on-error: true` |
| L167 | Check rule gate                   | shadow mode, `continue-on-error: true` |
| L337 | Lint modified files               | report only, `continue-on-error: true` |
| L363 | **test-baseline 整个 job**        | `continue-on-error: true` |

**测试完全不把关。** 仓库注释已自承 Phase 1→2→3 升级路径（"3 个月后"、"6 个月后"），
但按 E. 的可膨胀原则，`continue-on-error` 一旦登记就倾向永久化。

### 证据 4 — 本地无任何钩子

无 `.husky/`、无 `.pre-commit-config.yaml`、`.git/hooks/` 仅剩 sample。
`rules:gate:commit`（快档）已存在，**但没有自动触发点**。
→ 直推主干 / 本地修改，是零防护区。

### 证据 5 — 规则体系已近饱和，边际收益递减

```
规则 73 条 / 已执行 67 条 (91.8%)
检查器 65/74 已接线（零接线豁免 9 项）
未被任何规则登记的守卫脚本 26 个
人工评审兜底 5 条：MEMORY-001/004, PROCESS-001/101, DOCS-004
```

再加第 75 个检查器，收益接近 0，维护成本线性增长。

## 2. 三层措施

### L0 — 写入前硬拦截（把「事后唠叨」变成「事前拦截」）

**这是唯一一处能真正翻转时间顺序的改动，优先级最高。**

- **位置**：`services/backend/src/tools/{FileEdit,FileWrite,MultiEdit,ApplyPatch}Tool/index.js`，
  在真正 `fs.writeFileSync` **之前**调用已有的 `weakModelChangeGuard.assessWeakModelChange()`。
- **契约**：`allow === false` → 返回**工具级错误**（而非 advisory 文案），写入不发生。
- **fail-closed**：未知 tier 按最弱档处理（对齐 SECURITY-004 不变量）；
  判定必须与 `KHY_PERMISSION_MODE=bypass/yolo`、`KHY_SYSCALL_GATEWAY=off` 无关
  （复用 SECURITY-002 `isUnbypassableGate` 的既有模式与断言）。
- **门限不变**：仅 `tier ∈ {T2,T3}` 且 `risk === 'red-line'` 才挡；`sensitive` 仍为 confirm。
  不会误伤 T0/T1 与日常编辑。
- **反哺现有守卫**：`check-weak-model-guard` 的第 8 条断言（`guard-declared-deny-unconsumed`）
  会从 WARN 自然升级为 ERROR —— 因为拒绝信号终于有消费者了。这是**自检效果**，不需要手写。

> 配套警戒：`KHY_WEAK_MODEL_EDIT_GUARD=off` 逃生阀保留，但必须**默认开**，
> 且需要一条守卫防止它被写进默认配置（否则等于把锁焊死在开门位）。

### L1 — 逐文件「改前 vs 改后」棘轮（换分母）

取代全仓基线对小漂移的无力。核心规则一句话：

> **存量债冻结不动，但文件一旦被摸过，它的债不许增加。**

对每个变更文件 F，采集同一组指标，对比 `git diff <base>...HEAD`：

| 指标 | 方向 | 备注 |
|------|------|------|
| `lines`            | 只降 | 行数 |
| `maxFunctionLines` | 只降 | — |
| `maxNesting`       | 只降 | 需先修计量口径（见 debt-ledger `nestingDepth` 条） |
| `consoleCalls`     | 只降 | 非测试文件 |
| `lintErrors`       | 只降 | 缺口正是 pr-gate L337 的 report-only |
| `lintWarnings`     | 只降 | 同上 |
| `duplicateBlocks`  | 只降 | 复用 check-duplication 已有能力 |
| `todoCount`        | 只降 | 防「标记代替修复」 |

**判定**：
- 新增文件（状态 A）→ 零容忍档，全部指标不得超过新文件阈值。
- 修改文件（状态 M）→ `metric_after(F) ≤ metric_before(F)`，严格成立。
- 违反 → error + 退出码 1；显式豁免走 `--accept=<file>:<理由>`，
  写入 `regression-exemptions.json`，带 `owner` + `dueBy` + 到期自动复检（不得是永久通行证）。

**为什么比全仓棘轮强**：同一个 `consoleLog` 例子 ——
全仓视角 4584→4592（+0.17%，不可见）；
被改的那个文件视角 12→20（**+67%，立刻红**）。

**副作用是正面的**：它把"还债"的激励放对了地方 —— 你想改一个脏文件，就得顺手把它弄干净，
而不是像现在这样随便改、脏债原样留下。

> 全仓棘轮**不废弃**，两者并存：全仓棘轮拦「别人搬走文件、新增未登记目录」这类全局破坏，
> 逐文件棘轮拦「每次 +3 行」的漂移。

#### L1 实现状态（2026-09-17 已落地）

- **脚本**：`scripts/ci/check-file-ratchet.js`（AST-free、零依赖、秒级）。
- **配置**：`scripts/ci/file-ratchet.config.json`（caps / softMetrics / exceptions）。
- **指标模型**：HARD（变差即红）= `maxFuncLines` / `maxNesting` / `consoleCount` /
  `debuggerCount` / `todoCount`；SOFT（只报告）= `lines` / `dupBlock`。
  lint 指标（原提案表里的 `lintErrors/lintWarnings`）默认不内置，避免每文件跑全量 eslint
  拖慢门禁；现有 pr-gate 的 lint 步骤已覆盖该维度，故不重复。
- **判定**：M/R 文件比 base 与 head 的同一指标，任一 HARD 变差 → error；A 文件按 `caps` 绝对上限卡。
- **接线**：
  - `pr-gate.yml` 在 report-only lint 步骤后新增**阻断**步骤 `Check per-file change ratchet`
    （无 `continue-on-error`，`GIT_BASE_REF = PR base.sha`）。
  - `package.json` 新增 `check:file-ratchet`；并接入 `check:changed` 本地链尾（本地提交前即可拦）。
- **测试**：19 项断言全绿（单测覆盖指标/评估/例外/解析；集成用临时 git 仓库验证
  改坏既有文件→exit 1、新增脏文件→over-cap、无变化→exit 0）。
- **已知约束**：本机 Git Bash 的 `tail/grep/cd/rm` 被 shim 截断，取值一律走 node + `spawnSync` 收集；
  仓库实际上游是 `khy-mirror/main`（勿硬编码 `origin/main`）。

### L2 — 计数棘轮，替代「全绿才过」

这是解开「红灯常态化」两难的正确姿势。现状：9 个失败用例 → 整个 test job 不阻断。
不是桩上墙——而是在拦住新劣化的同时不打死主干。

- 记录基线 `{ passed, failed, skipped }`。
- 断言：**`failed` 不得增加、`passed` 不得减少**。
- 存量 9 个失败可以躺债去还，但**谁弄坏一个新的，立刻红**。
- 达标后可平滑升级为"全绿才过"，届时删掉 `continue-on-error` 即可。

同理适用于 E：并不能让 rules:gate 立刻转阻断，但可以先把 gate 内的计数棘轮起来。

### L3 — 健康快照时间序列 + 回滚锚点

- `npm run health:snapshot` → 产出 `{ commit, date, metrics{} }`，追加到时间序列。
- 劣化发生时输出：**「上次绿在 <sha>，差 <n> 项」**，让回溯有锚点。
- 每次绿灯的发展分支的 commit sha 都能成为回滚点。

## 4. 明确的反模式（不要做）

1. **不要再加第 75 个检查器。** 91.8% 覆盖说明瓶颈不在这。
2. **不要试图让 `weakModelChangeGuard` 认识更多红线路径。** 6 类红线已足够；
   「改坏」的主要来源不是改红线文件，而是**在普通文件里堆积劣化**
   （`aiChatCore.js` 涨到 4738 行就是这么来的）。
3. **不要把 `continue-on-error` 一把删掉。** 那会让主干永久红灯，然后所有人学会忽略红色 ——
   这正是债务台账 `_why` 记下的教训。用计数棘轮过渡。
4. **不要让新守卫可被 `--yolo` 绕过。** 必须复用 `isUnbypassableGate` 的 fail-closed 模式。
