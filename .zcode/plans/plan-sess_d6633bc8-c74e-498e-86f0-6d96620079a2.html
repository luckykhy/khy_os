计划：新增 [DESIGN-LAY-002] 目录层级与文件归类规范#

结论先行#

用户要的这份规则，大部分骨架已存在（[DESIGN-ARCH-068] 定 L0–L6 与依赖边、[MGMT-STD-001] 定文档编号、[DESIGN-DOC-001]/[DESIGN-NAM-001] 定文件名），真正的空白只有四个：①公共 vs 私有边界（仓库里从未定义过，连「私有目录」四个字都不在 docs 里）②分层→命名风格映射 ③文件归类标准（哪些扩展名能落在哪一层）④完整的典型目录树示例（README 只画到 4 个顶层目录）。

因此做法不是再立一套平行真源，而是在 _规范/ 下用既有 LAY 域码新增一篇规范，显式声明「层级 SSOT 仍归 ARCH-068，本文只补正交维度」，并把四个空白写满、附冲突裁决。落位已按你选定的方案。

一、新建规范正文#

文件：docs/_规范/[DESIGN-LAY-002] 目录层级与文件归类规范.md

选 DESIGN-LAY-002 的依据：DESIGN-LAY-001（后端分层架构规范）开篇即声明「ARCH-068 §4 已定义仓库七层模型，本文档聚焦 L2 内部」，且索引里记录了它从 DESIGN-ARCH-082 改号迁入 _规范 的先例——说明团队已在主动把规范味文档迁出 ARCH 序列。同域同族、编号顺接，且 MGMT-STD-008 §3.1 明确 LAYOUT 域职责就是「目录层级、依赖方向、根/任务入口命名、文件规模上限」，P1 档示例也直接写了「布局层级」。

章节骨架：

  1. 定位与边界 — 一句话用途 + 一张 SSOT 指针表（层级→ARCH-068、文档编号→MGMT-STD-001 §2.3、文件名→DESIGN-DOC-001 §2 / DESIGN-NAM-001 §10.1、后端内部分层→DESIGN-LAY-001、扩展包布局→ARCH-069）。按 MGMT-STD-008 §3.2「跨域引用用 ID，不抄正文」，只放指针和摘要。
  2. 第 4 轴：公共 / 内部 / 私有（与 L0–L6 正交，这是新增轴，必须写明正交关系而非细化）
    • PUB 共享：跨层可依赖，必须是 pnpm workspace 包且 "private": true。仓库现状登记：只有 @khy/shared（platform/packages/shared，v1.6.5）与 @khy/ui-shared（v0.1.0）两个，且 @khy/shared 的 src/index.js 头部注释是仓库里唯一一处「谁可以依赖我」的声明。
    • INT 内部：仅同层可依赖。
    • PRV 私有：仅同包可依赖，命名信号为 _ 前缀或 __tests__。
    • 四问判定树 + 三张清单：现有 PUB 清单 / 私有反例清单（services/backend/vendor/shared 构建期镜像、services/backend/src/services/_llmDecomposer.js、platform/khy_platform/_bootstrap.py、kernel/moonbit/_build/、.khyos/deadcode-quarantine/）/ 应下沉清单（引用 ARCH-068 §2.1② 已点名的 8 个纯函数）。
    • _ 前缀三义冲突裁定：现状同一个前缀同时表示「跨阶段轴」（ARCH-068 §3.1 明确「不是隐藏或不重要」）、「模块私有」（_bootstrap.py）、「临时草稿」（khy-Trajectory/_probe*.txt）。裁定：跨阶段轴仅适用于 docs/ 顶层，代码树内 _ 一律表示 PRV，临时草稿不得进入 docs 正文层级。
  3. 分层 → 命名映射表 — L0–L6 + 横切各自的语言轴与命名风格：L0 kernel/（C/asm，snake_case）、L1 platform/khy_platform（Python，snake_case）、L2 services/（JS CommonJS，camelCase，实测基线 6622 个 .js）、L3/L4 前端（Vue/TS，camelCase 目录）、L5 extensions/<分类>/<id>/（id 必须等于叶子目录名，ARCH-069 约束，MAX_DEPTH=2）、L6 tools/、横切 scripts/。每行注明「真源」列，避免被误读为替代 NAM-001。
  4. 文件归类标准 — 扩展名 → 允许层级矩阵（.js/.mjs/.cjs/.ts/.tsx/.vue/.py/.c/.h/.asm/.mbt/.md+.html 孪生/.json 配置/.bat+.ps1+.sh 三档 launcher 放置），产物与源码分界（指向 ARCH-068 §1.3 GENERATED_TOP_LEVEL_DIRS），草稿与产物分界（_产物/ 已冻结语义）。
  5. 完整典型目录树示例 — 覆盖全部 L0–L6 + 横切层 + docs 两轴，每个节点一行职责注释，每个节点同时标注「层」（L0–L6/横切）与「可见性」（PUB/INT/PRV）。树形按 ARCH-068 §1.2 的 CROSSCUTTING 集合核对，不引入任何未登记的顶层目录。
  6. 冲突裁决（按 MGMT-STD-008 §2.2 裁决算法逐条给出，含优先级与理由）
    • ①HTML 孪生：裁定「.md 必有同名 .html 且纳入版本控制」，依据 OPS-MAN-169 §2.5 + verify_docs_site.js 硬门 + git 实际跟踪 463 个 docs .html；同时修正已失效的 [DESIN-DOC-001] §6（见下）。
    • ②JS 文件命名：裁定 camelCase 优先，不追溯改名存量。
    • ③_source/ 注册表幻影：裁定已废弃未落地。
  7. 可追溯表 — 每条规则 ← 覆盖它的既有守卫，未覆盖者标注「人工评审」。遵守你选定的「不加新守卫」：只读引用，不新增 scripts/ci/ 文件。
  8. 例外与豁免 / 9. 版本记录。

元规则合规点（必须写进正文，否则会被判 CP-6 违规）：[MGMT-STD-001] §2.3 / CP-6 明文禁止在任何规范或提示词里写死编号格式。所以本文只规定目录名的风格族（camelCase / snake_case / kebab-case 的适用语言轴），不规定 docs 内的 [STAGE-TYPE-NUMBER] 编号格式、不规定索引文件前缀；第 5 节的树必须显式标注「示例，非强制格式」，docs 侧编号一律指向 MGMT-STD-001 §2.3 由执行 AI 动态决策。

二、配套修改（缺一不可）#

  1. docs/_规范/00_INDEX_规范-总目录.md — §二「文件清单（按域分组）」LAY 组下补一行（参照 DESIGN-LAY-001 那行的写法）。CP-3 强制。
  2. docs/_规范/[DESIGN-INDEX-001] 规范索引.md — §1 情景速查补一行「放新文件前看哪篇」，§2 分域清单补一行。
  3. docs/00_INDEX_文档索引.md — _规范 分区补一行 + 更新顶部计数。
  4. docs/_规范/RULES-REGISTRY.json — 新增 LAYOUT-001 条目，按 MGMT-STD-008 §1.1 填满 15 个必填字段（domain: "LAYOUT"、priority: "P1"、status: "active"、nature、trigger、constraint、grants、benefit、exception、version、ssot、owner 等）。LAYOUT 在 check-gov-rules.js 的 RULE_DOMAINS 白名单内，字段缺失或权力无约束边界配对会被 GOV-TOOL-006 直接判违规。
  5. docs/_规范/[DESIGN-DOC-001] 文档结构规范.md §6 — 删除「HTML 为导出格式，不纳入版本控制」及那段不存在的 gitignore 片段，改为指向 OPS-MAN-169 §2.5 与 verify_docs_site.js，并在版本记录注明 2026-09-15 裁决。这是你选定「修正明确失效项」中确认的唯一一处过时条文修正。

第 6 项（可选但建议，与前三项独立可拆开）：_source/ 幻影注册。ARCH-068 §1.4 明文「只改脚本不改本文即视为违规」，反过来只改本文不改脚本同样是文档/守卫分叉。若要清干净，必须三处同步：ARCH-068 §1.2 表格删行 + scripts/ci/check-repo-layout.js 的 CROSSCUTTING 删除 _source 键 + scripts/ci/repo-layout-baseline.json 删对应字段。改动极小但触及守卫代码，故单独列为可选项。

不做的事：不新增 scripts/ci/ 守卫；不重命名任何存量文件（kebab-case 分歧只裁定不追溯）；不改 check-repo-layout.js 的规则集（除非做第 6 项）；不动 ARCH-068 的层级表本身。

三、生成与验证#

npm run docs:build          # 生成 .html 孪生（不手写 HTML）
npm run docs:verify         # 孪生齐全 + 本地链接可解析，红灯即非零退出
npm run check:layout        # root-whitelist / layer-registry / docs-index-* 不得新增命中
npm run check:gov-rules     # RULES-REGISTRY.json 新条目字段与配对铁律校验
npm run check:structure     # 上述两项 + 其余 11 个守卫的完整链

验收标准：五条命令全部 exit 0；check:layout 的各 warning 计数不高于 repo-layout-baseline.json 现有值（当前全 0）；新 .md 有同名 .html 且被 git 跟踪；三处索引均含新条目。
