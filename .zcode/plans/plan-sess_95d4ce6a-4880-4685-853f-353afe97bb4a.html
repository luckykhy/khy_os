目标#

支持改名：新增 khy user rename <新账号名>（TUI 内 /user），把当前登录账号在所有存储面上原子地改名，旧名自动保留为登录别名（现有 ARCH-074 别名机制），避免改名后登录失效。

设计决策#

  • 命令名：khy user rename <新名>（顶层 user + 子命令 rename；裸 khy user <新名> 也接受；不带参数时交互询问；/user 斜杠命令走同一入口）。已确认 user 在各 dispatcher、命令注册表、斜杠菜单中均空闲，不与会话标题改名 /rename 冲突。
  • 改名对象：以当前 session 的用户名为准，自动识别两种账号并存更新：
    1. 默认管理员（.khy/credentials/default-admin.json）
    2. 本地注册账号（credentials.json + 会话 session.json）
  • 旧名保留：数据库行与本地 credentials 都把旧名 push 进 aliases（登录解析顺序 username→email→alias，旧名/旧 token 仍可登录）；邮箱仅当本地部分等于旧用户名时换 local part、保留域名。
  • 无密码确认：默认管理员密码是自动生成的随机值（用户未必知道），且本机改名与 khy doctor/clean 同等信任级别——不设密码门槛。
  • 安全/冲突：改名前做硬冲突检查——数据库已存在同名账号或 bridge 库已存在同名 → 直接中止（规则 2.2 具体报错）；数据库不可用则本机照常改名并如实标注「数据库未同步」。
  • 校验：2–32 位 [a-zA-Z0-9_-]（复用 credentialGenerator.validateCustomUsername，与首次登录自定义同一契约）；bridge 库自身规则是 2–20 位无连字符，超限时跳过 bridge 并标注（fail-soft，不阻断）。

改动文件（7 个 + 测试）#

  1. services/backend/src/services/credentialGenerator.js
    • 新增 renameDefaultAdminCredentials(newUsername)：同步改 default-admin.json 的 username（密码不变，写 renamedFrom/renamedAt）；文件不存在/同名/非法名 → {ok:false, reason}。
    • 新增 renameDefaultAdminUserInDb(oldName, newName, {email})：仿 ensureDefaultAdminPassword 的 fail-soft 模式（@khy/shared/models 不可用不抛）；但同名/同邮箱冲突是硬失败（{ok:false, conflict:true}）；更新行 username+email（可选）并把旧名 push 进 user.aliases（beforeUpdate hook 只在 changed('password') 时哈希，改名不碰密码，安全）。
  2. services/backend/src/services/cliAuthService.js
    • 新增 renameAccount(newUsername) 编排器：session 检查 → 名称校验/同名检查 → DB 冲突预检（硬中止）→ DB 改名 → 默认管理员文件改名（若匹配）→ 本地 credentials 改名+旧名入 aliases（若匹配）→ 会话 username 原地更新 → bridge 改名（先冲突预检，fail-soft）→ 返回 {success, oldUsername, username, details[]}（每面一行中文状态，含「数据库未同步：原因」等）。
  3. services/backend/src/bridge/bridgeAuth.js
    • 新增并导出 renameBridgeUser(oldName, newName)：bridge 库文件不存在/新名不符 USERNAME_RE/无此行 → {ok:false, skipped:true, reason}；同名占用 → {ok:false, conflict:true}；否则 UPDATE users SET username=? WHERE username=?。
  4. services/backend/src/cli/routerDispatchTail.js
    • 在 case 'passwd' 旁加 case 'user'：未登录→具体报错；有参取 rename 子命令位或裸名；无参且 TTY→inquirer 单问「新账号名 (当前: xxx)」；非 TTY 无参→打印用法；调用 cliAuth.renameAccount()，成功打印 账号已改名: 旧 → 新 + 各明细行。
  5. services/backend/src/constants/commandSchema.js
    • ROUTER_COMMANDS 加 'user'；ROUTER_SUB_COMMANDS 加 user: ['rename']；CATEGORY_BY_COMMAND 加 user: 'security'；BUILTIN_SLASH_COMMANDS 加 { cmd:'/user', label:'账号改名', desc:'重命名登录账号(/user rename <新名>)', route:'user rename', category:'security' }（TUI 斜杠菜单与 REPL 自动可见）。
  6. services/backend/src/cli/aliases.js
    • 认证区（~576 行）加：改账号名/改用户名/gaidangzhao/gaiyonghuming → { command:'user', subCommand:'rename' }（naturalLanguageAliasGuard 无需改动——其白名单只保护整句自然语言，不保护明确命令意图）。
  7. services/backend/src/cli/tui/ink-components/App.js
    • 2354–2358 的 auth 命令判断加 parsed.command === 'user'；runAuthForm 加 command === 'user' 分支（仿 passwd 分支，单字段 FormFlow，未登录给 notice，成功后 已改名: 旧 → 新）。

明确不做（范围控制）#

  • user_logs.username 历史回刷（展示用，历史行保留旧名属正常审计痕迹）
  • 服务端新增 rename API 端点（CLI 与 monolith 共享同一 SQLite/PG 库，直接改行即对 Web 端可见）
  • Web 前端改名界面
