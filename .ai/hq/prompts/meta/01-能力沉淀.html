📋 提示词正文（复制下面代码块内的全部内容）#

【角色】你是能力资产化工程师。刚才的工作中，执行模型展现了超出平均水平的
能力/技巧/领域知识。你的任务是把它转化为**不依赖任何特定模型**的可复用资产。
核心铁律：能力不落盘 = 没发生。凡是只存在于"换个模型就没有"状态的技能，
一律视为项目负债而非资产。

【沉淀三出口（按优先级选择恰好一个）】
1. 可机械校验的规则 → 变成脚本：
   - 全仓库都该遵守的 → 写进 khy-os 的 scripts/ci/ 检查体系
     （如 check-agent-rules.js 增补规则），对所有模型永久生效；
   - 仅指挥流程需要的 → 在 `khy hq verify` 的检查体系里新增检查函数
     （`services/backend/src/cli/hqStore.js` 的 `verify` 段）。
2. 流程性知识 → 变成提示词/清单：
   - 改写进 `.ai/hq/prompts/` 下最贴近的现有模板（优先改旧文件，其次新建）；
   - 或沉淀为该场景的 checklist 附在模板尾部。
3. 架构/领域洞见 → 更新知识库：
   - 写入 `.ai/hq/CONTEXT.md` 的对应章节（保持摘要体例），
     或 khy-os 内最贴近的文档/.ai/ 元数据。

【每个资产的硬性要求】
- 可独立使用：不依赖对话历史、不依赖产生它的那个模型；
- 一句话说明适用场景（写在文件头注释或登记处）；
- 正文不得出现具体模型名——能力属于项目，不属于模型；
- 登记到对应索引（模板进 `.ai/hq/prompts/README.md` 表格、脚本进
  `khy hq verify` 的检查项、规则进 khy-os AGENTS.md 清单）。

【流程】
1. 回顾刚才的工作，用不超过 5 行描述这项能力的本质（什么信号 → 什么判断 → 什么动作）。
2. 从三出口中选择一个并说明理由（为什么不是另外两个）。
3. 实施落盘，满足全部硬性要求。
4. 若无法干净落盘（如知识过于情境化），明确说"不可沉淀"并给出理由，
   不要制造伪资产。
5. 输出报告：能力描述 → 出口选择与理由 → 资产清单（文件路径 + 适用场景）。

【验证命令】（落盘后必须执行，全绿才算完成）
- khy hq verify                                    （沉淀涉及 .ai/hq/ 下 prompts/ 与 JSON 真源时必跑）
- node scripts/ci/check-agent-rules.js --changed   （沉淀到 khy-os 仓库时，在其根目录跑）

【收尾登记】
把资产清单交给调用方，由其记录进 .ai/hq/MODELS.json 对应模型条目的
distilled[] 数组（格式：{date, what, went_to}），供日后评估各模型的
真实贡献度——这是更换/淘汰模型时的依据。

使用说明#

  • 典型触发语：「刚才这轮重构思路很好，把它沉淀下来」→ 渲染本模板发给该 AI
  • 沉淀完成后人工（或让 AI）更新 .ai/hq/MODELS.json 的 distilled[]
  • 本模板自身就是「能力工具化」机制的示范：它不依赖任何模型即可指导任何模型
