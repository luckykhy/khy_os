## 📋 提示词正文（复制下面代码块内的全部内容）

```text
【角色】你是开发环境接入工程师。这台电脑要加入一条多机协作流水线：
每台机器各持有一份「khy-os」仓库——它既是操作系统代码库，也是提示词库与
任务/Bug 状态真源（数据在 `.ai/hq/`，命令面是 `khy hq`）——靠 GitHub 仓库互相同步。
你的任务是让这台机器成为完整的工作节点，全程自主完成，只在需要凭据时询问用户。

【背景事实】
- 系统代码仓库（同时承载任务/Bug 状态真源）：https://github.com/luckykhy/khy_os
- 状态真源：仓库内 `.ai/hq/`（PROGRESS.json / BUGS.json / MODELS.json /
  ROADMAP.md / CONTEXT.md + 19 个提示词模板），只走 `khy hq` 命令读写，
  不手改 JSON
- 同步机制：单仓。开工 `git pull --ff-only`、收工检查全绿后 `git push`；
  autopull.bat + Windows 计划任务只在工作区干净时周期同步已提交内容
- 会话协议与铁律以 khy-os 根目录 AGENTS.md 为准，接入完成后先读它；
  单仓六步会话协议速查见 `.ai/hq/CONTEXT.md` 第八节

【流程】
1. 定位本机的 khy-os 目录：依次探测环境变量 KHY_OS_DIR、
   <便携根>\khy-os、<盘符根>\khy-os。都不存在则先安装 git、Node.js 与 Python，
   再 clone https://github.com/luckykhy/khy_os.git 到 <便携根>\khy-os。
   已存在则尝试 git pull --ff-only 更新；若因本地有未推送提交而失败，
   不要强推不要重置——如实报告用户，由用户决定处理方式
2. 确认本仓库的 git 提交身份已配置（否则 commit 报
   Author identity unknown，会卡死整个同步链）：git config user.name 与
   user.email 任一为空时，参照仓库既有历史设定仓库级身份：
     git log -1 --format="%an|%ae"     ← 查看历史作者
     git config --local user.name "<历史作者名>"
     git config --local user.email "<历史作者邮箱>"
3. 机械验收：在 khy-os 根目录运行 khy hq verify，必须 exit 0
4. 同步体检：git fetch && git status -sb，确认本分支与 origin/main 的
   领先/落后状态
5. 注册周期拉取（当前用户即可，无需管理员）：
   schtasks /Create /F /TN "khy-hq-autopull" /SC MINUTE /MO 10
            /TR "<khy-os 的绝对路径>\autopull.bat"
   注册后必须加固——schtasks 默认 StopOnIdleEnd=true，机器一离开空闲状态
   Windows 就掐断运行中的任务，Last Result 报 -1073741510（0xC000013A）。
   在 PowerShell 里执行：
     $t = Get-ScheduledTask khy-hq-autopull
     $s = $t.Settings
     $s.IdleSettings.StopOnIdleEnd = $false
     $s.ExecutionTimeLimit = 'PT30M'
     $s.DisallowStartIfOnBatteries = $false
     $s.StopIfGoingOnBatteries = $false
     Set-ScheduledTask khy-hq-autopull -Settings $s
   然后 schtasks /Run 手动触发一次，schtasks /Query /V 确认 Last Result = 0。
   说明：计划任务指向本机路径属机器配置，允许含盘符
6. 试运行领活循环：在 khy-os 根目录执行 khy hq status，能输出任务总览即接入成功

【工程红线】
- 全程禁止 force push；禁止把 token/密码写进任何被 git 跟踪的文件
- 仓库文件内部严禁硬编码盘符路径（脚本一律从自身位置推算）；
  只有计划任务注册这类机器级配置可用绝对路径
- 任何推送动作前必须 khy hq verify 全绿；本任务原则上只 clone/pull，不主动 push
- 不要手改 `.ai/hq/` 下的 JSON——状态迁移一律走 `khy hq` 命令正门

【验收标准】（全部满足才算完成，缺一即返工）
1. khy hq verify exit 0
2. git fetch && git status -sb 能如实报出本分支与 origin/main 的领先/落后状态
3. 计划任务 khy-hq-autopull 存在，手动运行后 Last Result = 0，
   且 IdleSettings.StopOnIdleEnd 已为 False
4. khy hq status 能输出总览
5. 最终报告逐条列出每个步骤的实际命令与结果

【验证命令】（在 khy-os 根目录）
- khy hq verify
- git fetch && git status -sb
- schtasks /Query /TN "khy-hq-autopull" /V /FO LIST
- powershell -NoProfile -Command "(Get-ScheduledTask khy-hq-autopull).Settings.IdleSettings.StopOnIdleEnd"
```

### 使用说明

- 场景：新机器只有 khy-os（甚至什么都没有），想让它成为第二工作节点
- 把渲染出的提示词发给该机上任意编码 AI（Claude Code / Codex / opencode 等），
  它会自主完成 clone→检查→计划任务注册→验收，仅在需要 GitHub 授权时找你
- 完成后该机即纳入多机协议：其上的 AI 用 `khy hq next` 自己领活，无需人工传提示词
- khy-os 的 AGENTS.md 已内置「多机流水线自举」一节：只要那台机器的 khy-os
  拉到含该节的提交，其 AI 冷启动即可自行发现接入指令——本模板是它的
  显式人工触发版，二者内容保持一致
