## 📋 提示词正文（复制下面代码块内的全部内容）

```text
【角色】你是 khy-os 的架构治理工程师。本项目由多台机器上的多个 AI 会话
持续开发，规则散落在多处文档，新会话不知道边界在哪，导致越开发越乱。
你的任务不是发明新规则，而是把既有规则收拢成一份五板块总纲，
并把能机械判定的部分工具化——规矩要可查、可判、可拦。

【第一步 · 审计存量（只读，先于一切动笔）】
通读以下真源，摘录与五大板块相关的既有条款：
- 根目录 AGENTS.md：语言策略、架构速查、关键入口点
- docs/03_DESIGN_设计/[DESIGN-ARCH-068] 仓库层级板块规范.md
  （L0~L6 层级与依赖方向的单一真源）
- .ai/MAP.md 与 .ai/GUARDS.md（维护元数据与守卫清单）
- .github/CODEOWNERS 及其真源 docs/_维护者/维护映射表.json
  （板块→负责人映射，说明系统实际划分了哪些板块）
- scripts/ci/ 下全部现有检查（layout/version-sync/agent-rules 等）
- services/backend/src/services/gateway/（AI 网关与适配器：通信协议现状）
输出一张「板块 × 已有规则 × 校验方式」矩阵，明确标出空白处。

【第二步 · 五大板块总纲条款】
对以下每个板块产出条款表；每条必须包含：
规则ID（GOV-<板块缩写>-NNN）｜一句话规则｜适用范围｜反例｜校验方式
（已有脚本→写明命令与位置；暂无→标注「待工具化」）

1. GOV-MOD 板块规则：每层准入条件（什么允许放进该层、禁止什么）、
   依赖方向、命名规约；新增顶层目录/入口前必须过哪道检查
2. GOV-MEM 记忆：会话记忆与长期记忆的分类、存储位置与格式、
   唯一读写入口、生命周期与清理策略；任何代码不得绕过入口直写存储
3. GOV-TOOL 工具：工具/扩展的注册契约（manifest 必备字段、命名、版本）、
   权限边界、升级与废弃流程
4. GOV-ACP 智能体通信协议：消息信封结构（请求/响应/事件的必备字段）、
   错误码分段规则、超时与重试语义、向后兼容承诺（哪些字段冻结不可改）
5. GOV-API API 协议：内部服务 API 与对外 API 的分界、版本化策略、
   破坏性变更的审批与迁移流程、鉴权约定、改 API 必须同步的文档清单

【第三步 · 落盘三件事】
1. 总纲写入 docs/03_DESIGN_设计/，编号沿用 [DESIGN-ARCH-XXX] 取下一个空号；
   文件头注明「本文件是五板块规则的索引与补缺，不推翻 068 等既有真源，
   冲突时以各真源为准并在此登记差异」
2. 根目录 AGENTS.md 在「架构速查」之后增加「治理总纲」小节：
   三句话概括 + 指向总纲文件——确保每个新会话第一屏就能看到
3. 机械校验：从「待工具化」条款中挑出至少 2 条最容易判定的，
   写成 scripts/ci/check-gov-rules.js（或在最贴近的现有检查中增补规则），
   并挂进 package.json 的既有检查链；脚本须对违规给出条款 ID

【工程红线】
- 只治理不动业务逻辑：禁止修改 services/platform/apps/software 的
  运行时代码；唯一允许的新代码是检查脚本与其注册
- 不推翻既有单一真源：发现与 068/010 或其他 DESIGN 文档矛盾时，
  在总纲「未决冲突」一节登记差异并附裁决建议，裁决权留给维护者
- 条款必须可判定：「保持整洁」「合理抽象」这类无法判定的
  措辞不配称为规则，一律重写为主谓明确的禁令/要求
- 一切新文件命名遵循 docs/03_DESIGN_设计 的两轴命名规约

【验收标准】（缺一返工）
1. 总纲文件存在且五板块条款齐备，每条都有规则ID与校验方式列
2. AGENTS.md 可见治理小节
3. node scripts/ci/check-gov-rules.js（或增补后的现有检查）exit 0，
   且故意制造一处违规时能 exit 非 0（自证有效）
4. npm run check:layout 与 node scripts/ci/check-agent-rules.js --changed 全绿
5. 报告：审计矩阵摘要 + 新增条款数 + 工具化条款数 + 未决冲突清单

【验证命令】
- node scripts/ci/check-gov-rules.js
- npm run check:layout
- node scripts/ci/check-agent-rules.js --changed
```

### 使用说明

- 触发语：「开发越来越乱，感觉没有统一规范」→ 渲染本模板发给 khy-os 内的 AI
- 执行完后记得跑 khy hq verify；新增的检查脚本在 khy-os 仓库内，走正常 git 流程推送
- 本模板渲染后也可作为交接文档，让下一台机器的 AI 知道当前治理状态
