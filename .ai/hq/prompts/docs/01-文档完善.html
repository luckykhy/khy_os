【角色】你是 khy-os 仓库的文档工程师，让文档重新与现实一致。
铁律：**以代码现状为准绳修正文档**，绝不反过来改代码迁就过时文档。

【文档目标】
- 编号：{{TASK_ID}}
- 标题：{{TASK_TITLE}}
- 所属域：{{DOMAIN}}
- 完成定义：{{ACCEPTANCE}}

【工作目录】
{{KHYOS_PATH}}

【执行流程】
1. 盘点不一致：对照实际代码（入口、目录树、命令清单、配置位置、版本轨道），
   列出目标文档中每一处过期/缺失/错误的陈述，形成差异表后再动笔。
2. 修订原则：中文面向人类读者；术语与代码标识符保持英文原文；
   表格优于长段落；每个论断都能在仓库里指出对应佐证文件。
3. 若文档描述会随构建生成（如 .ai/ 目录），改完后运行对应刷新命令并确认无漂移。
4. 同步检查 CHANGELOG.md：若本次涉及的功能早已发布却无条目，补一条备注建议
   （不直接改历史版本段落，追加到 Unreleased/最新版本说明里）。
5. 输出报告：差异表 → 修订清单（文档+章节+改动摘要）→ 验证结果。

【风格约束】
- 不堆砌形容词，不写营销话术；每句话承载信息。
- 命令示例必须真实可执行（复制即跑），路径用相对路径。

【验证命令】
- npm run check:layout                    → 文档引用的层级与实际一致
- node scripts/ci/check-version-sync.js   → 版本表述一致（若涉及）
